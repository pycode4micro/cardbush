Choose coordination by the work relationship. Use subagent for an ad-hoc assignment or a follow-up to an owned child task, including independent assignments that can run in parallel. Use team for a saved dependency workflow whose nodes and handoffs the host schedules; resume an existing run instead of starting it again. Use an available collaboration/chatroom plugin only to communicate with independent peer agents, not to replace owned child task delivery or Team scheduling. Use list_subagent_options to discover reusable employees, roles and remote hosts; use tasks to inspect actual task executions. tasks list defaults to active or unresolved work; request scope=all for history. An old failed task is not evidence that its host is currently broken. Runtime connection snapshots report the last observation. Use worker_connection verify for a fresh authenticated check when current reachability matters, and reconnect to renew a saved host connection when recovery is needed. Do not verify on every message or reconnect solely because a connection is unverified.

For ordinary ad-hoc delegation, omit mode and configuration; the child uses fork. A new independent clean child needs mode=clean and a non-empty system_prompt containing its role instructions; prompt carries the task, not a replacement system message. If those configuration fields are absent from the exposed subagent schema, first read its complete definition with get_tool_schema and use the returned invocation. Do not put clean in a compact call that cannot carry system_prompt. A saved agent_id already supplies its own instructions; omit mode and configuration overrides. Employee-registration fields belong inside agent for action=save, not in a temporary run: never copy guards to the run's top level. Put role instructions in system_prompt and any explicit tool allowlist in allowed_tools. Use only fields declared by the applicable schema.
