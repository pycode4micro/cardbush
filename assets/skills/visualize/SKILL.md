# 交互呈现

围绕用户当前主题，把需要理解、比较、选择或操作的内容做成可交互 HTML，让用户直接探索结果。通常优先用交互承载主要内容，而不是输出长篇文字；不必等用户明确要求“画图”或“做网页”。图表只是其中一种表达，解释原理、梳理流程、方案对比、情景推演、计划与资料浏览也适用。单个事实、简短操作、普通表格或明确指定的输出格式，直接用合适的文本表达。

## 先确定用户要做的交互

- 根据任务选择最小且有用的交互：比较时切换条件或方案，解释时分步演示与点击展开，推演时调整参数观察变化，资料探索时筛选、搜索与查看详情。围绕主题组织内容，不默认套图表、仪表盘或卡片墙模板。
- 让交互取代正文的重复与分支：将细节、备选项、推导或大量条目放进视图，默认先呈现关键结果与必要控件。不要把一篇长文装进 HTML 就当作交互交付，也不要为了“可交互”增加没有用途的控件。
- 控件必须有真实行为和可见反馈；提供清晰标签、键盘操作、选择状态及必要的重置或空状态。切换条件后同步更新相关结果。数据读写、工具调用或持久保存需要实际可用的通路，不能用页面动画冒充执行成功。
- 涉及数据图表、趋势或 BI 时，再读 [references/charts.md](references/charts.md)；其他交互不需要加载图表细则。图表起点可用 [assets/trend.html](assets/trend.html)，其中模拟数值必须替换或明确标注。

## 读取当前界面主题

每次创建或重新设计交互视图前，查询当前 CardBush 的实际主题。任务主题决定内容和交互，界面主题决定颜色与字体；不要根据旧截图、操作系统主题或模板猜测实际配色。

1. 用命令工具运行此 skill 目录内的 `node scripts/read_theme.mjs`（工作目录不在 skill 内时，传入脚本的绝对路径）。它优先读取 `CARDBUSH_THEME_CONTEXT_PATH` 指向的主题快照；默认安装也可从用户配置目录读取。此操作只读，不修改用户主题。
2. 读取结果中的 `theme`（实际主题）、`preference`（选择来源）、`colorScheme`、`background`、`fontFamily` 和 `tokens`。当用户选择跟随系统或自定义主题时，以实际颜色为准，不能只看主题名称。
3. 据此确定背景、标题、正文、控件、选中状态与浮层配色；有图表时再处理网格、图例和数据系列。初始回退值采用本次查到的颜色，保持文字对比，并用下文的宿主变量与事件适配后续主题切换。
4. 在当前主题下预览后再交付。交付前若主题已切换，重新读取并复核。读取失败时，使用当前可用的界面读取或截图工具查看 CardBush 的实际外观；仍无法确认时保持深浅主题感知、明确该项未验证，不假装已经读取主题。

## 在 CardBush 中交付

- 将完整、可运行的 HTML 写入当前任务可长期保留的目录，使用真实的绝对路径。优先使用原生 HTML、CSS、JavaScript；按内容需要使用 SVG、Canvas 或已有库，简单交互无需下载新依赖。预览只有浏览器 API，没有 Node.js 或 CardBush API。
- 完成主题适配后，在 `<head>` 声明 `<meta name="cardbush:preview" content="visualization">`，启用融入对话的呈现和自适应高度；该标记适用于这些交互视图，不要求页面有图表。不能只给仍然写死浅色背景的旧页面加声明来隐藏边框。
- 在最终回复中单独一行输出 `![交互视图标题](<绝对路径/view.html>)`。CardBush 将 HTML 图片语法渲染为可交互预览；普通 `[标题](<路径>)` 只显示文件链接。不要使用其他产品的私有可视化标记。
- 视图在助手回复完成后加载。最终答复只保留核心结论、必要的操作提示和未解决的限制，用清晰的 Markdown 分隔；主要内容在视图中交付，不再重复一份长文、数据或表格。仅最终答复要求简洁，开场、进度与讨论按任务需要充分说明；不压缩用户明确要求的细节。

## 自然融入对话

- 一个简洁标题后直接呈现主题内容与关键交互，必要时标明口径、单位和来源。不默认添加网站导航、页头横幅或层层圆角容器。
- 页面顶层透明、无外框和阴影，宽度跟随容器。宿主提供起止分隔、选项和整个预览的展开/收起入口，HTML 不重复这些控件；内容内部的步骤、筛选和详情展开按任务需要设计。
- 使用宿主注入的 CSS 变量：`--background`、`--foreground`、`--muted-foreground`、`--border`、`--popover`、`--popover-foreground`、`--font-sans`，以及 `--viz-series-1` 到 `--viz-series-6`。独立打开时可给变量设置随 `prefers-color-scheme` 切换的回退值；不要固定成白底网页或仅适配黑色。
- 宿主更新 `document.documentElement.dataset.cardbushTheme` 和 `color-scheme`，并发送 `cardbush:theme-change` 事件。HTML 和 SVG 优先直接引用 CSS 变量；Canvas 或缓存颜色的库监听此事件更新颜色，保留用户输入、步骤、筛选、缩放和选中状态。
- 宿主按内容测量高度，默认预览不超过 520px（小窗口进一步缩短），展开仍有 2400px 上限。第一屏放关键结果与主要控件；更多细节按需查看，超长内容可在内部滚动或侧栏打开。保持自然排版，避免顶层 `100vh`、固定最小页高、截断高度或横向溢出。
- 不显示滚动条或预留滚动条槽。用 `scrollbar-width: none` 和 `::-webkit-scrollbar { display: none; }` 隐藏滚动条，保留滚轮、触控与键盘滚动；不要用 `overflow: hidden` 截掉内容，优先随对话自然滚动。
- 适应实际容器宽度；在 320px 窄窗口换行控件、纵向排列面板，保持文字和点击目标可用，不整体缩放到难以阅读。每个完整内容单元及其标题、说明和控件放在同一个 `section`、`figure` 或带 `data-chart-section` 的容器里，供宿主选择完整的折叠边界。

## 动画与滚动性能

- 默认按输入、数据、尺寸、主题或交互变化更新，不常驻逐帧循环。有播放/暂停的动画，暂停时用 `cancelAnimationFrame` 真正停止循环，恢复时只启动一个循环并重置上一帧时间；仅停止时间累加但继续绘制仍会影响会话滚动。
- 页面隐藏时停止绘制，恢复后保留用户的暂停选择，避免按隐藏时长补跑动画；尊重 `prefers-reduced-motion`。不要为了维持离屏动画改用定时器绕过浏览器节流。
- 验证动画时实际点击暂停，确认 DOM/Canvas 更新停止；再验证恢复、重复切换不会叠加循环，以及鼠标经过视图时仍能连续滚动会话。只有视图确实提供缩放等滚轮操作时才拦截对应手势。

## 交付前验证

- 实际预览并点击主要控件，输入与切换条件，确认结果、详情和状态正确变化。只检查事件代码或直接用脚本修改内部状态，不算交互验证；无响应时区分宿主遮挡与 HTML 未绑定行为。
- 检查深浅主题、320px 与常规聊天宽度、键盘操作、主要空状态及主题切换后的输入保留。确认没有白色页面底、内容截断、无意义的内滚动或运行时错误。
- 区分真实资料、示例、假设和预测，注明必要来源或计算口径，不用模拟数据伪装实际结论。无法验证的功能应明确说明，不声称已经可用。
