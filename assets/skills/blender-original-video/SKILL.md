# Blender 原创视频预演

把用户的创意变成可以观看、局部修改和复用的动态预演，再按授权完成最终视频。Agent 负责创意与判断；现有 Blender MCP 执行场景操作；已有生成插件负责生图、生视频和任务状态。无需另建一套原子工具。

人物只使用无肢体的简单占位体，Blender 负责空间、主体整体位置与朝向、走位和运镜。不建模四肢，不制作骨骼、步态、手势或表情动画；肢体表演用文字交给视频生成模型完成，避免把僵硬动作带入成片。

配合视频生成时，优先生成首尾帧图片或人物、产品、场景参考图，确定外观与画面风格；已有合适图片直接复用。人物默认适度风格化，避免完全真人化、照片级人脸和皮肤质感，并在实际生图、生视频提示词中保持这一要求。用户明确指定其他风格时沿用其意图。

## 确定工作范围

- 沿用用户指定的主体、产品、风格、比例、时长、模型和声音意图。首尾帧或参考图按镜头需要选择，不强制每镜两张；新增生图仍须在用户已有授权内。仅对影响创意、素材绑定或费用的关键缺口提问，其他细节可提出明确的草案。
- 先判断本次是创意方案、动态预演、预演修改，还是包含最终生成的完整制作。仅请求方案或预演，不默认授权付费生成；已有生成授权按其范围执行，不重复征求。
- 发现当前实际可用的 Blender MCP，确认实例、版本、场景和项目路径。按暴露的工具定义操作，需要 Python 时查询实际 Blender API；不照搬其他 MCP 实现的工具名或参数。
- 无可用 Blender 连接时，可交付镜头方案并说明缺少执行能力；脚本、工具调用成功或计划文字均不能代替可播放的预演。

## 设计并制作预演

1. 将创意整理为可见的情节或展示节奏：主体意图、空间关系、整体动线、景别、镜头运动和声音作用。肢体动作保留为文字意图。镜头数量、是否一镜到底由内容决定，模板仅作为起点。
2. 涉及最终视频生成时，先选定或按授权生成首尾帧图片或外观参考，统一人物身份、发型、服装、比例和风格，明确开场与结尾意图。只做空间/镜头预演时，不强制新增付费生图。
3. 按选定构图在 Blender 中建立场景和简单占位体，只制作主体整体位移、朝向与相机动画。具体方法见 [预演与修改](references/previsualization.md)。
4. 渲染或播放实际摄影机视角，检查构图、空间连续性、遮挡、运动和节奏，并核对首尾状态与参考图是否一致。运动判断需要查看连续片段；抽帧仅用于定位构图与细节，说明尚未观察的部分。
5. 根据发现或用户反馈修改对应对象、路径或时间段，保留其余已确认内容。保存可恢复版本，重新检查受影响片段及其衔接。

先让预演达到镜头意图，再准备最终生成。用户要求先确认时，展示预演并等待；已授权端到端制作时，可在自行检查通过后继续，不额外设置一律人工批准的关卡。

## 从预演生成成片

进入生成、替换素材或生成后修订时，按需读取 [生成交接与验收](references/generation-handoff.md)。明确预演、首尾帧、人物、产品、场景、风格、台词和音频分别决定什么，使用当前工具能力组织输入；将前面选定的外观与构图参考明确绑定到本次请求。

交给模型的是干净的实际摄影机预演。模型应参考其空间、整体动线与镜头时序，人物和材质外观由相应素材定义，肢体表演按文字意图自然生成。实际提交的提示词须说明占位体不提供姿态或步态参考，不要复刻它的滑行或僵硬姿态。预演是参考约束，不代表模型会逐帧精确执行；生成后仍须对照检查。

## 保存可继续的工作

交付可编辑的 `.blend`、可播放预演，以及本次已完成的成片或关键素材。用简短自然语言记录当前版本、镜头意图、角色与素材对应关系、已确认部分、实际检查结果、待解决问题和下一步；有生成任务时保留任务 ID 与结果路径。不要求固定 JSON 或每镜头套用完整表格。

压缩上下文时，在既有摘要中保留本任务仍需要的 Skill 决策和上述制作状态，按相关性选择，不抄完整 Skill，也不因压缩而强制重读全部参考文档。

## 执行边界

- 修改已有工程前确认目标并保存版本，避免覆盖用户原稿或清空无关场景。角色与物体保持稳定标识，生成结果绑定具体预演版本。
- 同一 Blender 实例的写入需串行或由执行层隔离。Skill 中的约定不等于跨 Agent 的锁；实际存在竞争时，使用已提供的独立实例或排队能力，不能假定互不影响。
- 渲染排队、进程恢复和付费请求幂等由执行工具负责。超时先查询已有任务和产物；状态不明时不重复提交可能收费的生成。
