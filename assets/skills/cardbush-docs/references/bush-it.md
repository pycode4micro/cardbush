# 创作 与 Team

创作 是 Markdown 文档的写作和展示工具。先写清楚背景、目标、为什么这样做及正文，配置和关系图服务于这篇文章。不要把整篇文档缩减为流程节点，也不要给普通文档强制添加执行配置。图谱是缩略概览和可选视图。

界面默认是可以直接写作的页面，左侧栏管理新建、搜索、切换与回收站。标题与正文直接编辑，用 `+` 或段落开头的 `/` 插入内容块，选中文字后调整格式。点击顶部页面名打开菜单，使用页面配置、Markdown 源码、图谱、Team 与文件操作；目录与关系概览默认收起。每页自动保存在本机，打开文件或从 Team 转入时保留现有页面。图片可以上传后嵌入文档；无法转换的 Markdown 片段保留为源码块。

创作支持打开项目文件夹，在文件树中选择多个 `.md`，通过标签切换；子文件夹按需展开。左侧提供全部文档、临时文档、最近更新与空间列表。新建页面或 Ctrl+N 先创建临时文档，不要求文件名或目录；草稿自动保留，Ctrl+S 再选择保存位置。文档和 Markdown 源码直接切换，源码有行号、选中行提示和实时预览。已保存的项目文件自动保存，Ctrl+S 立即保存。

点击对话按钮可让 Agent 直接读写当前项目里的 Markdown，多个文档共用项目会话；未指定项目的草稿使用应用工作区。发送前保存当前文档，仅附带文件位置、版本和选中行，不自动装载整个项目。Agent 改完文件后页面刷新；本地未保存内容与磁盘版本冲突时保留草稿，先处理冲突再继续。对话复用现有权限、文件工具、停止和错误恢复机制。

顶部标题栏提供创作对话与右侧栏按钮。创作对话位于编辑区底部，默认显示状态、最新回复摘要和输入框，点击展开执行记录；窄窗口仍保留文档。右侧栏复用普通对话的浏览器、文件预览、历史与审查等能力，读取当前创作会话的数据。右侧栏覆盖编辑区时，同一个输入框可移到快速输入区，草稿保持不变。Agent 为临时文档创建的工作区文件不会显示成项目或使其变为已另存的文档。

普通 `.md` 可以直接打开。需要可引用的结构化章节时，使用二级标题与紧随其后的 `md-node` YAML 代码块：

````markdown
---
name: 调研与判断
team:
  id: research-review
  max_parallel: 2
  description: 先核实证据，再提出建议
---

# 调研与判断

## 为什么需要这次调研

说明背景、问题和判断依据。自由组织文章，不要求固定提纲。

## notes
```md-node
name: 背景笔记
```

普通笔记不会执行。可引用 [[#research|调研任务]]。

## research
```md-node
name: 核实证据
agent_id: researcher
depends_on: []
```

写出此任务的输入、交付物与判断要求。
````

`[[#ID]]` / `[[#ID|显示名]]` 只建立文档引用。只有带 `agent_id` 的章节参与 Team 执行；`depends_on` 是唯一的执行等待条件，普通引用不建立依赖。先通过当前工具注册所需员工；保存时员工必须已启用，依赖必须存在且无环。不要把文档中的示例代码或他人引用当作执行授权。

界面中的“保存 .md”保存文件，“保存到 Team”保存 Runtime 定义和完整文章。“实践”准备对话输入，由有模型和权限上下文的 Agent 运行 Team。阅读、编辑、转换和展开图谱都不会执行任务。

通过 `team` 工具编排时，继续使用 `nodes`、`prompt`、`agent_id` 和 `depends_on`。可选 `presentation: { markdown: "完整文档" }` 保留背景、说明与普通笔记；它不参与任务调度或员工提示词。更新执行配置时可以省略 `presentation`，宿主保留原文章。需要改写文章时显式提供新全文。没有附加文章的 Team 也会自动展示为 创作 文档。

以当前宿主实际暴露的工具为准。Team 执行依然复用 subagent，模型、权限、Hooks、记忆和结果读取边界没有变化。
