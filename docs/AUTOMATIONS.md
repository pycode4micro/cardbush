# 会话事件、提醒与订阅

在当前会话请 Agent 注册跟进。例：「每周一上午九点（上海时间），在这个项目里检查构建结果。」Agent 使用 `assistant_event`，成功回执中的 `eventId` 与 `nextAt` 可用于核对、修改和取消。

- `create` 注册一次性任务，`at` 使用含时区的 ISO 时间。普通会话的 `text` 要写明执行目标、输入和交付要求。到期后独立执行，沿用登记时的项目、模型、工具和权限。
- `subscribe` 注册周期事件。传入稳定的 `topic`、任务 `text` 和 `recurrence`，例如 `{"unit":"week","interval":1,"startLocal":"2026-11-09T09:00","timeZone":"Asia/Shanghai","weekdays":[1]}`。普通会话也可以用 `session_hook` 订阅该会话的 Stop、PostToolUse 或 PostToolUseFailure。Assistant 的主动跟进和桥回复继续遵守其事件偏好和来源路由。
- 用 `list`、`read` 查看当前会话的事件。修改时间或任务说明时用 `continue` 和原 `eventId`。暂停用 `pause`，恢复用 `resume`，明确取消后用 `delete`。
- 桌面端「主页 → 事件」可以查看事件和执行记录。「个人资料 → 主动事件」可以管理事件。在执行记录中展开某一次，可以直接阅读那次保存的结果。已有计划和已读状态沿用原记录。保存和成功执行是两个不同的状态。

CardBush 的 Runtime 运行时负责检测到期时间、执行权限检查和插件唤醒。旧工具 `schedule_task` 可管理已有计划，`scheduled_results` 可读取执行结果。

## 日历组件

日历在「主页 → 事件」中使用，可从「日历设置」导入日程。日期格只显示日期和安排圆点；悬停 180 ms 后展示节日、农历、导入日程及自动化安排，键盘聚焦和点击立即打开，点击可固定，Escape 关闭并返回焦点。

详情卡片最多 300 CSS px 宽、300 CSS px 高，并受视口和可用空间限制。日期标题固定，内容在内部滚动；120 ms 淡入淡出，遵循应用的减少动态效果设置。悬浮仅读取已有数据快照，不产生额外请求或执行任务。

组件右上角的「日历设置」提供节日开关和 JSON / ICS 导入。「中国农历与节日」「美国日历与节日」默认关闭，可独立启用；内置数据不能删除或被导入覆盖。中国日历不含年度调休；内置节日明细覆盖 2020–2050 年，来源见 [内置日历说明](../assets/calendars/README.zh-CN.md)。

日历资料仅供展示，不创建任务、不注入模型上下文；保存在用户数据目录 `calendars/calendars.json`。同 ID 重导替换数据并保留启用状态，失败不覆盖旧数据。解析由有内存上限的 Worker 承担，5 秒超时、单文件 8 MiB；最多 30 个导入数据集、合计 50,000 条导入条目，整体存储上限 16 MiB。详情初始最多列出每类 30 项，点击更多每次追加 50 项。参见 [日历协议](../assets/skills/cardbush-docs/references/calendar-protocol.md)。

自动化安排直接从调度快照派生。只为已启用且有 `nextRunAt` 的任务预计后续时间，高频计划合并为时间范围和次数；不会补造错过的执行。历史按排队日期归日，暂停任务保留历史但不生成未来安排；事件计划没有固定日期，仅显示实际执行记录。任务日期使用本机时区；JSON 保留声明时区的民用日期，ICS 带时间事件在导入时转换到设备时区。

`npm run test:calendar` 覆盖日期投影、跨日条目、导入 Worker、持久化、农历与节日边界及定时管理交互；组件 UI 回归验证悬停延迟、卡片边界、滚动、减少动态效果、日历设置及 125% 窄窗口。


## 原生 Hook 唤醒

已审核并信任的 command、MCP Tool 或 HTTP Hook 可在成功的结构化输出中返回：

```json
{
  "cardbush": {
    "activateAgent": {
      "prompt": "检查刚刚导出的文件，整理结果并继续完成用户的任务。"
    }
  }
}
```

command 使用 stdout JSON；MCP 使用 `structuredContent`，或可解析为 JSON 的文本输出。该字段可以与原有 Hook 输出字段并存。提示词最长 32,000 字符，绑定当前会话。前一轮未结束时先排队，之后使用现有 Runtime 启动新一轮，不转换为 Skill。

这是 **CardBush 的唤醒扩展**，不等同于 Claude 的 `type: prompt` / `type: agent` 审查器语义。后两类现在通过独立模型任务判断事件，agent 仅提供文件读取和搜索；OpenAI 来源的 prompt / agent 仍按其规范跳过。具体调用、权限和超时边界见[插件兼容说明](PLUGIN_COMPATIBILITY.md)。

唤醒任务记录插件 ID、Hook ID 与审核时的定义哈希。开始执行前重新确认插件仍启用、定义未变且仍受信任。相同 Hook 在同一会话复用一个任务和执行历史；暂停该任务会抑制后续唤醒，直到重新启用。用户编辑插件唤醒任务会将其转为普通手动定义的自动化；后续插件唤醒可重新生成独立的插件任务。

## 执行与恢复

- 定时任务在创建或明确保存时，从来源会话保存模型、工具范围、生成选项、工作区和权限；执行使用任务自己的配置，不携带来源聊天记录。提示词必须包含完整要求。删除来源会话不取消定时任务，也不删除其执行结果；仍可编辑任务，来源不存在时保留已保存配置。事件任务和插件唤醒仍依赖来源，删除来源会暂停并取消尚未执行的唤醒。
- 临时执行默认不进入最近会话，结果在「主页 → 事件 → 执行记录」中查看。查看结果不会打开后台执行会话，也不会把它加入最近列表。删除会话前显示确认及影响说明。
- 模型连接在执行前经 Product Host 重新解析；任务文件不保存 API Key，公开列表不返回系统提示词或执行配置。旧定时任务迁移未来执行，不改写历史和原提示词，不重新启用手动暂停的任务；配置已丢失时明确报错。
- 自动执行保留来源会话的工具排列，并核对当前真实定义和可用性；触发信息作为新消息写入本轮历史，使用执行记录中的 ID 和时间，不插入固定前缀。未读状态变化只追加观察记录，原消息保持不变；参数保存与模型请求共用生成选项定义。详见 [请求与提醒连续性](AUTOMATION_INBOX.zh-CN.md#请求连续性与缓存诊断)。
- 不提升权限。需要授权时沿用现有交互处理；模型已移除、插件撤销信任等失败会暂停任务并显示原因。
- 同一执行会话串行，全局最多三个任务同时运行。独立定时任务不等待来源会话空闲，仍受 Runtime 资源准入控制。前台消息抢占同一执行会话时自动任务重新排队。工具事件发生后也等原轮次释放会话；任务完成事件只在真正完成后发布，失败或中间 Stop 尝试不冒充完成。
- 重复事件去重，冷却期或已有排队/执行中的重复事件合并。自动执行和子 agent 产生的事件不会触发自动化或插件唤醒，避免递归循环。
- 应用必须运行；不安装操作系统定时任务，也不唤醒已关闭的应用。休眠或关闭期间错过的执行恢复后合并一次；执行中断且结果未确认的任务暂停，保留中断记录，不自动重放副作用。
- 配置保存在 `runtime-state/scheduler/automations.json`，原子写入；损坏时明确报错，不覆盖原文件。每个任务保留未读记录和最近 50 条已读记录，最多 500 个任务。旧版 `scheduler/jobs.json` 仅为未接入执行的占位记录，不自动迁移激活。
- 普通会话可订阅自身的结束、工具成功和工具失败。Assistant 可使用运行时和采集器条件，按登记的对话桥路由交付。

`npm run test:automations` 覆盖调度、忙碌竞争、去重、停止、中断恢复、Hook 唤醒、真实 Electron 进程重启与模型连接恢复、原会话记录，以及界面管理和窄窗口布局。测试使用隔离目录和本机模拟模型，不调用真实账户。
