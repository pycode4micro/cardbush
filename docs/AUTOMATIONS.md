# 定时与事件自动化

侧栏「定时与自动化」和 agent 的 `schedule_task` 使用同一个 Runtime 调度器和持久化任务表。定时到达、匹配会话事件或受信任插件的 Hook 发出唤醒请求后，会在目标会话提交一轮真实的 agent 执行；结果、工具记录、授权请求和停止动作复用现有会话链路。

## 使用

1. 在目标会话发送一条消息，建立模型、工作区、工具目录和权限配置。
2. 打开「定时与自动化」，填写名称、目标会话、执行提示词与触发方式。也可以在会话中要求 agent 设置定时。
3. 支持指定时间、固定重复间隔（至少一分钟）、任务完成、工具成功和工具失败。工具事件可填写精确的 Runtime 工具名，留空匹配全部；冷却时间至少一分钟。
4. 可查看执行记录、打开原会话、编辑、暂停、启用、立即执行、停止和删除。运行中的任务需先停止才能编辑或删除；暂停会取消排队，停止还会中止正在执行的一轮。

日期输入和列表时间按本机时区显示，实际存储带时区偏移的 ISO 时间；固定间隔按经过的秒数重复，不是 Cron 或按夏令时变化的日历规则。UI 使用当前本机时区保存，工具可显式传入 `time_zone`。

工具示例：

```json
{
  "action": "create",
  "name": "项目检查",
  "prompt": "检查项目构建结果，整理失败原因和需要处理的问题。",
  "time_zone": "Asia/Shanghai",
  "trigger": { "kind": "interval", "at": "2026-09-10T09:00:00+08:00", "seconds": 86400 }
}
```

`list` 返回本会话的任务。`update` 传完整定义；其他管理操作使用 `job_id`。可携带 `expected_revision` 拒绝并发覆盖。`cancel` 为 `pause` 的别名。子 agent 不开放该工具。

## 原生 Hook 唤醒

已审核并信任的 command、MCP Tool 或 HTTP Hook 可在成功的结构化输出中返回：

```json
{
  "cardbush": {
    "activateAgent": {
      "prompt": "检查刚刚导出的文件，整理结果并继续完成用户的任务。"
    }
  }
}
```

command 使用 stdout JSON；MCP 使用 `structuredContent`，或可解析为 JSON 的文本输出。该字段可以与原有 Hook 输出字段并存。提示词最长 32,000 字符，绑定当前会话。前一轮未结束时先排队，之后使用现有 Runtime 启动新一轮，不转换为 Skill。

这是 **CardBush 的唤醒扩展**，不等同于 Claude 的 `type: prompt` / `type: agent` 审查器语义。后两类现在通过独立模型任务判断事件，agent 仅提供文件读取和搜索；OpenAI 来源的 prompt / agent 仍按其规范跳过。具体调用、权限和超时边界见[插件兼容说明](PLUGIN_COMPATIBILITY.md)。

唤醒任务记录插件 ID、Hook ID 与审核时的定义哈希。开始执行前重新确认插件仍启用、定义未变且仍受信任。相同 Hook 在同一会话复用一个任务和执行历史；暂停该任务会抑制后续唤醒，直到重新启用。用户编辑插件唤醒任务会将其转为普通手动定义的自动化；后续插件唤醒可重新生成独立的插件任务。

## 执行与恢复

- 沿用目标会话最近成功进入 Runtime 的普通轮次配置。自动执行本身不覆盖这份配置。模型连接在执行前经 Product Host 重新解析；任务文件不保存 API Key，公开列表不返回系统提示词或执行配置。
- 不提升权限。需要授权时沿用现有交互处理；模型已移除、插件撤销信任等失败会暂停任务并显示原因。
- 同一会话串行，全局最多三个任务同时运行。前台消息抢先进入时自动任务重新排队。工具事件发生后也等原轮次释放会话；任务完成事件只在真正完成后发布，失败或中间 Stop 尝试不冒充完成。
- 重复事件去重，冷却期或已有排队/执行中的重复事件合并。自动执行和子 agent 产生的事件不会触发自动化或插件唤醒，避免递归循环。
- 应用必须运行；不安装操作系统定时任务，也不唤醒已关闭的应用。休眠或关闭期间错过的执行恢复后合并一次；执行中断且结果未确认的任务暂停，保留中断记录，不自动重放副作用。
- 配置保存在 `runtime-state/scheduler/automations.json`，原子写入；损坏时明确报错，不覆盖原文件。每个任务保留最近 50 次记录，最多 500 个任务。旧版 `scheduler/jobs.json` 仅为未接入执行的占位记录，不自动迁移激活。
- 当前事件源仅为会话生命周期。文件监听、Webhook、Slack 等外部事件订阅及 Cron / RRULE 尚未接入。

`npm run test:automations` 覆盖调度、忙碌竞争、去重、停止、中断恢复、Hook 唤醒、真实 Electron 进程重启与模型连接恢复、原会话记录，以及界面管理和窄窗口布局。测试使用隔离目录和本机模拟模型，不调用真实账户。
