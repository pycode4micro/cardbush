# 上下文、压缩与个性化记忆

[English](CONTEXT_AND_MEMORY.md) · [简体中文](CONTEXT_AND_MEMORY.zh-CN.md)

三者独立：会话历史记录发生过什么，上下文压缩为同一任务生成更小的模型输入，习惯/预测用于可选的跨会话个性化。压缩不会自动把聊天变成习惯。

## 普通轮次与压力

Runtime 持久化用户输入、assistant 文字、工具调用/结果和终态。完成 turn 不立刻改写历史或请求总结模型。工具工作后单独 `summary_for_user` 是终轮展示信号，并可写入受开关控制的个性化字段；`{}` 有效，它不是压缩调用。

接近输入预算时，默认从完整 turn 的工具名称、既有 reason/标题、相关参数、实际回执、准确终轮回复推导 handoff。按顺序保留纠正、失败、未完成/未知状态、标识和授权事实；工具返回不自动等于业务成功。已知大文本可明确节选并附归档定位，来源指令和图像交换有更严格保留方式。

只有完整重建请求变小，且满足 token、输出预留和请求体限制才接受。原历史仍供审计、fork、工具检查；应用引用/hash 跨重启保存，不重复副作用。`preferRecordedToolHandoffs:false` 用于对照实验，不是新增用户流程。

## 模型兜底

记录压缩不能腾出足够空间时，Runtime 要求原模型提交 `checkpoint_context`，模型不主动调用。来源编号稳定，合法部分保留，所有必要来源完成才应用；超大来源先按完整消息/工具交换分片，再合并。原输入、已接受摘要及来源链接可追溯。

旧摘要为主的历史可以再合并，近期完整来源保留。提交/完成前检查整个后续请求，有限收紧并保留可用余量。压缩维护不消耗消息唤醒的任务轮次上限；重启保留接受内容和片段边界，不从头执行工具。

语义保真仍需模型质量审查：路径/修订/行号证明出处，不证明概括保留每条要求。`read_conversation_history` 有界读取当前会话原日志，`read_archived_tool_result` 只接受 Runtime 发出的准确定位器，都不是任意文件/跨会话访问。

默认配置窗口 530000 tokens，应按真实模型/服务上限设置；填更大不产生服务容量。输出预留与 wire 大小分别控制：适配器默认 JSON 40,000,000 字节，35,000,000 进入维护。并行工具轮共享一份结果入口预算（含图像），不是每个工具都填满余量。见[图像预算](MODEL_IMAGE_BUDGET.md)、[Runtime 契约](../packages/bush-runtime/README.zh-CN.md)。

## Cachechain

参数变化与消息前缀改写分开：`parametersChanged/changedParameters` 记录预算、温度、工具、绑定等；`frozenPrefixBreak/breakIndex/messageBreakIndex` 记录真实输入变化，投影格式切换建立新基线。实际压缩可能一次断链，普通只追加轮次不因参数变化误报。命中只以 Provider usage 为准，见[缓存路由](PROMPT_CACHE_ROUTING.md)。

## 可选个性化

习惯和预测独立，新会话默认关闭。CLI `/habit`、`/prediction` 按会话保存，恢复沿用，fork 继承后可独立修改。关闭不删除已有记录。召回过滤过期/撤回/被替代项，不自动把后续用户消息采集成证据队列。

普通完成只合并调度本地去重、过期及可撤销证据归档，不因 token 阈值自动调用总结模型。可召回记忆和证据各有 8,000 条活动容量保护。长期习惯不因最近未召回而过期，预测通常 7 天。

手动模型整理需明确启动并产生用量，复用内部任务 runner 的有界输入/重试/取消，核对来源引文并逐批保留合法结果。未知证据不算反例，失败不再开自动后台任务，来源始终保留。容量、恢复及离线回放见[记忆维护](memory-maintenance.md)。

个人助手摘要、语音恢复是另一种有界会话投影，不是习惯库，见[助手](PERSONAL_ASSISTANT.md)、[语音](REALTIME_VOICE.md)。诊断时分别看用量、结构连续性和产物质量，分享记录前脱敏原始隐私历史。
