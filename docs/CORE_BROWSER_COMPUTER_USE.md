# 浏览器与 Computer Use：CardBush 内置能力边界

Browser Use 在 Windows 11 上统一控制 CardBush 内置浏览器和分别配对的 Chrome / Microsoft Edge。外部浏览器保留各自的扩展、登录状态和个人配置；内置浏览器操作应用中正在展示的真实标签页。这些能力与 Computer Use 一起随应用交付和维护。

## 内置标签页控制

在输入框使用 `@ → CardBush 浏览器`，宿主按窗口、标签身份和真实 guest ID 绑定当前会话，不按网址匹配 Chrome / Edge。Browser Use 的 `list_pages` 会标明 CardBush 页面，随后可使用同一套快照、点击、输入、导航和截图工具。内置页面无需扩展、配对或启动外部连接器。Agent 也可显式 `select_browser({connectionId: "cardbush"})` 后 `new_page`。

只向会话开放明确引用、为该会话新建或由其本地子任务新建并回传的页面。关闭、替换、重启后失去 guest 的引用会明确失败，不自动选中其他页面或外部浏览器。远程 Agent 暂不控制本机内置页面；高级 Chrome 远程调试模式需先在设置中切回普通 Browser Use。内置模式暂不提供 `download_file` 的下载任务跟踪能力，调用时明确返回不支持。

本地子代理在派发、继续执行或接收指导前，经私有宿主通道继承父会话的内置浏览器路由及确切页面授权；先验证任务归属，不接受模型传入父会话 ID 来授权。父子会话分别保存页面选择，重复同步不重置子会话选择，父会话新增 `@` 引用后再同步。失效页面仍按原 guest 身份拒绝操作，不按网址重认页面，也不妨碍不使用浏览器的子任务运行。远程派发不走此授权通道。

页面的显示归属与浏览器授权独立保存：即使主会话尚未选择内置浏览器，子代理首次打开、选中或关闭的内置页面也由根会话的工作区展示，嵌套子代理同样如此。后台任务只更新所属会话的标签页，不切换用户正在查看的其他会话，也不会因显示归属而获得额外页面权限。

子代理通过 `new_page` 新建并确认就绪的页面，会把同一个 guest 的控制权限沿宿主验证的父子关系回传到各级父会话。不会回传子代理已有的独立页面、后来引用的页面或其他会话页面；遇到父会话已绑定另一窗口时停止向上传递。父会话保留原先选中的页面，续派也保留子会话的选择；新的明确 `@` 引用仍会按原规则同步给子会话。任一获授权会话通过工具关闭共享页面后，会同步移除该页面的授权；手动关闭、替换或重启导致的旧引用仍明确失效。

尚未绑定浏览器的父会话收到子任务新建页面后，首次读取直接使用 CardBush。已有 Chrome／Edge 绑定保持不变，显式切回 CardBush 后即可读取回传页面，无需重复打开网页。

主进程通过经过身份认证的本地 MCP 端点提供统一路由；内置操作使用所属 webview 的页面级 CDP，外部操作继续使用原有配对连接器。renderer 只注册属于自己的网页 guest，不能注册应用界面或其他窗口。HTTP MCP 的页面选择和渐进快照游标保存在宿主中，不随单次请求销毁。本机端点直连，不经过插件代理；取消或超时会解除等待和调试连接，不自动重放操作。

回归入口：`npm run test:browser-integrated`。隔离测试覆盖真实 Runtime 工具发现、内置 webview 引用、assistant 子任务读取与点击、新建页面向父会话回传及父会话实际点击、嵌套派发、独立选择与窗口隔离、再次引用后的同步、截图、导航、同网址隔离、关闭／替换／重启边界，以及卡住的页面脚本取消后仍可继续操作。

## Browser Use 连接与路由

- 用户仅需打开并保留网页时，桌面 Runtime 提供 `open_external_url`，通过私有宿主 RPC `browser.open-external` 交给主进程 `shell.openExternal`。浏览器不属于终端任务树，终端或 turn 结束不回收它；远程 Agent 服务不暴露此桌面能力。两端校验仅接受不含内嵌凭据的 HTTP(S)，不改变 OAuth 链接校验。返回 `dispatched` 只表示系统接受了打开请求，不证明页面已加载，也不提供配对、网站授权或页面控制。终端原有的子进程回收保持不变。
- 回归入口：`npm run test:desktop-browser`。覆盖 URL/取消/失败边界，以及真实 Electron Runtime、模型工具循环和独立配置的 Chrome 在终端清理、turn 完成、Runtime 退出后继续运行；测试仅将系统默认浏览器选择替换为隔离 Chrome 启动器，不修改用户默认浏览器或现有窗口。
- 对外名称统一为 **Browser Use**，模型工具命名空间为 `browser_use`。现有资源目录、内部配置身份 `chrome` 和私有 IPC 标识保留，避免重置已有启停选择；这些标识不代表仅支持 Chrome。
- 仅支持 Windows 11；Chrome、Edge 使用同一份 MV3 扩展（1.2.3），分别在 `chrome://extensions` / `edge://extensions` 加载并配对。升级时重新加载原扩展，避免卸载导致已保存的扩展数据被清除。替换磁盘文件不代表 Chrome 已更新正在运行的 service worker；弹窗比较构建内容指纹与后台加载时的指纹，发现旧后台（含没有指纹的旧版本）时明确提示更新尚未生效，并提供「重新加载扩展」。重新加载不清空配对、启用意图或网站授权；连接和控制中先关闭应用端连接器，避免中断在途操作。构建、开发启动自动生成指纹，避免仅手改版本号漏掉更新。
- 设置中选择浏览器、填写可选连接名称，再生成五分钟有效的配对码。每条配对具有独立凭据；Chrome、Edge 及不同浏览器用户配置可同时在线，最多保留八条。更换同一配置的配对后可移除旧记录。
- 扩展通过固定扩展 Origin 和双向 HMAC 验证本机 WebSocket；握手确认浏览器类型。凭据不出现在模型工具、连接状态或诊断中。仍只监听 `127.0.0.1`，不引入外部注册表项或新的 MSIX capability。
- `list_browsers` 返回连接名称、浏览器类型、在线状态、默认连接和当前会话选择；`select_browser` 显式绑定目标连接。未选择且没有子任务回传的内置页面时，首次页面调用使用默认连接。绑定保存在受保护的 `browser-connector/routes.json`，重启不改变归属。
- 更改默认值只影响未绑定会话。断线、撤销配对或重启不自动回退到另一浏览器；在途请求立即返回断线错误，动作可能已经执行，需要恢复后重新观察。连接之间按请求和会话校验响应，不按相同 tabId 路由。
- 显式切换先释放旧浏览器的本会话控制；释放失败则不切换。在途操作期间不允许切换。成功后模型必须重新获取页面和元素 ID。
- 移除连接只撤销对应凭据；已绑定会话保留原归属，需明确选择新连接。关闭连接器停监听及控制但保留配对和路由，再次开启后自动重连；“移除连接器配置”才撤销全部配对并清理路由。普通退出保留配对、绑定和启用意图。
- 扩展使用 local 保存启用意图及站点/全部网站授权。断线先在 worker 存活期间按 1、2、4 秒快速重试，同时保留每 30 秒的 alarm；握手成功后清除 alarm。浏览器调度或休眠可能延迟 alarm，不承诺固定恢复上限。重启浏览器也自动重连，打开弹窗可立即重试；明确关闭扩展连接后保持关闭。配对码五分钟只约束首次配对，成功后的凭据持续有效。临时授权和标签组标识仍只存 session，不在浏览器重启后凭名称认领个人标签。
- 应用按用户资料单实例运行：关闭到托盘后再次启动唤回原窗口。桥启动失败保留之前保存的启用意图、配对与路由；重新打开窗口或点击“重试连接”可重试。设置页区分启动失败和首次配对，仍允许明确关闭。
- 工具仅对桥确认的 `not_dispatched` 离线请求等待重连，最多 8 秒且不超过请求预算的一半；等待期间固定原连接，明确切换浏览器后取消原操作。超时、执行中断线和已发出的命令不自动重放。诊断记录等待次数；轮转日志仅记连接状态变化，不写配对码或网页内容。
- 默认加载 Browser Use 自有 skill。原厂 Chrome DevTools MCP 和资源保留为用户主动选择的高级远程调试模式，此路径仍仅面向 Chrome，不作为连接器失败时的自动回退。
- 许可按来源区分：CardBush 自有连接器、适配层与技能遵循仓库 Apache-2.0；高级模式的 Google MCP 及其依赖保留上游许可。分发说明与 axe-core 对应源码入口见 `assets/plugins/chrome/THIRD_PARTY_NOTICES.md`。
- 本次不增加 Linux/macOS 支持，也不改变 Windows Computer Use 的实现。

## Browser Use 点击与渐进快照

连接器的 `click` / `hover` 使用 `pagePointer.ts`：先检查节点仍存在、可见、非 inert，点击时另查原控件和祖先的禁用状态。零面积控件仅允许使用 HTML 明确关联且可见的 label；坐标取自视口内的内容四边形，通过 CDP 实际命中节点复核，支持子节点、Shadow DOM、iframe 的坐标与遮挡检查，也检查 iframe 容器的可见性。鼠标移入后、双击的第二下前再次复核；失效或被遮挡就停止，不偷偷换 JavaScript click、Enter 或重放已发出的点击。

回执改为 `status: input_dispatched`、`hitTargetVerified: true`、`outcomeVerified: false`，只承诺输入已发送且发送前命中检查通过。网页提交、跳转和业务成功仍需观察确认；检查和浏览器事件之间不是原子操作。中途失败返回已尝试按下次数、已完成点击次数，并明确提示可能已经生效，避免重复提交。

内容四边形和鼠标输入使用视口坐标，`DOM.getNodeForLocation` 使用文档坐标；每次命中检查重新读取页面滚动偏移并转换，覆盖横纵滚动、页面缩放、iframe 和悬停后继续滚动的情况。几何位置没有命中节点时按未命中处理；真实传输错误仍中止操作。失败回执保留视口点、文档点和滚动量，便于定位问题。

`take_snapshot` 默认最多 60 行、正文约 7,000 个转义后字符。正文只放 `content`，`structuredContent` 保留计数、预览/遗漏信息与 `nextCursor`，不再复制整份快照。支持 `rootUid` 子树、`query` 关键词、`roles` 角色过滤；忽略无内容通用节点和重复 InlineTextBox。长字段默认预览，`rootUid + fullText:true` 可按字段/字符偏移分段读原始 AX 文本，续读相同游标结果稳定，不消耗或屏蔽已读节点。

分页固定在同次采集；导航、重新采集和会话/浏览器不匹配会明确返回失效原因，不伪装成无匹配。保留的紧凑文本单份最多 512 KiB / 4,000 行，全局最多 2 MiB / 8 份，三分钟自动清理，释放连接时立即清理。超限明确报告遗漏，允许继续用过滤器读取；不保留完整原始 AX 树，不新增常驻服务。首次采集仍需浏览器读取 AX 树，分页主要减少模型返回、重复传输和后续重复采集。

回归：`npm run test:chrome-actions`。使用独立隐藏 Electron 窗口和真实 CDP，不操作用户浏览器。覆盖零尺寸提交控件三次实际提交、遮挡/禁用/移入变化、Shadow DOM、iframe、点击中断及快照分页、原文续读、失效与预算。

## 已落实

- 插件目录中 Browser Use 和 Computer Use 的卡片描述、详情及示例提示词跟随界面语言即时切换。清单默认文案为英文，`cardbush.localizations.zh` 提供中文；宿主解析后由显示层按语言取值，缺项回退默认文案，不改写插件配置。其他插件也可选填 `cardbush.localizations.zh/en` 的 `shortDescription`、`longDescription`、`defaultPrompt`。
- 设置侧栏独立提供「浏览器」和「电脑操控」。Browser Use 连接、启停以及 Computer Use 原有配置可直接管理。
- 标签使用网站图标、较宽的标题区域和常显关闭按钮；空间不足时横向滚动，并保持当前标签可见。悬停可查看完整标题与网址。「＋」紧跟标签，点击直接创建独立新标签页并聚焦地址栏。新标签页在本地展示工具入口、常用网站和收藏夹；未收藏时提供 Google 入口。
- 网页实际发声时，在该标签关闭按钮左侧显示静音按钮，标签列表中也可操作；无声且未静音的标签不显示、不占位。静音后保留恢复按钮，只控制当前 guest 的音频输出，不暂停媒体或修改网页音量，刷新与同标签导航保持静音。音频状态由 Chromium 事件驱动，覆盖后台标签、子框架和 Web Audio，不轮询网页。
- 网站图标跟随网页的 favicon 更新，并按来源保存少量本地图标元数据供收藏夹复用。未访问的收藏尝试网站自身的 `/favicon.ico`，加载失败时显示通用图标，不通过第三方图标服务转发网址。
- 地址栏支持网址和搜索词：普通域名补全 HTTPS，localhost/本机回环地址使用 HTTP，其他文字交给 Google 搜索。空白输入不导航，本地路径与可执行协议不会发给搜索引擎。
- 地址栏星标旁提供「安装为网页应用」，单页与多页面模式均可用。确认名称、启动网址和可选的侧栏固定后加入应用中心，显示网站图标，支持搜索、固定、拖动及移除，也可用 `@` 引用应用。从应用中心启动使用 CardBush 内置浏览器，复用网站的 Cookie/存储；移除应用只删除入口与固定项，不清理网站数据。安装范围是 CardBush 应用中心，不注册系统 PWA 或桌面快捷方式。
- 网页应用有独立的 `web` 类型和保存记录，不改变原有外部链接的启动方式。只在用户打开安装界面后读取当前 guest 的网页清单，按 [Web Application Manifest](https://www.w3.org/TR/appmanifest/) 解析同源启动地址、身份和范围；优先清单名称/图标，无清单或读取失败时使用当前网页。按应用身份去重，安装前后校验标签归属和网址，读取有截止时间与大小边界；网页清单不能注册插件、调用工具或获得额外权限。
- 不再提供初始主页设置，也不读取旧主页配置。新标签以 `about:blank` 创建，Connector 的 `new_page` 未提供 URL 时也如此；显式 URL 保持原目标。在新标签中打开网址复用原 webview，保留每个标签的独立状态。
- 标签页列表右侧的竖向三点菜单提供页内查找（含网页中的 Ctrl+F）、原生打印、网页缩放、响应式设备工具栏、可见页面 PNG 截图、收藏夹导入/检索、下载、浏览历史、数据清理及浏览器设置。页面操作使用当前激活的真实 guest，多页面模式也不转去操作另一个标签页；菜单同时适配浅色和深色主题。
- 浏览器菜单在点击应用内其他区域或真实网页（含内嵌页面）、按 Escape、窗口失焦时收起。网页点击通过宿主已有的 guest 输入通知关闭菜单，保持该次点击和网页输入焦点；菜单内的缩放操作继续保留菜单。
- 收藏夹可从本机 Chrome / Edge 的 Default、Profile 配置读取，也可手动选择浏览器导出的 HTML 或原始 Bookmarks JSON。导入仅解析数据，拒绝可执行协议和含凭据的网址；保留目录名称，按规范化网址去重合并，移除原有 100 条静默截断。新标签保留前 12 项快捷入口，并在下方展示完整收藏夹，支持按名称、网址、文件夹搜索，每次展开 24 项，点击直接在当前标签打开；导入和管理入口在区域标题旁。管理弹窗每页 50 项。密码、Cookie 和联系信息不在导入范围。
- 浏览历史从升级后的访问开始记录，最多保留最近 5,000 个网址；下载元数据最多保留 1,000 项，支持运行中暂停/继续/取消及在文件夹中显示。重启后未完成的下载标为中断，不伪装成仍在运行。浏览数据保存在用户资料的 `browser/library.json`，只供本地 UI 使用，不加入模型上下文。清除下载记录不删除文件，运行中的下载记录也会保留。
- 数据清理允许独立选择历史、已结束的下载记录、网页缓存和当前网站数据。站点清理校验选定 guest 与当前来源，按来源删除 Cookie/存储，不清理应用的 localStorage、收藏夹或会话；页面地址变化后要求重新选择。导入和管理 IPC 只允许主窗口，网页没有桌面桥。
- 内置网页默认以 100% 比例显示，支持用户主动调整 25%–500%，跳转和刷新保留 Chromium 的站点缩放；不再按面板宽度自动缩小字体。较宽页面使用网页自身的横向滚动。拖动面板仍合并尺寸更新，避免每一帧触发文档重排。
- 右侧面板停靠时，拖动窗口右边缘或右侧角点优先调整右侧面板，保持会话区宽度；到达面板最小宽度后再压缩会话区。窗口左边缘、移动、最大化和还原保留各自的自适应规则，通过系统拖动事件区分，避免根据窗口尺寸变化误判。
- 网页由 Chromium 正常绘制，加载完成不再叠加自上而下的裁切或淡入动画，避免每次导航结束时把已显示内容重新隐藏再展开。加载提示只跟随顶层文档导航。滚动触发的 iframe 延迟加载、页面内跳转不再遮住正文；已经显示的网页在后续导航等待期间保持可见。超时后收到成功的文档就绪事件会自行清除超时提示，无需再刷新一次。
- 内置网页不能直接唤起系统应用：主页面、隐藏 iframe、重定向及弹窗中的 `bytedance:` 等应用协议均被拦截，会话权限同时拒绝 `openExternal`，避免反复弹出 Windows 应用选择或商店提示。普通网页导航、页面内资源和工具栏显式「在外部浏览器打开」继续可用；权限策略统一由 `electron/appSessionPermissions.ts` 管理，应用麦克风仍仅允许主应用页面使用。
- `chrome`、`computer-use` 及大小写、下划线别名保留给核心能力。安装器拒绝外部同名包；目录扫描忽略旧的同名用户包，保留随应用发布的实现。普通插件安装和管理不受影响。

插件页面只复用核心设置组件和展示目录信息，核心组件没有反向导入插件管理页面或其样式。配置仍兼容现有 `apps.json` 中的 Chrome / Computer Use 条目，避免迁移时丢失用户设置；工具服务总开关暂时仍沿用现有逻辑，关闭时独立设置页会说明原因。

运行时继续由 CardBush 注册固定的 `browser_use` 和 `cardbush_apps` 服务。MCP 是进程通信和工具描述接口，不意味着普通插件能接管核心实现或权限。随应用的 `assets/plugins/` 目录保留现有资源打包方式。

Electron 的扩展支持是 Chrome 扩展 API 的子集，不能承诺任意 Chrome Web Store 扩展都在内置浏览器中运行。这也是连接外部浏览器的原因：[Electron 官方说明](https://www.electronjs.org/docs/latest/api/extensions)。内置站点权限、存储清理与下载入口可以利用 Electron 的会话接口逐项实现：[Session API](https://www.electronjs.org/docs/latest/api/session)。

## Computer Use 多屏与截图坐标

`observe` 的窗口发现结果包含 `displays`：屏幕 ID、物理像素范围、工作区和缩放比例，以及每个窗口所在的屏幕。`screenshot` / `observe` 可以传入返回的 `display_id` 获取单屏原图；不传则保留原有发现或整个扩展桌面截图行为。屏幕总览仅供观察，操作仍须绑定具体窗口的 `hwnd` 和一次性 `state_id`。

- 原生截图和输入线程使用 Per-Monitor V2 DPI 感知。窗口操作坐标按物理像素计算，不再额外乘 Windows 缩放比例；主动指定的截图裁剪/缩放仍由已有 `image.origin`、`image.scale` 说明映射。
- Runtime 尊重 MCP 的 `codex/imageDetail: original`，将原始字节存入不可变图片快照，不与普通压缩版本混用。原图大小超过现有限额时明确报错，建议单屏或局部截图，不静默缩图。此保证针对本地传递链路，模型服务自身的视觉预处理由服务商决定。
- 每次观察记录屏幕布局签名和目标窗口 DPI；输入前重新检查。连接、移除、位置、缩放或工作区变化后，旧观察会被拒绝，要求重新观察。检查发生在工具调用与原生操作边界，不增加后台轮询；长文本和拖拽过程还会复查目标窗口范围与 DPI。
- `PrintWindow` 失败或画面内部呈均匀颜色时，尝试经过验证的可见窗口截取：目标必须位于前台，完整落在真实屏幕范围内，且没有其他窗口遮挡。复制前后都复查目标、位置及屏幕布局，遵守窗口的禁止截屏设置。仅仅黑色或纯色不等于失败；无法验证的纯色图会标记 `visual_evidence_verified: false` 并阻止物理输入。
- 此实现未引入 Windows Graphics Capture。`PrintWindow` 卡住仍受原生工作进程超时保护；受保护内容、被遮挡的截图失败和部分 GPU 窗口不能保证恢复。
