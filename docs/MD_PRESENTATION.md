# md演示

应用中心提供内置的 **md演示** 与 **Team**。md演示负责 Markdown、节点图谱和编辑；Team 复用同一套渲染与编辑组件，将节点映射到现有 Team 工作流。顶栏不再提供 Beta 菜单。

## 编辑

- 点击节点编辑名称、正文及引用，切换预览查看 Markdown。
- 拖动节点调整位置；也可以用 Alt + 方向键移动。
- 点击节点右侧圆点，再点击目标节点，目标会引用起始节点。
- 滚轮缩放，拖动画布平移；右下角支持适应画布和自动排列。
- Markdown 模式编辑完整文档，图谱与文本共用同一份内容。格式错误时保留源文并提示，不回退到旧图谱覆盖内容。
- 节点 ID 可修改，已有链接会同步改名；删除节点会移除指向它的链接。

md演示的草稿保存在本机。打开、保存、另存为均使用 `.md` 文件；取消文件选择不会替换当前内容。外部修改后使用“重新载入”，编辑中的内容会先提示是否放弃。保存时检查文件版本，拒绝覆盖外部修改。文件须为 UTF-8，最大 2 MB，最多 128 个节点。

## Markdown 结构

文件头可使用 YAML 属性，普通正文作为文档说明。每个二级标题后紧跟 `md-node` 元数据块表示节点；普通正文中的其他标题和代码示例不会拆成新节点。`[[#节点ID]]` 或 `[[#节点ID|显示名]]` 建立链接，遵循同文件标题链接的写法。

````markdown
---
name: 项目笔记
---

这是一份可以用外部文本编辑器修改的图谱。

## research
```md-node
name: 调研
position:
  x: 100
  y: 200
```

记录问题和证据。

## conclusion
```md-node
name: 结论
```

依据 [[#research|调研]] 整理结论。
````

代码块、行内代码和转义的 wiki 链接只是示例，不建立关系。普通 Markdown 可以作为文档说明打开、编辑及预览，不要求先添加节点。此格式是一份 `.md` 文档内的图谱，不扫描外部 Obsidian vault。

正文含未闭合代码块或展示 `md-node` 格式本身时，编辑器会用元数据中的 `markdown` 多行文本保存原文，并用 `links` 列表保存依赖。这避免未完成的代码块吞掉后续节点；图形编辑仍是同一份正文。

## Team 装配

Team 的“团队流程”页直接使用 md演示。节点增加员工选择，箭头由前置节点指向等待方。无依赖节点可并行，汇总节点等待其引用的节点完成。文档属性增加 `id`、`name`、`max_parallel`，节点元数据增加 `agent_id`；岗位指令、Hooks、Guard、记忆仍在员工注册页管理。

参考 [可编辑示例](examples/team-order-review.md)。示例中的员工 ID 需要先在当前主机注册；打开文件不会执行任务。

“保存 .md”保存文件；**“保存流程”** 才将修改提交给当前 Runtime，随后可在对话中选择并执行 Team。在外部编辑文件后，重新载入并保存流程使编排生效。运行中的团队继续使用启动时冻结的定义。

保存流程时继续校验唯一 ID、已启用员工、有效依赖、无循环、任务内容和最大并行数；运行上限仍为 64 个节点。注册定义使用原有 revision 冲突检查。`name`、`position` 仅用于节点展示，不增加执行职责。聊天右侧 Team 详情复用图谱，只读查看节点和对应员工。

## 验证

`npm run test:md-presentation` 检查 Markdown 往返、链接编辑、循环拒绝、文件取消及冲突、真实 Chromium 中的节点拖动和主题布局。`npm run test:team` 继续覆盖员工与 Team 执行、记忆、依赖调度及会话引用。
