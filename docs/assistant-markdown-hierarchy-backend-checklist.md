# Assistant Markdown 层级：后端对照清单

## 结论

CardBush 前端已经按标准 GFM Markdown 渲染标题、段落、嵌套列表、引用、表格和代码块。后端不需要新增协议字段，也不需要返回 HTML；只需要保证 `assistant_message` 及流式 token 最终组成结构稳定的 Markdown。

前后端职责边界：

- 后端负责表达语义层级：章节、子章节、条目和子条目必须使用正确的 Markdown 结构。
- 前端负责视觉层级：字号、字重、间距、缩进、引导线和窄窗口换行。
- 前端不会根据“Bug 1”“现象”“根因”等自然语言正则猜测层级，避免误判普通内容。

## 后端必须满足

### 1. 标题必须使用标题语法

- 回答主标题可使用 `##`。
- 主章节使用 `##`，章节内的小节使用 `###`。
- `####` 只用于确实存在的第四级内容，不要为了加粗而使用标题。
- 不要用单独一行的 `**标题**` 模拟章节标题。
- 标题前后保留空行。

推荐：

```markdown
## Bug 清除完成

### Bug 1：删除按钮错误显示

#### 根因

共享样式覆盖了 `hidden` 状态。
```

不推荐：

```markdown
**Bug 清除完成**
**Bug 1：删除按钮错误显示**
**根因**
共享样式覆盖了 hidden 状态。
```

### 2. 从属信息必须使用嵌套列表

- 同一对象的“现象、根因、修复、复测”应作为该对象的子级，不要全部放在同一级列表。
- 子列表至少缩进两个空格；推荐统一使用两个空格。
- 每个列表项只承载一个信息点。
- 多个 Bug、文件或阶段可以使用 `###` 分节；内容较短时也可使用顶层列表加嵌套列表。

推荐：

```markdown
### Bug 1：删除按钮错误显示

- **现象：** 新增模式下错误显示删除按钮。
- **根因：** `.btn-icon` 的共享规则覆盖了 `[hidden]`。
- **修复：** 增加统一的隐藏规则。
- **复测：**
  - 新增模式：按钮隐藏。
  - 编辑模式：按钮显示。
  - Escape 关闭：正常。
```

不推荐：

```markdown
- Bug 1：删除按钮错误显示
- 现象：新增模式下错误显示删除按钮
- 根因：共享规则覆盖 hidden
- 修复：增加隐藏规则
- 复测：新增模式正常
- 编辑模式正常
```

### 3. 段落、列表和表格之间必须留空行

- 标题与正文之间留一个空行。
- 段落切换到列表、表格或代码块前留一个空行。
- 不要把标题、解释和列表连续挤在同一行。
- 表格只用于字段严格对齐的内容；叙述性内容使用列表。

### 4. 代码必须使用正确的代码语法

- 文件名、符号、命令参数使用行内代码，例如 `` `server.js` ``。
- 多行代码使用 fenced code block，并标注语言。
- fence 开始行只包含语言名，代码从下一行开始。
- 不发送空代码块。
- Windows 路径不要误放到 fence 的语言位置。

推荐：

````markdown
```css
.btn-primary[hidden] {
  display: none;
}
```
````

### 5. 状态说明使用一致结构

建议终轮回答固定为以下顺序，缺少某项时可省略，但不要改变剩余项的相对顺序：

1. `## 结果`：一句话说明是否完成。
2. `## 修改`：按功能或文件分组说明修改。
3. `## 验证`：列出测试、构建和人工验证结果。
4. `## 注意事项`：只写未完成项、风险或需要用户处理的内容。

状态词使用明确文本，例如“通过”“失败”“未执行”，不要仅依靠颜色或 emoji 表达结果。

### 6. 流式输出必须保持结构稳定

- SSE 协议和现有 `message_id`、`assistant_segment_index` 路由保持不变。
- 同一 assistant segment 的 token 只能追加，不能重复发送已输出文本。
- 已经开始的标题或列表不要在后续 token 中改写为另一种层级。
- 不要在一个 token 中拼接上一段的结尾和下一段标题而缺少换行。
- 分段结束时保证 fence 成对闭合；异常中断时应在最终持久化内容中修复未闭合 fence。
- `done.assistant_message` 保持当前分段的最终 Markdown，不要改成 HTML，也不要把不同 segment 重新拼接。

## 推荐的系统提示词约束

后端可将下面内容加入负责最终回答格式的系统提示词，而不是对模型输出做高风险的正则重写：

```text
使用标准 GFM Markdown 输出。用 ## 表示主章节、### 表示子章节；不要用单独一行的粗体模拟标题。同一对象的现象、根因、修复和验证必须放在该对象标题下，或使用正确缩进的嵌套列表。标题、段落、列表、表格和代码块之间保留空行。多行代码块必须标注语言且 fence 开始行不得包含代码。不要输出空代码块或原始 HTML。
```

## 后端验收矩阵

| 场景 | 必须验证的结果 |
|---|---|
| 单个问题 | `##` 结果下包含一个 `###` 问题小节 |
| 多个问题 | 每个问题各自使用 `###`，内容不混入同级列表 |
| 现象/根因/修复/复测 | 使用小节内列表，复测明细可继续嵌套一级 |
| 命令与文件 | 文件名和短命令使用行内代码 |
| 多行代码 | fence 有语言、内容另起一行、正常闭合 |
| 表格 | 表头、分隔行和列数一致，前后有空行 |
| 流式输出 | token 仅追加，标题和列表缩进在完成前后保持一致 |
| round/segment 切换 | 新 segment 独立输出 Markdown，不与上一 segment 尾部粘连 |
| 中断/超时 | 持久化内容不留下未闭合 fence 或半个表格头 |
| 历史刷新 | 重新加载后的 Markdown 文本与流式完成时一致 |

## 联合验收样例

后端回归测试至少应覆盖下面的最终文本，并由前端在宽、窄窗口各检查一次：

```markdown
## 修复结果

已完成 3 个问题的修复并通过回归验证。

### Bug 1：删除按钮错误显示

- **现象：** 新增模式下按钮可见。
- **根因：** 共享样式覆盖 `[hidden]`。
- **修复：** 在 `admin.css` 增加统一隐藏规则。
- **验证：**
  - 新增模式隐藏。
  - 编辑模式显示。

### Bug 2：favicon 主题色不一致

- **修复：** 将 `index.html` 与 `admin.html` 的主题色统一为 `#e8352a`。

## 验证

| 检查项 | 结果 |
|---|---|
| 弹窗交互 | 通过 |
| API 对拍 | 25/25 通过 |
| 构建 | 通过 |
```

前端验收标准：标题层级明显、嵌套内容有缩进和引导线、窄窗口不横向撑开、代码与表格仍可读、工具卡片和用户引导状态不受 Markdown 样式影响。
