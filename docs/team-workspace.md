# 协作流程

[English](team-workspace.en.md) · [简体中文](team-workspace.md)

Team 的桌面入口以流程图和对话为主。新建流程先保留输入草稿，首次发送时才创建会话和工作区；用户描述目标后，Agent 通过已有 `subagent` 和 `team` 工具注册员工、保存节点与依赖。界面不要求用户先写 Markdown 或填写配置表单。

- 图中的节点、连接来自 `TeamWorkflow.nodes` 和 `depends_on`；运行视图使用 `TeamRun.workflow` 快照以及真实节点状态。文档链接、画布坐标和模型回复不会成为执行依赖。
- 每个流程复用自己的会话，支持模型选择、权限、排队、交互问题、停止和连接恢复。底部复用创作的 `InspectorCoverControls`，默认只显示“输入”和拖动柄，点击后展开简要会话，流程图保持原有大小。创作和流程无需“返回”按钮；会话使用正常 `ChatPanel`，右侧面板沿用普通会话能力。
- 创作和流程沿用普通会话归属：未选项目进入“最近”，显式选择项目则归入该项目，自动任务目录只供执行使用。打开输入框、编辑临时文档或重新开始对话不会提前创建历史记录；首次发送沿用普通会话的草稿持久化、去重与重试机制。历史空会话保留但不展示，旧版误标为项目的自动目录按任务目录展示。
- 接收请求与执行结束时刷新会话列表；从最近或项目打开后继续同一个会话，返回编辑器仍保留该记录。切换视图重新读取已保存的历史。首次发送创建的会话带有 `conversation_started` 标记，首次运行尚未提交历史时也显示在列表里。
- 输入直接复用 `Composer`，跟随“组件”里已有的标准／精简设置（包括欢迎页布局覆盖）。流程浮动面板内保留所选样式；切换样式或关闭输入保留草稿、附件、模型与权限。右侧覆盖式快捷输入仍使用原有紧凑模式，返回流程后恢复所选样式。点击画布或 Escape 收起输入；运行、新建对话或让 AI 调整步骤时自动展开。
- 每次提交固定流程 ID、版本、所选节点和运行 ID。切换页面不会改变排队请求的目标。Agent 保存前仍须读取最新版本并使用版本校验。
- 流程图复用创作的 `MdGraphCanvas`，支持缩放、平移、拖动节点、自动排列和从端口连接依赖；步骤名称优先展示可读名称。拖动与依赖变更自动保存并校验版本，保存期间保留画面位置，失败或版本冲突后恢复最新定义。环路和重复连线不会保存。
- 点击节点展开职责、上游输入、输出或错误，当前流程可断开依赖或让 AI 调整步骤。默认打开可编辑的当前流程；历史运行使用独立的只读快照，可一键返回编辑，修改配置不改写已经开始的运行。
- 视图选择复用 `SettingsDropdown`，以“当前流程／历史运行”分组，完整展示时间、状态、版本、进度和运行输入。支持键盘选择、长列表滚动和窄窗口；显式选中的历史运行不会被后台新运行替换。
- “运行”通过当前对话发送请求；“停止”停止实际运行。其他会话创建的失败运行通过“在原会话继续”返回其所属会话，保留运行归属和恢复规则。
- “更多”保留员工管理和 Markdown 导入。导入先预览，写入时校验读取到的版本；导出以及在“创作”中编辑保留原有说明文档。原有流程和运行数据无需迁移。

验证：`npm run test:md-presentation`。界面测试使用模拟会话服务，不调用付费模型；覆盖首次发送创建、默认／项目归属、工作区与项目目录分离、重试与草稿保留、创建结果同步、历史快照、输入目标、会话复用、拖动与连线保存、循环依赖、并发版本冲突、分组列表键盘操作、深浅色和窄窗口。
