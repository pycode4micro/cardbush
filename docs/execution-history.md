# 时间与历史执行查询

系统提示只保留一条固定规则：任务需要当前日期、时间或时区时，由 Agent 通过终端工具获取。主 Agent 与子 Agent 共用这条规则，不再自动追加 `session_environment` 日期消息。

## `search_execution_history`

Agent 填写 1–3 个关键词和一句描述；本地使用明确的标识匹配和 BM25 词项匹配检索摘要，不调用额外模型，也不要求所有关键词同时命中。例如：

```json
{
  "keywords": ["verify_4k", "补漏"],
  "description": "查找之前抽查头部遮罩覆盖的执行记录"
}
```

- 默认查询当前项目的未删除会话；无项目时只查当前会话。工作副本按源项目归属匹配，不通过模型传入任意项目或会话 ID 扩大范围。
- 每页最多返回 5 条摘要，包括稳定记录 ID、记录时间、工具名、执行状态和命中的关键词。保持查询内容不变，传入 `next_offset` 继续读取摘要。
- 文件名、路径、带分隔符的工具名及日期等标识完整命中时优先返回（`match_type: identifier`）；随后是其他关键词命中（`keywords`），最后是描述或词项相关结果（`related`）。不同层不混在一页，避免为了凑满 5 条而注入弱相关内容。没有精确命中时自动返回下一层；没有任何匹配时为 `none`。所有候选仍可通过分页访问，不合并不同执行事件，也不滤除失败、取消记录。
- 标识按 Unicode 规范化、大小写和斜杠统一后匹配字母数字边界，`exe` 不再匹配 `exec`。词项使用明确的标识拆分和相邻中日韩字符对，不依赖 Node/Electron 的 `Intl.Segmenter` 字典差异；常规 `learn` 检索规则不变。
- `recorded_at` 是工具回执的入库时间，不是完整任务的开始或完成时间；`returned` 只表示工具返回。摘要保留原始错误及明确的结果状态，不替模型判断任务是否完成。
- 摘要最多 640 字符，来自参数中的标识字段、文件变更路径和返回文字的短摘录。文件记录保留原始 `purpose` 与前 3 条 `points`；工具返回的 `note` 优先于输入参数。长路径压缩中部以保留文件名。不重新判断这些备注是否正确，不会返回文件正文、图片数据、撤回快照或 diff，没有读取原始全文的模式。
- 检索基于摘要中的可见词项，不提供语义同义词保证。未命中不表示操作从未发生；Agent 可以更换关键词继续检索。
- 查询工具自身的执行记录不参与检索，避免递归命中过去的搜索结果。

## 存储与兼容

新工具日志在原始大载荷前保存单独校验的轻量摘要。完整执行记录及原有读取接口保持不变。

首次查询某会话时，在其工具日志旁建立可重建的 `.jsonl.history` 索引；后续只处理新增的日志段。查询不调用整份日志的 `load()`，也不恢复冷却的 diff／撤回载荷。项目归属读取轻量会话元数据，不构造完整对话快照。

摘要与索引有格式版本。旧索引在下次查询时从原始日志重建，旧摘要头不会阻止新规则补回用途和要点；不改写原始日志。当前版本的摘要头可直接读取，避免重新解析大载荷。

旧日志没有摘要头，首次建立索引时逐条读取和校验；单条超过 16 MiB 的旧记录会跳过并通过 `unindexed_oversized_records` 明确返回遗漏数量。如果超大旧记录已有经过校验的旧摘要，则保留旧摘要，并通过 `unrefreshed_summaries` 返回未能升级的数量。带当前版本摘要头的记录不受这个旧格式回填限制。未完成的日志尾部不作为执行事实。

索引与原始会话日志共用清理归属，删除会话后查询不再返回其记录；无引用缓存维护同时回收索引。返回值用独立记录 ID 标识摘要，不携带外部会话引用，避免查询本身把已删除会话的完整日志留住。摘要不会被自动注入用户消息或固定前缀，只有模型主动调用查询工具才返回。

## 验证

`npm run test:execution-history` 覆盖摘要边界、精确与弱相关排序、跨层分页、执行状态、旧索引迁移、超大旧记录、项目隔离与默认逻辑检索回归，并比较 Node/Electron 的同一组查询。

`node scripts/replay-execution-history.mjs <sessionId> <turnId> [runtimeRoot]` 可只读重放已提交轮次中的当前会话范围查询。按每次查询前的记录范围重算，对比原响应大小与候选，验证所有分页的跨环境一致性；索引迁移只发生在临时副本，不执行任何历史业务工具。报告仅包含摘要计数、ID、工具名、检索词和校验摘要，不输出原始结果链接或完整对话。
