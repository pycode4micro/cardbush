长回执两轮按新 A、旧 A、旧 B、新 B 的顺序分别运行。新版直接带入更多原始证据，追问输入为 17,537–17,591 tokens，旧版为 16,721–16,980 tokens。这个小样本显示可省去后台模型往返，前台回复耗时没有稳定改善。两种样本共用一组事实，不能据此推断线上准确率或延迟分位数。[逐次调用耗时、模型答案和评分](../packages/bush-runtime/test/fixtures/assistant-retention-live-20261119.json)

## 原文和旧会话

- 空闲维护先尝试缩短旧工具回执中的长日志，保留用户原话、调用参数、回执 ID 和消息顺序。只有能够腾出足够空间时才写入这项变更。新输入仍可取消正在等待模型的空闲维护。
- 正文或不可缩短的回执仍然触发语义摘要。摘要旁按位置附带用户原话和工具事实，单项过长时标出摘录，较早记录可按范围回读。在有限的摘要预算内，部分细节仍需回读核实。
- 原文位置指向当前 Assistant 会话的追加日志。个人 Assistant 可以用 `read_conversation_history` 分页回读，重启后仍有效，清空会话后旧位置失效。已有旧版摘要首次打开时会补上原文位置，无需重新调用模型。原文回读限于可见记录，隐藏推理和模型供应商的回放数据会被过滤。
- 自动回归覆盖前台紧急整理、用户打断、连续摘要、嵌套任务回执、旧会话升级和跨页回读。上表的模型追问禁用工具，因此记忆分数只反映直接带入上下文的事实。回读能力另由运行时集成测试验证。

## 复测

先构建运行时，并确保本机 CardBush 已配置可用的默认模型。每条命令使用一个新的输出文件，脚本仅创建临时合成会话。要复测旧版，向同一脚本传入 `--runtime <旧版已构建的运行时目录>`。每个版本使用相同模型和适配器。

```powershell
npm.cmd run build --workspace @cardbush/bush-runtime
node scripts/probe-assistant-retention.mjs --live --scenario receipts --output receipts-run.json
node scripts/probe-assistant-retention.mjs --live --scenario narrative --output narrative-run.json
```
