# 插件卸载

禁用只停止加载，保留安装文件、配置与数据。用户安装插件的卸载由主进程接收插件 ID，宿主读取当前安装记录，并完成以下操作后才报告成功：

1. 在现有 Apps 配置锁内关闭加载，写入 `removalPending`。不另建安装记录或清理数据库。
2. Runtime 确认没有执行中的回合或插件命令，取消该插件的后台 hooks，释放原生扩展，等待 MCP 连接及其进程树清理结束。
3. 删除插件自己的 OAuth 缓存和私有密钥引用。其他插件/独立 MCP 共用的密钥引用及共享账号保留。
4. 删除 `userData/plugins/<id>`、`userData/plugin-data/<id>` 和 Runtime 的 `plugin-data/<sha256(id).slice(0,24)>`。仅接受受管理根目录中的直属真实目录，拒绝目录联接越界；原始 ZIP、源代码目录、市场来源和工作区产物不属于安装目录。
5. 清除 Apps 配置中的插件记录。再次安装使用新配置。

安装和卸载使用同一生命周期队列；实际文件操作另有短期队列，读取目录不会在 Runtime 清理期间互相等待。配置锁阻止旧草稿覆盖卸载结果。

运行忙碌、连接清理失败或文件删除失败时，界面显示“卸载未完成”，不报告成功。现有配置保留停用的重试入口；即使包已部分删除，重启后仍能继续清理，也不会重新装载残留能力。

随应用发布的内置组件只提供停用，不使用“卸载”表示保留包文件。历史会话和工具记录不因卸载删除。

验证入口：`npm run test:plugin-uninstall`。覆盖真实 MCP 退出、真实 Runtime 原生命令占用与释放、后台 hooks、目录越界、部分删除后重试、配置冲突、重装及界面行为。
