# Your Friends：事件交互与界面方案

更新：2026-11-04。状态：交互预览与基于认知资料的形象生成已接入 App，事件执行与元认知／habit 闭环尚未接入。下文架构为目标设计，不代表已有运行能力。

当前可体验：Assistant 下方入口、从入口展开的圆形过渡、保留底层工作区的返回、默认启动与命名、可续接的逐步认知流程、基于认知资料生成并修改 SVG 形象、三个可选内置形象、资料／边界确认、用户事件原话／关联／归档，以及明确标注的渐进执行示例。进入、认知和日常主界面不展示占位形象；示例不会操作项目文件。

当前资料、草稿和用户事件保存在本机 App 存储；边界选项仅为偏好草稿，不是运行时授权。形象生成复用配置的模型与 Runtime，生成请求不开放工具；此阶段尚不创建事件检测器、自动发送消息、生成 habit 或调度事件执行 Agent。

本文落实用户最新约束，并取代[数字分身初案](DIGITAL_TWIN_DESIGN.zh-CN.md)中以目标、关注计划和会话组织产品的部分。Your Friends 并入 CardBush，共享执行、habit、权限和插件基础；拥有独立的进入体验、内容舞台和输入区。产品只管理事件。

**核心职责：Friends 对 habit 的适用、执行一致性和修正负责。其推理上下文由事件执行上下文与元认知上下文组成，不维护用户连续对话，不承担面向用户的对话组织与措辞。沟通层负责理解用户表达、形成可追溯的事件／反馈，以及呈现 Friends 的结构化结果。**

## 1. 已确定的产品约束

- 导航入口紧跟 Assistant，默认名称为 `Your Friends`。用户可命名，入口、空间标题和称呼同步更新；内部身份 ID 不随名称变化。
- 点击入口时，以实际按钮位置为圆心向外展开，覆盖整个 App 内容区域，产生进入另一个应用的体验。
- 设置支持默认进入 Your Friends。直接启动时不伪造来自不可见按钮的过渡；首次进入仍执行初始化，之后直接进入同一个朋友的空间。
- 无新建会话、会话列表、目标面板、任务面板。用户说的话成为事件，分身回应和执行围绕事件组织。
- 输入区属于空间外壳，在底部独立常驻；上方内容区只展示 Agent 的必要表达、状态和渐进产出。
- Agent 依据 habit 选择呈现方式与信息量；宿主保证状态、必要问询、失败和真实交付信息不会被隐藏。
- Agent 可以设计自己的 HTML 动画形象。默认视觉柔和、安静、圆润，减少边框、表格和工具控制台感。

## 2. 参考设计与取舍

Muse 的设计说明强调可命名的个人形象、可查看的活动，以及只在有意义时主动出现的信息。借鉴其亲近感和个人归属感；其会话／目标组织不作为本产品的数据模型。[Muse 设计说明](https://introducing.muse.ai/)

Grok Bot 的设计说明强调用形象表达状态，按需查看执行，并用结构化产物承载合适的信息。借鉴状态表达和逐步披露；不照搬其多 Bot 名册和聊天组织。[Grok Bot 设计说明](https://x.ai/news/designing-grok-bot)

这些是公开设计说明中的原则，原型中的布局、角色和过渡为 Your Friends 自行设计；未将参考产品的实际运行表现当作本轮验证结果。

## 3. 产品对象：朋友与事件

### 3.1 用户的话就是事件

每次真实用户提交都会在接收层保留不可变的原始记录，包括闲聊、分享兴趣、要求执行、补充信息、纠正和取消。沟通层识别其中的事件与反馈，保留原话及来源引用；有歧义时由沟通层澄清。事件不要求附带目标、任务描述或预先选择的会话。问候可以在沟通层以回应结束，无需唤醒 Friends；偏好表达可以成为 habit 候选证据，具体请求可以形成执行事件。接收记录不会自动进入 Friends 的累计对话历史。

例如：

- “最近又开始看 NBA 了。”——一条用户事件；可以交流或澄清，不据此悄悄打开每日推送。
- “有我关注球队的比赛就提前告诉我。”——一条用户事件；在授权范围内建立关联检测。
- “以后别告诉我比分。”——新的纠正事件，关联先前偏好、检测与待交付内容。
- “先别继续了。”——新的用户事件；在对象明确时暂停对应执行或监测，不把历史删掉。

父 Agent 的决定、子 Agent 回执和采集结果不能伪装成真实用户事件。后台触发仍受支持：它形成 `EventOccurrence`，带来源证据，关联此前用户事件或用户明确授予的持续委托。

用户事件是产品对象；模型 Turn、内部任务、上下文压缩和执行会话只是技术实现。使用既有运行时不意味着 UI 需要暴露这些概念。

### 3.2 补充、关联与管理

事件之间使用明确关系：`continues`、`corrects`、`cancels`、`answers`、`triggered_by`。即使界面把连续补充收束到同一事件下，原始输入、作者、时间和修改关系仍可查询。

独立输入框默认创建新事件。选中一个事件时，可以出现“补充这件事”的轻量引用；用户可取消引用。审批回答必须绑定具体请求及版本，不能由模型猜测一个“可以”究竟批准了什么。多个事件并行时，对含糊指代先澄清对象，避免把用户的话送入错误执行。

事件抽屉只提供查看、补充、暂停／继续、停止后续关注和归档。归档改变展示，停止改变未来执行，删除／忘记属于独立数据操作。不能把事件改个名称做成传统任务清单，也不要求用户维护项目层级。

建议状态为“已收到、处理中、等你回应、持续关注、已完成、已暂停、遇到问题”。一次结果已经交付、但后续仍在关注时，同时保留结果状态与订阅状态，避免单一“完成”使人误以为监测停止。

### 3.3 上下文：事件执行与元认知

Friends 每次被事件、执行回执或相关反馈激活时，按需装配两部分上下文：

| 部分 | 内容 | 生命周期 |
| --- | --- | --- |
| 事件执行上下文 | 当前事件及明确关联、必要的原始证据、执行进度、工具／子 Agent 回执、待解决事项、产物与有效委托引用 | 随事件推进；可从持久状态恢复，完成后保留证据而不累积到全局聊天历史 |
| 元认知上下文 | 本次相关 habit 及其版本和适用条件、采用或不采用的依据、已知例外与冲突、待验证假设、历史纠正及验证结果 | 跨事件保留可追溯的状态；只检索当前判断需要的部分，不把所有 habit 和经历整包注入 |

元认知关注“现有 habit 是否适用于这件事、执行是否符合它、偏差来自执行还是 habit 本身、是否有足够依据修正”。持久化的是结构化判断、证据引用与版本变化，不保存模型内部思维链，也不把每次自我评价当成事实。

一轮闭环为：接收事件 → 装配事件执行与元认知上下文 → 依据相关 habit 决策／执行 → 对照结果和反馈复核 → 保持、补充例外、修订或停用 habit。成功执行本身不能证明用户偏好正确；一次结果也不必产生 habit 更新。明确的一次性要求可以形成当前事件的例外，不自动覆盖长期 habit。

跨事件持续的是 habit、元认知状态与可检索的事件证据。单次事件执行仍可使用有限的模型交互历史；重启或下一次激活依据上述状态恢复，不要求续接上一段用户聊天。不同事件的关联必须有依据，不能因为时间相邻就混入同一上下文。

### 3.4 与沟通层、Assistant 的边界

- 沟通层负责称呼、访谈措辞、指代澄清、自然语言回应和展示编排；它向 Friends 提交带来源的事件与反馈。认知阶段的原话经此入口形成有依据的 habit 候选，不作为 Friends 的永久聊天前缀。
- Friends 输出事件状态、执行事实、habit 判断／变更，以及需要补充的信息或决定。输出携带事件、证据和版本引用；沟通层将其表达给用户，不能修改其事实或把表达加工反写为用户证据。
- 元认知对是否需要修正 habit 负责，执行层对动作和回执负责，沟通层对用户可理解的表达负责。habit 可以约束沟通偏好，其适用和修正仍归 Friends；具体消息由沟通层生成。
- Assistant 可以作为一个沟通入口，Friends 自身界面或其他渠道也可以接入相同接口。Friends 不依赖 `personal-assistant` 的身份、对话记录或系统提示词，两者共享模型传输、执行调度、权限和存储等基础设施。
- habit 表达偏好与决策方式，执行授权仍由宿主管理；维护 habit 不会自行授予新动作权限。

## 4. 导航、命名与默认进入

入口顺序为 Assistant → Your Friends，处于同一导航层级。入口不藏进 Assistant 设置页。命名后入口显示用户名称，设置中的功能说明仍能识别这是 Your Friends。

进入后采用覆盖 App 内容区的独立外壳：主侧栏退到下层，朋友空间保留轻量“返回 CardBush”、名称、事件入口和设置。窗口原生关闭／最小化等能力继续可用。退回后恢复之前页面、滚动位置和焦点，后台事件不因离开空间而自动取消。

设置包含：朋友名称、启动时默认进入、动画偏好、信息展示偏好、必要通知和授权入口。启动目的地使用稳定路由 `your-friends`，不保存用户名称作为路由。

启动顺序：明确外部深链／文件打开请求优先，其次用户设置的默认入口，最后既有启动回退。默认进入未完成初始化的朋友时，继续未完成的交流。重命名不重建身份、不清空 habit、不重跑初始化。

## 5. 圆形进入动画

点击时记录按钮中心在 App 内容根节点中的坐标。最终半径取圆心到四个角距离的最大值，并留覆盖余量；不使用固定宽高推测，不用一个缩放后仍露角的椭圆蒙版。

建议初始动效参数（实现后按真机调整）：

| 阶段 | 表现 |
| --- | --- |
| 按下 | 入口轻微压下，立即提供反馈 |
| 展开 | 约 600ms 的圆形裁剪展开，前段迅速离开按钮，后段柔和减速 |
| 内容出现 | 在展开后段，形象、标题和内容轻微上移并显现；不等待网络请求才开始过渡 |
| 返回 | 可向仍存在的原入口位置收拢；位置失效时短淡出，恢复原页面焦点 |
| 默认启动 | 直接进入空间，可有一次轻微显现；不先闪现整个工作区再播放圆形动画 |

过渡期间不能点击穿透底层界面；重复点击不启动多条导航，尺寸变化重新计算覆盖范围。动效完成、取消和失败都要释放输入锁。遵守 `prefers-reduced-motion` 和应用设置，减弱模式采用短淡入或直接切换；动画不能成为等待状态或阻止操作的理由。

坐标计算属于真实测量，可在 TypeScript 中处理；时长、缓动、色彩、圆角和其他视觉值由 CSS token 管理。

## 6. 页面构成：内容舞台与独立输入区

```text
┌ 返回 CardBush       朋友名称                事件 · 设置 ┐
│                                                       │
│                  动画形象 + 一句状态                    │
│                                                       │
│        Agent 的必要表达                                │
│        当前事件的渐进产出                              │
│        文件变更 / 执行图 / 预览 / 必要确认               │
│                                                       │
├              留白与柔和背景过渡                        ┤
│           独立输入区：对朋友说些什么                    │
└                                                       ┘
```

实现为根外壳的独立行：顶部、可滚动的内容舞台、输入底座。输入组件与内容组件是兄弟节点，不位于消息列表／事件详情内部，不随滚动消失；内容高度需扣除底座实际高度，避免遮住最后一张产物。窄屏和软键盘出现时由可视区域重新布局。

用户发送后，输入清空的前提是事件被可靠接收；失败保留内容并支持重试，重试不得生成重复事件。通过轻量“已收到”与事件抽屉保留输入凭据，不向主舞台追加用户气泡。用户随时可以检查自己的原话与附件。

默认展示一个正在关注的事件及其必要内容；其余事件在轻量抽屉管理，有需要用户处理的事项时显式提示。新进展更新现有产物，不不断追加重复卡片；用户正在阅读时不强行滚到底部或切换到另一个事件。

## 7. 第一次认识：预设结构、自适应交流

访谈有预设阶段和完成条件，具体措辞与追问根据用户回答调整。一次只问一个重点，支持自由输入、简短选项、稍后再说和中途退出。用户已主动提供的信息不重复询问；不索取密码和不必要的敏感内容。

| 阶段 | Agent 可以怎样开口 | 保存什么／何时继续 |
| --- | --- | --- |
| 认识彼此 | “你好。我们先认识一下，我该怎么称呼你？你也可以给我起个名字。” | 用户称呼、朋友名称草案；没有起名则保留 Your Friends |
| 了解当下 | “最近有什么事，你很希望有人能替你记着，或者陪你一起处理？” | 用户原始事件与情境；不强制转换成目标表单 |
| 看见取舍 | “想想最近一件你不满意的代办：哪里没有按你的意思来？” | 具体反例、角色和条件偏好；避免凭性格形容词推断所有行为 |
| 关注与沟通 | “你喜欢从哪里了解这些事？我有发现时，你希望怎么听到？” | 来源、主题、渠道和打扰偏好；渠道未连接时保留待接入状态 |
| 明确委托 | “哪些事情我可以直接处理？哪些先问你？做完以后哪些一定要告诉你？” | 独立、可编辑的授权草案；已有授权不要求重复提交 |
| 认识我的样子 | “你觉得我更像什么？也可以让我先试着设计一个。” | 外形、色彩和动作偏好；生成预览后用户可保留、修改或稍后决定 |
| 复述与开始 | “我先按这样的方式陪你……”随后用简短条目展示理解与边界 | 画像和授权分别确认；把此前用户事件接回处理，不创建虚构目标 |

实现状态为 `not_started → in_progress → ready`，允许 `deferred`。对话草案逐步保存，恢复到最近未完成阶段；“已了解”不等于“用户已确认”。用户可以先完成最小初始化，其余通过之后的自然事件补充。

最小初始化包括：称呼／默认名称、至少一段用户真实表达、明确的初始委托范围，以及复述确认。外部渠道和个性化形象都不是开始交流的阻塞项。

初始化交流由沟通层承接；经确认的角色、条件偏好与反例形成有来源的 habit／元认知状态，Friends 在相关事件中按需读取。原始交流和推断分别保存来源，不能把整段访谈变成永久高优先级对话前缀。授权仍由宿主执行，不靠一段“非常重要”的文字赋予权限。

## 8. 动画形象

形象是这个朋友的身份和状态载体。默认采用小体积、柔软的有机形态，有可辨认的表情和克制动作；不默认写实人脸，不使用不断跳动、发光或撒娇的方式制造注意力负担。

支持状态：安静待机、收到输入、处理中、等待外部结果、等用户回应、完成、遇到问题。动作由真实 Runtime 状态驱动，配一句可读状态；不能仅凭颜色／动画传达错误，也不能用持续“思考”掩盖已停止的执行。

Agent 根据外形偏好生成版本化 HTML／CSS 动画包；首版优先纯 CSS 与本地矢量／几何元素，必要的脚本仅处理状态切换。生成与修改会调用模型，日常播放动画不会调用模型。可保存多个候选，但仅有一个当前形象，不因此引入多个父分身。

动画包在独立受限容器渲染，不能直接拼进宿主 DOM，不能访问 Electron preload、文件、连接凭据或父窗口状态。默认禁止联网与远程资源，宿主通过受控消息通道发送有限状态；包体、执行预算、版本和失败回退都需校验。生成形象拥有展示能力，不拥有执行工具的权限。

不可见时暂停，减弱动画时采用静态姿态；CPU 异常或渲染失败回退到默认形象。状态提示仍然工作，用户可以随时更换或恢复。

## 9. Agent 决定展示什么，宿主保证什么

新增逻辑上的 `EventPresentation` 层，区分内部执行日志和用户可见内容。Friends 提供结构化事实、状态、产物引用与必要的信息请求；沟通／呈现层按相关 habit 组织措辞和展示，经受控发布接口交给宿主组件。面向用户的消息及其连续性不由 Friends 核心维护；不让模型生成任意 HTML 代替整个操作界面。

推荐展示种类：

| 种类 | 使用场景 | 更新方式 |
| --- | --- | --- |
| 简短表达 | 回应用户、解释关键决定、给出结论 | 有新信息时追加；避免每个工具调用都说一遍 |
| 当前状态 | 用户需要知道仍在工作或被什么阻塞 | 同一位置更新，由真实执行状态支撑 |
| 文件变更 | 修复、写作、配置修改 | 引用真实 diff／产物版本，可展开必要内容 |
| 流程／执行图 | 分工、依赖或阶段关系确实能帮助理解 | 更新同一张图，只表示可验证阶段，不暴露内部推理 |
| 渐进产物 | 文档、界面、表格或其他可预览结果 | 明确草稿／已验证／已交付，稳定 ID 更新 |
| 用户决定 | 缺失信息、授权、审阅和偏好冲突 | 宿主提供真实按钮，绑定请求与产物版本 |
| 交付回执 | 发送、保存或发布的实际结果 | 区分完成、失败和确认未知 |

habit 可以决定更偏好图示还是文字、直接看 diff 还是先看效果、多久报告一次、结论需要多详细。代理可以少展示，但不能隐藏宿主要求呈现的待批准请求、关键失败、停止结果和用户明确要求的通知。

每个展示项有 `eventId`、`presentationId`、类型、证据／产物引用、版本和展示策略。状态与“测试通过”等结果必须引用实际回执，不能只采信 Agent 文本。原始活动可以按需查看，不主动铺成工具调用瀑布；内部推理不作为日志展示。

## 10. 一条执行示例

以下为界面演示数据，不表示真实文件已修改或测试已运行。

用户在底部输入：“设置页切换语言后，有个按钮还是中文，帮我修一下。”

1. 宿主可靠记录用户事件；输入区显示简短接收反馈，主舞台不新增用户气泡。
2. 朋友回应：“我来看看。我会沿用语言包的方式处理，先把改动给你看。”形象进入工作姿态。
3. 找到真实原因后，状态更新为“已找到没有跟随语言切换的文案”。若尚未找到，不提前显示此结论。
4. 原位出现一张产物：文件变更摘要与可展开 diff。若用户偏好执行图，则用“定位→修改→验证”展示当前阶段；没有必要时不同时放两种重复表示。
5. 验证完成后，原卡更新为经过验证的结果，并提供预览／查看变更。失败则展示实际失败和下一步，不用动画伪装成功。
6. 形成学习机会时，由父级按授权处理；需要用户决定才出现一条“以后同类修改也按这个方式处理吗”的具体建议。流程成功不直接变成用户偏好。

原型只需要这一条执行示例和初始化交流，重点验证必要状态、渐进产出与独立输入区，不填充虚构事件、成绩指标和仪表盘。

## 11. 柔和的视觉语言

- 大面积采用温和、低饱和的中性色，配少量雾紫／浅桃／柔绿；文字保留足够对比，不靠降低所有透明度制造柔和。
- 通过留白、圆角和浅层阴影区分层次；减少粗边框、密集分割线、格子状卡片和醒目的状态灯。
- 形象有轻微体积感，输入底座像一个独立、柔软的托盘。主要产物保持清晰，代码 diff 等信息不为风格牺牲可读性。
- 主内容保持适度宽度，宽屏留白、窄屏自然换行；按钮命名直接、语气自然，不堆“系统、代理、执行器”等内部词汇。
- 空闲空间可以安静；不强行摆满快捷按钮、欢迎语和任务推荐。动画完成后收敛，不能长期干扰阅读。
- 深浅主题分别定义 token，遵守减弱动画、键盘焦点和无障碍标签。首次访谈及事件展示中的每一句 App 自有文案都来自语言包。

## 12. 接入现有架构的变化

| 范围 | 推荐落点 |
| --- | --- |
| 导航与启动 | 扩展 [AppSection](../src/types.ts)、[appSections](../src/features/appSections.ts) 和 [App](../src/App.tsx) 的真实路由；入口位于 Assistant 后，启动设置使用稳定键 |
| 新外壳 | 拟新增 `YourFriendsShell`，负责进入动画、顶部、内容舞台、独立输入底座与返回；不通过给旧聊天列表换色完成 |
| 输入 | 复用既有输入能力和附件处理，但提交到事件接口；不依赖当前聊天会话选择 |
| 持久化 | 新增 `UserEvent`、`EventOccurrence`、`EventRelation`、`EventPresentation`、`FriendProfile` 和 `AvatarBundle`；以 owner／friend／event 隔离 |
| 模型上下文 | 分别装配事件执行上下文和元认知上下文；按需读取相关 habit、状态与证据，不依赖连续用户对话 |
| 元认知 | 保存 habit 的适用判断、例外、冲突、验证和修订依据；与事件及 habit 版本关联，不保存模型内部思维链 |
| 沟通适配 | 将用户表达转为有来源的事件／反馈，将结构化结果转为用户可理解的表达；与 Friends 核心独立 |
| 调度执行 | 复用既有调度器、子任务与权限 broker；内部执行标识映射到事件，产品不要求 `goalId` 或公开 `sessionId` |
| 检测定义 | 绑定来源用户事件或真实持续委托；初案 `WatchPlan` 的条件与响应配置作为事件内部配置，不再成为独立产品对象 |
| 呈现接口 | 受控发布状态、表达与产物，支持原位修订；主舞台与活动记录分离 |
| 画像与权限 | 命名、外形和 habit 共享稳定朋友身份；授权保持宿主所有，重命名和换外形不改变权限 |

只有一位朋友，持续的是身份、habit 和元认知状态；事件执行上下文按事件恢复。用户可以连续发出事件，宿主先持久化，再协调相互关系与并发执行，无需将它们拼成一条持续聊天。

## 13. 实现与验收顺序

1. **交互定型**：入口与圆形展开、命名／启动设置、初次交流、内容舞台与独立输入区。原型以示例数据演示，不冒充真实能力。
2. **事件与上下文接入**：可靠输入、原话与关系、沟通适配接口、事件执行／元认知上下文装配、展示协议、真实状态、审批与一个真实执行产物；不以 Assistant 对话历史代替事件状态。
3. **初始化与形象**：可恢复的访谈、确认画像、受控动画包、状态映射、减弱动效和回退。
4. **habit 与元认知闭环**：已有的本地检测、habit 适用决策、执行偏差复核和有证据的修订以事件方式接入；skill／插件建议通过执行能力扩展承接，不另建目标页。

首个完整试用版仍要含基础学习能力；界面原型只用于确认设计，不算该版本完成。

验收重点：

- 入口在 Assistant 下；折叠导航、窗口缩放、键盘进入、重复点击和返回都不露底、不丢焦点。
- 默认进入和名称实际持久化，深链优先，未完成初始化可续接；无工作区／会话也能输入。
- 输入区不属于内容滚动区；长产物、窄窗口、软键盘、附件、发送失败与连续事件都不遮挡或丢输入。
- 原话可追溯，父级输出不成为用户事件；含糊引用、审批版本和停止对象能正确绑定。
- 不提供连续聊天历史也能根据事件状态与元认知状态恢复；不相关事件和用户闲聊不污染当前执行上下文。
- habit 修订能追溯真实证据、适用范围与版本；后续相关事件采用修订，无关事件不被全局重启，执行成功不自动转成用户认可。
- 沟通层可独立替换；表达措辞变化不改变事件事实和 habit，待澄清问题及回答保留对象与版本绑定。
- 只展示必要输出，真实失败和必要确认仍能出现；同一产物更新不形成重复卡片，用户阅读位置稳定。
- 动画形象无宿主能力，离开后暂停；故障或减弱动画下仍可操作并读到状态。
- 运行 [AGENTS.md](../AGENTS.md) 规定的国际化、跨 App 和设置页回归；第一阶段另有 `npm run test:your-friends`，使用隔离资料验证真实界面交互。后续 Runtime、habit、审批与生成形象的验收不由此预览测试代替。
