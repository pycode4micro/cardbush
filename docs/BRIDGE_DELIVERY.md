# 桥接发送与延迟诊断

Assistant 可以直接使用当前工具作用域中由 Runtime 注册的桥接插件。普通 MCP、终端与文件写入能力仍按原有职责交给子 Agent。桥接调用继续经过 `ToolExecutionCoordinator`、文件身份/读取权限检查和消息来源绑定；本地提醒、被禁用的工具及受限执行策略不会因此获得外部发送权限。

## 发送链路

微信桥的出站 Worker 独立于来信转发、Assistant 回复查询和输入状态提示。请求持久化后立即唤醒 Worker；无待发内容时等待事件，有重试时等待登记的重试时间。单个出站 Worker 防止并发扫描重复发送，同一发送的片段保留稳定的平台 client ID，已上传的媒体凭据在重试与重启后复用。文件只有在平台发送成功且完成状态落盘后才清理。

状态包括 `queued`、`uploading`、`sending`、`retrying`、`delivered`、`failed`。查询包含 `phase`、`attempts`、阶段累计耗时、开始/结束时间、最近错误和下一次重试时间。可恢复的传输错误按 1、2、4、8、16、30 秒间隔重试，后续上限为 30 秒；明确的文件缺失、文件身份变化、媒体类型不符及不可信上传地址终止发送。以上判断仅针对协议和传输事实，不判断内容质量，也不指导模型下一步行动。

`accepted` 表示桥接接受调用；`delivered` 表示平台 API 确认，不表示用户已阅读。发送调用的相同请求 ID 仍用于安全重试同一调用，不能跨工具或更换参数复用。只读状态查询重新读取桥接状态，不返回永久缓存的旧快照。

## 完成事件

能力握手声明 `delivery_events` 后，桥接通过已认证的 `POST /api/webhooks/v1/{connectionId}/deliveries` 提交终态。正文为 `protocol`、`eventId`、`sourceRef`、`messageId` 和受约束的 `result`；不包含凭据、CDN 地址或模型指令。

宿主验证连接、原始来信及该连接实际接受的工具调用，持久化不可回退的终态，再写入 Assistant 的 `bridge_delivery_result` 内部事实。它关联原始用户消息，沿用当前 Assistant 配置，不替换模型设置，不恢复用户主动停止的工作。对话 generation 不匹配时不注入旧事件。通知故障可独立重试，不影响后续图片传输；相同终态恢复投递不会重复生成会话事件。晚到的 `queued` HTTP 应答不能覆盖终态。

## 桥接代理模式（2026-11-17）

桥接默认 `direct`，可用 `--proxy system` 或 `--proxy http://127.0.0.1:7897` 选择系统/指定代理，也支持 HTTPS、SOCKS5。选项适用于单平台、`start --all`、登录及诊断，仅对本次启动生效。微信 API/CDN、飞书 API/WebSocket 和远程宿主连接共用同一策略；本机回环通信始终直连。

Windows 直连通过按需加载的、带随机认证口令的回环 CONNECT 隧道，为 TCP 和 DNS 绑定物理 IPv4 上联网卡。TLS 始终在 Node 与平台之间校验和加密；不修改系统代理、路由或 DNS。这样能避免仅忽略代理环境变量后仍被全局 TUN/Fake-IP 接管。依赖活动物理 IPv4 上联网卡和其 DNS；不可用时明确失败，其他系统的普通直连仍受 OS VPN/TUN 路由影响。

实际诊断使用同一上传地址、同一合成图片与同一客户端：原 TUN 路径返回 HTTP 500 / `x-error-code=-5104001`，物理网卡路径成功。新网络实现下，270,448 字节及 1,080,993 字节的合成 PNG 均首次取得媒体上传回执，上传约 371 / 377 毫秒；未调用微信消息发送接口。桥接现在保留受约束的 HTTP 状态和数字 CDN 错误码，并区分 HTTP 200 缺少媒体回执。

验证包括桥接回归、认证代理与 WebSocket 升级、原生隧道认证、真实 CLI 宿主集成及 npm 资源清单。旧 `npm run test:cardbush` 的 14 项测试与当前宿主的 Assistant-only / 工具检索契约不兼容；在修改前的 `6e8578a` 基线复跑同样失败，没有删除断言或将其标为通过。当前主仓库的 `scripts/test-cli-webhook-bridges.mjs` 两项集成通过。

## 执行结果与回复投递分离（2026-11-17）

历史行情请求的前台执行记录为 `failed`，子任务稍后完成并产生了关联该输入的公开回复。旧投影仅处理 `completed` 记录，导致本地已有回复却未送到微信。现在所有终态均可投递随后提交的关联回复；保留原执行状态和错误，仅更新回复及投递序号。已提交的公开回复也不再等待全局 `busy` 解除，其他正在生成的回合不会阻塞它们。连接、输入来源和对话 generation 约束继续生效，不重跑请求、不恢复停止的工作、不判断回复语义。运行错误在回执中保存，避免被后续成功回合清空而失去诊断依据。

发送工具回执增加 `completion` 能力事实：有完成事件通道时为 `mode=event`、`recipient=assistant`、`eventType=bridge_delivery_result`，否则为 `mode=query`。完成事件仍由 Worker 提交，不增加模型调用或发送后的复核流程。平台错误保留发生阶段、操作、HTTP 状态、数字错误码及最多 512 字符的脱敏说明；不推断 `-2` 等平台错误的业务含义，不把文字发送失败误归因为媒体上传失败。

本次视频记录共 24 次尝试、总计约 581 秒，上传累计约 1.6 秒，最近一次失败发生于 `sending_text`。旧记录缺少平台错误说明，无法据此确认各次失败的共同原因。新增反馈用于补齐事实，不承诺未知平台故障已消除，也不替模型决定是否继续查询。

## Windows 激活与输入边界（2026-11-17）

原生控制宿主在持有当前窗口操作时向实际执行进程请求前台资格委托，不使用 `ASFW_ANY`，是否允许仍由 Windows 决定。激活只恢复最小化窗口，发起一次请求并在最多一秒内观察真实前台；失败返回 `activation_failed`、已派发状态、激活前后窗口/PID、系统调用及资格委托结果。动作后的观察复用已有采集，不重复截图。

任务栏观察返回 `pointer_activation_available`。仅真实 Shell 进程的主/副任务栏、未被遮挡的命中点可接受一次左键坐标点击；派发前再次校验前台和命中点，物理用户接管仍会中止操作。点击后不恢复指针，避免把预期的前台切换误判为上下文异常。键盘、拖拽、语义输入及普通窗口仍要求目标在前台；本地不选择替代操作。

回归使用临时桥接状态、本地模拟接口及替换 WinAPI 的生产原生代码，覆盖失败/中断/停止后的晚到回复、重启恢复、跨 generation 拒绝、发送阶段与错误脱敏、前台请求返回值和实际结果不一致，以及伪造任务栏/遮挡命中拒绝。未操作真实桌面或重发历史消息；修改需重启 CardBush 和桥接服务后生效。
