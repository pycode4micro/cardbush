# 记忆整理：有界输入与增量保存

记忆整理使用现有 `RuntimeInternalTaskRunner`，由 Runtime 负责请求、流、重试、超时和取消。记忆模块只负责选择材料、校验结果和保存 SQLite 事务。它不创建普通会话，不装配工具，也不改变普通会话的提示词或顶层 schemas。

## 执行边界

- 事件和习惯的阈值分别判断。默认 10,000 tokens 是触发阈值，不代表积压材料总量，也不代表模型输出额度。
- 每次请求的输入按最多 10,000 tokens 的本地保守预算装配；小上下文还要为用户配置的输出额度留出空间。只按完整记录或完整预测/证据对分批，不截掉条件或证据尾部。
- 保持选定模型的 `reasoningEffort` 和 `maxOutputTokens`。配置与上下文不兼容时报错，不偷偷降低思考档位或输出额度。
- 无待核验预测的材料直接归档，原文和撤销记录保留。已处理的证据对通过持久账本去重。
- 核验请求只带预测、适用条件、实际用户消息和允许核验的配对。完整数据库元数据、长来源 ID、过期时间及历史计数不交给模型重复处理。
- 积压核验最多重叠两个 Runtime 请求，优先处理配对较多的批次。保存使用短串行队列；只接受本次任务自身提交的版本变化，外部编辑仍触发版本冲突。
- 核验只输出命中或明确否定；其余记为未知，未知不算失败。命中和否定必须带对应用户原文中的引用，同一预测的同一用户轮次不能重复计数。
- 核验完成后重新检查剩余预测的容量：已经简短且低于阈值就停止，不因命中数变化而额外发起“推导习惯”的请求。证据账本和命中数照常保留。确需压缩预测或归纳重复反馈时，模型才处理这些候选；重复查询具体对象不能自动扩大成普遍习惯。
- 习惯压缩只在其自身阈值触发、相关失败被手动重试或明确的纯习惯整理时执行。未被模型明确替换的记录保留。

## 保存与恢复

有效核验和独立合并及时保存。单条候选不符合晋升、适用条件、来源或容量要求，不撤销其他有效结果；必要时只纠正剩余条目一次。整个 JSON 无效、请求失败或被取消时，已提交批次仍保留，下一次从尚未处理的配对继续。

过期时间由程序继承，整理后的记录不能晚于其来源的最早到期时间。模型不计算到期时间，也不把数据库时间戳拼进偏好正文。核验节省的空间可以供同一任务的习惯提炼使用，但整个任务不能扩大有效记忆总量。

未变化的确定性失败暂停自动重试。手动重试或记录、配置变更可以重新执行。界面区分等待响应、思考、生成、重试、校验及批次，并分别显示思考字符和结果字符。

引用校验能够检查来源归属和原文一致性，不能数学证明语义判断正确。习惯泛化和否定判断仍需要质量抽查；“请求成功”与“记忆质量正确”分别验收。

## 真实数据回放

`scripts/replay-memory-summary.mjs` 只读源数据库，创建独立目录及数据库副本，复用真实 Runtime 和所选服务商配置。回放保留失败时的相对时间关系，避免过期记录变化污染对比。凭据不写入报告。私人原文、模型结果和完整回放记录只保存在指定的本地目录，不能提交到仓库。

```powershell
node scripts/replay-memory-summary.mjs --live `
  --source C:\path\snapshot.sqlite `
  --models C:\path\models.json `
  --model exact-model-id-or-name `
  --at 2026-10-16T09:04:36.666Z `
  --output C:\path\new-replay-directory `
  --baseline C:\path\failed-runtime-events.jsonl
```

`--live` 会调用已配置的模型并产生用量。输出目录必须不存在；程序拒绝覆盖源数据库或旧回放。

源文件须是对应失败状态的数据库快照。`--at` 用于保留相对时间关系，不会把之后修改过的记录自动还原成任意历史版本。

回放验收分别记录墙钟耗时、每次请求输入/输出用量与模型设置、成功及拒绝的批次、已有习惯保留情况、原始材料可追溯性，以及新判定和新习惯的语义抽查。不使用关闭或降低思考的试验作为架构提速证据。

### 2026-10-16 失败数据回放

固定使用 `deepseek-v4-1-flash-260910`、`reasoningEffort=max`、`maxOutputTokens=128000`、530,000 上下文额度。正式数据库不修改，全部验证在副本进行。

| 指标 | 原失败记录 | 最终实现回放 |
| --- | ---: | ---: |
| 完整耗时 | 356.0 秒 | 201.7 秒 |
| 模型总输入 | 47,189 tokens | 8,109 tokens |
| 模型总输出，含思考 | 43,641 tokens | 47,389 tokens |
| 完成情况 | `unsupported_promotion`，未保存本阶段 | 2/2 请求完成，全部材料处理完成 |
| 已有习惯 | 65 条 | 65 条原文与条件完全保留 |
| 预测 | 33 条 | 33 条保留，更新核验计数 |
| 原验证材料 | 153 条 | 153 条原文可追溯，活动队列剩余 0 条 |
| 新增习惯 | 失败，未写入 | 0 条；无需强行归纳 |

本次墙钟时间缩短约 43%，输入减少约 83%；总输出反而增加约 9%。因此不能宣称减少了所有模型计算，提速包含两个有界请求重叠执行的贡献。服务商速度和缓存命中也会波动；这是一次完整最终版本回放，不能推导长期成功率。

186 个待核验配对均有账本记录：9 次命中、3 次否定、174 次未知。计数是模型判断，不等于人工准确率；短确认、对象范围变化等语义仍应抽查。本次没有将这些计数直接扩展为新习惯，原记录和来源均保留。

对完成后的同一副本再次手动整理，19 毫秒返回，模型调用为 0。这验证的是“不重复处理已经完成且低于阈值的数据”的程序路径，不是模型响应速度。此前关闭思考得到的 32.6 秒结果不计入有效性能对比。

质量核验覆盖原习惯逐字及条件比对、153 条材料原文保留、未处理配对清零、未新增习惯、失败批次恢复、重复计数防护、来源版本与过期时间保护。模型语义判断的不确定性不应由宿主冒充成事实。
