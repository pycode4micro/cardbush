# 可选本地语音

CardBush 推荐 SenseVoice Small 作为中英文离线识别选项，但不预装模型，也不在启动、打开设置或开始录音时自动下载。新安装仍使用原有 Windows 系统听写；既有识别设置保留。安装和选用是两个独立操作。

## 使用

1. 打开「设置 → 语音」，在 SenseVoice Small 卡片点击「下载并安装」。Windows x64 下载约 187 MB，安装后约 260 MB。
2. 可以查看上游来源和模型许可证，下载中可以取消；校验失败不会接受文件。
3. 安装完成后点击「选用此模型」，再点击「保存」。识别语言可选自动、中文、英文；中英混说建议自动。文字整理默认「保留原词」，避免 ITN 数字/标点整理误改夹杂的英文；仍可显式选择自动整理。
4. 「麦克风」可指定笔记本、耳机等设备；未指定时使用系统默认输入。指定设备断开时显示错误，不暗中切换到其他设备。
5. 识别与朗读独立：可使用 SenseVoice 识别、Windows 本地男声/女声朗读，无需 API Key。普通录音仍发送文字，只有语音通话自动朗读 Agent 回复。
6. 要卸载模型，先选用并保存其他识别方式。卸载不影响聊天记录或 Windows 语音组件。

没有模型或本地识别失败时会提示处理，不会自动安装、使用云端或上传录音。模型安装不修改当前识别设置。

下载使用「设置 → 网络 → 插件代理」，默认跟随模型代理，也支持系统代理或单独配置。下载从 GitHub Release 跳转到官方资源域名时逐次检查来源；禁止改用关闭 TLS、跳过校验或未经核验镜像的方式处理失败。云端语音请求使用模型网络会话，和模型下载的代理配置分开。

## 来源与版本

- 原始模型：[SenseVoice / FunAudioLLM](https://github.com/QwenAudio/SenseVoice)。
- ONNX 模型转换：[sherpa-onnx 官方 SenseVoice 文档](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)。采用 `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17`。
- 运行库：[sherpa-onnx v1.13.8 官方发布](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v1.13.8)，CPU 推理，无需 Python、CUDA 或另外安装服务。
- 模型许可证：[FunASR MODEL_LICENSE](https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE)。模型不等同于代码的 MIT 许可；安装目录同时保留模型许可、sherpa-onnx 的 Apache 2.0 许可、ONNX Runtime 的 MIT 许可及来源信息。

未采用日期较新的 2025-09-09 转换包：其上游说明指向粤语微调模型，开发机真人普通话/英文样本测试也出现了语言误判。不能仅根据发布日期替换模型。

## 安装与运行边界

- 安装入口仅允许应用主窗口调用。所有归档来自固定 HTTPS GitHub Release 地址；重定向也限制在 GitHub 官方资源域名。
- `electron/voiceModelManifest.ts` 固定版本、归档字节数及 SHA-256；解包后的模型、词表、可执行文件与动态库分别再次校验固定字节数及 SHA-256。
- 只提取固定条目到应用管理的目录，不运行安装脚本、不用包管理器、不请求管理员权限。使用临时安装目录，成功后再切换到完整版本；失败/取消清理本次暂存文件。
- 模型放在 Electron `userData/voice-models/`，不写入源码、安装包或系统程序目录。不打包本次开发机下载的模型。
- 首次推理和文件属性变化后重新校验文件内容；损坏时拒绝执行。识别/合成期间阻止卸载。
- 录音在桌面端转换为单声道 PCM WAV；SenseVoice 子进程需要临时 WAV 文件，正常完成、失败及取消时删除，不写转写日志。强制终止应用/操作系统仍可能留下临时文件，不应将其描述为“音频仅在内存中”。
- 单段录音上限约两分钟，长音频在低能量位置切分至每段不超过 25 秒，保持顺序。CPU 推理串行，有时间限制和取消处理。
- Windows x64 已实测；Linux x64 有官方运行库适配，但本次没有 Linux 实机回归。Windows 本地语音合成不适用于 Linux。

## 开发机实测（2026-10-03）

设备：Windows，i5-13500HX，约 16 GB 内存。使用上游公开真人录音，未录制用户麦克风。

| 样本 | SenseVoice 输出/表现 | Windows 传统听写 | 一次端到端耗时 |
| --- | --- | --- | --- |
| 中文，约 5.6 秒 | “开饭时间早上九点至下午五点”；仍将“开放”错认成“开饭” | “早上去我家是小五角” | 1.8 秒 |
| 英文，约 7.2 秒 | 完整句子可识别，但句末 gold 识别为 code | 本机未安装英文识别组件，无法比较 | 1.4 秒 |
| 中英混说，约 14.7 秒 | 保留 machine learning、deep learning、data analytics、data science、again；不自动加标点 | 大量英文变成中文错词 | 1.7 秒 |

这些是少量公开样本的结果，不是准确率基准，也不能保证用户口音、背景噪声或专业名词的效果。耗时包含本地进程启动/模型加载；每段加载模型，不承诺流式语音模型级延迟。自动断句、现有 Agent 文本流和逐句朗读保持原来的架构。

中文、英文来自官方转换包 `test_wavs/zh.wav`、`en.wav`；混说录音来自 SenseVoice README 链接的 [公开样本](https://isv-data.oss-cn-hangzhou.aliyuncs.com/ics/MaaS/ASR/test_audio/asr_example_cn_en.wav)。

## 验证

- `npm run test:voice`：语音状态、凭据保护、男声/女声、本地识别、安装失败/取消、内容篡改、长音频分段、真实 Electron UI。常规测试不下载模型。
- `npm run test:voice-model-native`：已有模型与公开样本的真实推理、Windows 对照、取消及音频清理；缺少模型或样本时跳过。报告写入忽略的 `tmp/voice-sensevoice-benchmark.json`。
- `node scripts/test-voice-model-native.mjs --install-dev`：**显式开发机安装**，先编译 Electron 源码；只在用户授权开发机安装时运行。不修改识别设置。
- `node scripts/test-voice-ui.cjs --local-model`：显式扩展 UI 测试，使用 `tmp/sensevoice-upstream/` 中已从官方取得的归档，经真实下载/解包校验路径安装到隔离测试目录，验证不自动选用、保存、本地 IPC 推理和卸载。不会操作用户已安装的模型。

上游模型/运行库升级时必须重新核对来源、归档摘要、内部文件摘要、模型许可及语言质量，不使用未经校验的动态 latest 下载。

## 混说、排队与通话交互修复（2026-10-03）

同一份 14.7 秒公开混说录音，在相同自动语言和模型下，`--sense-voice-use-itn=1` 将 `data science` 输出成 `da scienceence`，将 `again` 输出成 `aga`；设为 `0` 后这些原词能保留。默认改为保留原词，不做基于模型想象的错词替换。断句静音窗口由 850 ms 调整到 1250 ms，避免中英切换的短暂停顿过早切段；录音码率提高到 128 kbps。

现场文本事件显示，市场查询任务运行约 130 秒后紧跟着多条“嗯”“I.”。代码把消息发送的 Promise 当作接收回执，但它实际等待整个 Agent turn 结束，从而堵住转写队列。现在使用真正的接收回执（onStart/队列或引导接收），不等待工具执行或最终回答；发送失败仍保留转写供重试。最多三段转写排队，达到容量时暂停采集并提示，处理后恢复，不让积压无限增长。模糊填充词/单个英文字母先显示待确认，编辑发送或忽略；不会把“好”“停”等有效短命令一律过滤。未保存用户原始音频，不能据此复现用户每个错词。

语音通话显示 Agent 执行/等待用户状态，并播报公开的工具说明 `displayTitles/displayTitle`（源于工具 `_display_title`），不读取工具原始参数、结果或隐藏推理。播报按执行 ID 去重、至少间隔六秒，回答正文优先；打断后不重播已跳过的内容。循环折叠历史也纳入正文流式朗读。窗口标题支持拖动及方向键移动，缩小窗口后保持在可见范围；可收起为可移动悬浮按钮。收起与结束通话均不会结束 Agent 任务，结束通话会停止麦克风和播报。

## 可选本地自然音色

在「设置 → 语音 → Agent 的声音」增加 **Kokoro v1.1 INT8** 安装卡片和朗读方式。Windows x64 下载约 172 MB，安装后约 236 MB；不预装、不自动下载、不自动选用。安装后点选用并保存，也可保存并试听，再自行决定是否使用。现有 Windows 声音保留作为响应较快的选项。

- [原始模型与许可证](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)：hexgrad，Apache 2.0。
- [官方转换包和使用说明](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)：sherpa-onnx 的 `kokoro-int8-multi-lang-v1_1`；运行库固定 v1.13.8。
- [音色映射与试听](https://k2-fsa.github.io/sherpa/onnx/tts/all/Chinese-English/kokoro-multi-lang-v1_1.html)：女声使用 sid 3（zf_001），男声 sid 58（zm_009）。提供男女声与语速；**没有情绪提示词、声线克隆或任意情绪控制能力**。
- 运行所用 eSpeak NG 的[源代码与 GPL 许可证](https://github.com/espeak-ng/espeak-ng)在设置中可查看，安装目录保留相应通知及原始模型许可。
- 共用模型安装器，通过固定归档和所有文件 SHA-256 校验；大量词典文件使用一次解压到 stdout，按固定清单写入指定路径，归档不能创建任意路径或链接。
- 神经朗读与 ASR 的模型、运行队列、选择与卸载彼此独立；不调用云端，不使用保存的 API Key。正常完成/失败/取消均清理本次合成 WAV。
- 这是逐句合成，仍不是原生实时语音模型。CPU 合成有等待，不宣传即时通话级延迟。该机短句“你好，我先核对一下最新行情。”：女声首轮约 8.4 秒（含安装后文件校验），男声约 5.0 秒，音频约 3.0/3.2 秒。使用已有本地 ASR 回读确认输出文字；没有代替真人听音评价。
- 本次仅在隔离测试目录安装和测试 Kokoro，未更改用户实际朗读设置。ASR 已安装模型保持原位。

额外验证：`node scripts/test-voice-kokoro-native.mjs` 使用已下载并核验的 `tmp/kokoro-upstream/` 缓存，运行安装、男女声 PCM、取消和音频清理，无缓存则跳过、不联网下载。`node scripts/test-voice-ui.cjs --local-model --speech-model` 验证两套模型的隔离安装、显式选用、真实 Electron IPC 和卸载保护。常规 `npm run test:voice` 不安装模型；新增接收回执、短语确认、ASR 背压、公开工具播报、拖动/收起和窗口缩放回归。

## 下载、杂音打断与默认胶囊修复（2026-10-03）

开发机系统代理能访问官方模型。原下载器通过 Electron `net.fetch` 请求手动重定向时，在 GitHub 302 响应处报 `Redirect was cancelled`，同时没有使用应用的代理配置。现在注入现有 `PluginNetwork.fetch`，既可逐跳校验来源，又能复用系统/PAC/手动代理及绕过列表。实测走系统代理从官方完整下载约 172 MB，380 个文件校验和安装后 acquire 校验通过；验证发生在隔离测试目录，不修改用户选择。网络错误只给出处理入口或 HTTP 状态，不回显代理凭据、上游响应正文或签名下载地址。

录音与通话默认显示同一种可拖动胶囊。录音保留时长、发送和取消；通话保留静音、状态和结束，播报期间可直接停止声音。点击状态展开详情、识别确认及设置；普通展开不遮挡或锁住会话输入。录音发送后立即释放麦克风，胶囊显示转写进度；完成后消失，失败时可重试或展开查看原因。

音量变化不再直接打断播报。采集端加入持续时长、语音频段与自适应噪声门限，减少短促碰撞、低频嗡声、纯音及宽带噪声进入识别。只有有效转写或用户明确确认才停止播报；空结果、模糊短词、失败及与最近播报高度相似的疑似回声都保留当前播报。疑似回声送到人工确认而非悄悄删除，避免用户主动重复时丢失内容。中文、英文、中英混合公开语音均通过真实浏览器音频分析器的门限回归。

这不是声纹识别，不能保证区分用户与旁人的完整讲话。自动插话要等待一句话的断句和识别，响应会比纯音量触发慢；需要立即停止时可用胶囊的停止按钮。没有引入云端判断，也没有把下一步预测接入语音。
