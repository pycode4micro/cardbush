# 可选本地语音

CardBush 推荐 SenseVoice Small 作为中英文离线识别选项，但不预装模型，也不在启动、打开设置或开始录音时自动下载。新安装仍使用原有 Windows 系统听写；既有识别设置保留。安装和选用是两个独立操作。

## 使用

1. 打开「设置 → 语音」，在 SenseVoice Small 卡片点击「下载并安装」。Windows x64 下载约 187 MB，安装后约 260 MB。
2. 可以查看上游来源和模型许可证，下载中可以取消；校验失败不会接受文件。
3. 安装完成后点击「选用此模型」，再点击「保存」。识别语言可选自动、中文、英文；中英混说建议自动。文字整理默认「保留原词」，避免 ITN 数字/标点整理误改夹杂的英文；仍可显式选择自动整理。
4. 「麦克风」可指定笔记本、耳机等设备；未指定时使用系统默认输入。指定设备断开时显示错误，不暗中切换到其他设备。
5. 识别与朗读独立：可使用 SenseVoice 识别、Windows 本地男声/女声朗读，无需 API Key。普通录音仍发送文字，只有语音通话自动朗读 Agent 回复。
6. 要卸载模型，先选用并保存其他识别方式。卸载不影响聊天记录或 Windows 语音组件。

没有模型或本地识别失败时会提示处理，不会自动安装、使用云端或上传录音。模型安装不修改当前识别设置。

下载使用「设置 → 网络 → 插件代理」，默认跟随模型代理，也支持系统代理或单独配置。下载从 GitHub Release 跳转到官方资源域名时逐次检查来源；禁止改用关闭 TLS、跳过校验或未经核验镜像的方式处理失败。云端语音请求使用模型网络会话，和模型下载的代理配置分开。

## 来源与版本

- 原始模型：[SenseVoice / FunAudioLLM](https://github.com/QwenAudio/SenseVoice)。
- ONNX 模型转换：[sherpa-onnx 官方 SenseVoice 文档](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)。采用 `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17`。
- 运行库：[sherpa-onnx v1.13.8 官方发布](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v1.13.8)，CPU 推理，无需 Python、CUDA 或另外安装服务。
- 模型许可证：[FunASR MODEL_LICENSE](https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE)。模型不等同于代码的 MIT 许可；安装目录同时保留模型许可、sherpa-onnx 的 Apache 2.0 许可、ONNX Runtime 的 MIT 许可及来源信息。

未采用日期较新的 2025-09-09 转换包：其上游说明指向粤语微调模型，开发机真人普通话/英文样本测试也出现了语言误判。不能仅根据发布日期替换模型。

## 安装与运行边界

- 安装入口仅允许应用主窗口调用。所有归档来自固定 HTTPS GitHub Release 地址；重定向也限制在 GitHub 官方资源域名。
- `electron/voiceModelManifest.ts` 固定版本、归档字节数及 SHA-256；解包后的模型、词表、可执行文件与动态库分别再次校验固定字节数及 SHA-256。
- 只提取固定条目到应用管理的目录，不运行安装脚本、不用包管理器、不请求管理员权限。使用临时安装目录，成功后再切换到完整版本；失败/取消清理本次暂存文件。
- 模型放在 Electron `userData/voice-models/`，不写入源码、安装包或系统程序目录。不打包本次开发机下载的模型。
- 首次推理和文件属性变化后重新校验文件内容；损坏时拒绝执行。识别/合成期间阻止卸载。
- 录音在桌面端转换为单声道 PCM WAV；SenseVoice 子进程需要临时 WAV 文件，正常完成、失败及取消时删除，不写转写日志。强制终止应用/操作系统仍可能留下临时文件，不应将其描述为“音频仅在内存中”。
- 单段录音上限约两分钟，长音频在低能量位置切分至每段不超过 25 秒，保持顺序。CPU 推理串行，有时间限制和取消处理。
- Windows x64 已实测；Linux x64 有官方运行库适配，但本次没有 Linux 实机回归。Windows 本地语音合成不适用于 Linux。

## 开发机实测（2026-10-03）

设备：Windows，i5-13500HX，约 16 GB 内存。使用上游公开真人录音，未录制用户麦克风。

| 样本 | SenseVoice 输出/表现 | Windows 传统听写 | 一次端到端耗时 |
| --- | --- | --- | --- |
| 中文，约 5.6 秒 | “开饭时间早上九点至下午五点”；仍将“开放”错认成“开饭” | “早上去我家是小五角” | 1.8 秒 |
| 英文，约 7.2 秒 | 完整句子可识别，但句末 gold 识别为 code | 本机未安装英文识别组件，无法比较 | 1.4 秒 |
| 中英混说，约 14.7 秒 | 保留 machine learning、deep learning、data analytics、data science、again；不自动加标点 | 大量英文变成中文错词 | 1.7 秒 |

这些是少量公开样本的结果，不是准确率基准，也不能保证用户口音、背景噪声或专业名词的效果。耗时包含本地进程启动/模型加载；每段加载模型，不承诺流式语音模型级延迟。自动断句、现有 Agent 文本流和逐句朗读保持原来的架构。

中文、英文来自官方转换包 `test_wavs/zh.wav`、`en.wav`；混说录音来自 SenseVoice README 链接的 [公开样本](https://isv-data.oss-cn-hangzhou.aliyuncs.com/ics/MaaS/ASR/test_audio/asr_example_cn_en.wav)。

## 混说、排队与通话交互修复（2026-10-03）

同一份 14.7 秒公开混说录音，在相同自动语言和模型下，`--sense-voice-use-itn=1` 将 `data science` 输出成 `da scienceence`，将 `again` 输出成 `aga`；设为 `0` 后这些原词能保留。默认改为保留原词，不做基于模型想象的错词替换。断句静音窗口由 850 ms 调整到 1250 ms，避免中英切换的短暂停顿过早切段；录音码率提高到 128 kbps。

现场文本事件显示，市场查询任务运行约 130 秒后紧跟着多条“嗯”“I.”。代码把消息发送的 Promise 当作接收回执，但它实际等待整个 Agent turn 结束，从而堵住转写队列。现在使用真正的接收回执（onStart/队列或引导接收），不等待工具执行或最终回答；发送失败仍保留转写供重试。最多三段转写排队，达到容量时暂停采集并提示，处理后恢复，不让积压无限增长。模糊填充词/单个英文字母先显示待确认，编辑发送或忽略；不会把“好”“停”等有效短命令一律过滤。未保存用户原始音频，不能据此复现用户每个错词。

语音通话显示 Agent 执行/等待用户状态，工具说明 `displayTitles/displayTitle`（源于工具 `_display_title`）只用于显示，不参与语音播报。只朗读可见的 Assistant 正文，不读取工具原始参数、结果或隐藏推理；打断后不重播已跳过的内容。循环折叠历史也纳入正文流式朗读。窗口标题支持拖动及方向键移动，缩小窗口后保持在可见范围；可收起为可移动悬浮按钮。收起与结束通话均不会结束 Agent 任务，结束通话会停止麦克风和播报。

## 可选本地自然音色

在「设置 → 语音 → Agent 的声音」增加 **Kokoro v1.1 INT8** 安装卡片和朗读方式。Windows x64 下载约 172 MB，安装后约 236 MB；不预装、不自动下载、不自动选用。安装后点选用并保存，也可保存并试听，再自行决定是否使用。现有 Windows 声音保留作为响应较快的选项。

- [原始模型与许可证](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)：hexgrad，Apache 2.0。
- [官方转换包和使用说明](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)：sherpa-onnx 的 `kokoro-int8-multi-lang-v1_1`；运行库固定 v1.13.8。
- [音色映射与试听](https://k2-fsa.github.io/sherpa/onnx/tts/all/Chinese-English/kokoro-multi-lang-v1_1.html)：默认女声 sid 3（zf_001）、男声 sid 58（zm_009），可分别选择已安装模型中的 55 种中文女声与 45 种中文男声，不重复下载。默认「连贯自然」仅合并已经到达的相邻短句，减少割裂感；可选择逐句朗读。两种节奏均严格使用设置中的语速，默认 1× 正常，不再额外乘以 0.94。男女声均支持保存并试听，试听文本包含陈述、问句和鼓励，便于比较自然起伏。**没有情绪提示词、声线克隆或任意情绪控制能力**，节奏优化不能保证特定职业、年龄或情绪的听感。
- 运行所用 eSpeak NG 的[源代码与 GPL 许可证](https://github.com/espeak-ng/espeak-ng)在设置中可查看，安装目录保留相应通知及原始模型许可。
- 共用模型安装器，通过固定归档和所有文件 SHA-256 校验；大量词典文件使用一次解压到 stdout，按固定清单写入指定路径，归档不能创建任意路径或链接。
- 神经朗读与 ASR 的模型、运行队列、选择与卸载彼此独立；不调用云端，不使用保存的 API Key。正常完成/失败/取消均清理本次合成 WAV。
- 这是逐句合成，仍不是原生实时语音模型。CPU 合成有等待，不宣传即时通话级延迟。该机短句“你好，我先核对一下最新行情。”：女声首轮约 8.4 秒（含安装后文件校验），男声约 5.0 秒，音频约 3.0/3.2 秒。使用已有本地 ASR 回读确认输出文字；没有代替真人听音评价。
- 本次仅在隔离测试目录安装和测试 Kokoro，未更改用户实际朗读设置。ASR 已安装模型保持原位。

额外验证：`node scripts/test-voice-kokoro-native.mjs` 使用已下载并核验的 `tmp/kokoro-upstream/` 缓存，运行安装、男女声 PCM、取消和音频清理，无缓存则跳过、不联网下载。`node scripts/test-voice-ui.cjs --local-model --speech-model` 验证两套模型的隔离安装、显式选用、真实 Electron IPC 和卸载保护。常规 `npm run test:voice` 不安装模型；覆盖接收回执、短语确认、ASR 背压、工具进度只显示不朗读、拖动/收起和窗口缩放回归。

## 主要播报模型：Qwen3-TTS

在「设置 → 语音 → Agent 的声音」选择首项 **Qwen3-TTS（推荐，需本地模型）**，选择官方 CustomVoice 模型目录和已经安装依赖的 Python，再保存并试听。Qwen 替代 Kokoro 成为主要推荐播报模型，复用本地目录适配器；无须语音云服务或 API Key。Kokoro 降为旧版兼容选项，只在选用它时显示安装卡片，不删除用户已有模型或配置。

默认女声为 Serena，男声为 Uncle Fu；1.7B 提供可编辑的成熟、温和、可靠的语气描述。使用模型自然语速 1×，不加速播放；音色情感仍取决于模型，提示词不保证某种听感。切换 Qwen 不改变 ASR、声纹或云端凭据，缺少目录、环境或推理失败时明确报错，不暗中回退到 Kokoro 或云端。

模型与 Python 环境仍由用户选择安装，不随 MSIX 预装。未配置的全新安装继续使用 Windows 系统语音；已有用户不会被自动切换到尚未安装的模型。商店安装与开发版可能使用不同的数据目录，需要在相应版本中选择本地目录。

## 自定义本地朗读模型

在「设置 → 语音 → Agent 的声音」选择「自定义本地模型」，再选择已有模型目录。读取完成后会显示模型类型和目录提供的音色，可以分别指定女声、男声，最后点击「保存并试听」。切换朗读模型不改变语音识别方式；普通文字对话仍不会自动播报。

当前支持两种格式，不能加载任意架构的权重：

| 格式 | 目录要求 | 运行环境 |
| --- | --- | --- |
| Qwen3-TTS 12Hz CustomVoice 0.6B / 1.7B | 完整的官方模型目录，包含配置、分词器、`speech_tokenizer/` 和 safetensors 权重（支持分片） | 单独选择已安装 `qwen-tts`、PyTorch 的 Python 解释器；可提示附近已有的 `.venv`，不自动创建环境 |
| Kokoro sherpa-onnx 中英文 | `model.int8.onnx` 或 `model.onnx`、`voices.bin`、`tokens.txt`、中英词典、中文 FST、`espeak-ng-data/` | 先显式安装现有 Kokoro 可选组件，复用其中校验过的运行程序；目前仅 Windows x64 |

Qwen 的音色列表从模型配置读取；官方 CustomVoice 的九个预设可以按偏好分配到男声／女声按钮。1.7B 可填写语气描述，0.6B 不提供此选项。计算设备可选自动、CPU 或 NVIDIA CUDA；自动优先使用所选 Python 环境可用的 CUDA。Qwen 按模型自然语速输出，不应用其他引擎的语速设置。Base、VoiceDesign、GGUF 和只含一个权重文件的目录不属于此入口支持的格式。

目录检测只检查格式和必需文件，不执行模型代码，也不代表已验证运行依赖、权重来源或推理效果。保存并试听时才启动本地合成；缺少 Python 包、CUDA、模型文件或内存时显示相应错误，不回退到云端。建议使用 [Qwen 官方安装说明](https://github.com/QwenLM/Qwen3-TTS) 和 [官方 CustomVoice 模型](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice)，在独立环境中安装依赖；Kokoro 使用 [sherpa-onnx 官方模型格式](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)。遵守所选模型和依赖的许可。

导入只保存本机目录和朗读设置，不复制、删除或上传模型文件，不随云 Agent 同步，不自动下载模型或安装依赖。Qwen 辅助进程使用离线模式、safetensors 和禁用自定义 Python 类的加载方式。停止试听、结束通话或关闭界面会取消请求；Windows 会同时结束该请求创建的 Python 子进程。模型在原处被移动或删除后，仍能打开设置重新选择。

本次仅增加自定义加载，没有调整合成或播放速度，也没有引入常驻模型、预加载或流式语音模型。Qwen 每次请求会加载模型并合成完整片段后播放，因此不应视作低延迟实时语音。

Qwen 的依赖导入和模型冷启动可能接近一分钟。本地 Qwen 合成允许最多 180 秒，外层自定义模型请求额外预留 10 秒用于清理；录音识别和其他普通引擎仍使用原有时限。等待时可随时停止，不会强制等满超时时间，也不会自动转用云端。这是避免冷启动被误判失败的时间边界，不是速度优化。

验证：常规 `npm run test:voice` 包含目录校验、设置持久化、独立路由、取消、音色列表和窄窗口渲染测试，不下载模型。`npm run test:voice-custom-native` 使用开发机已有的 Qwen 模型与 Python 验证真实 PCM 和取消；其他目录可通过 `CARDBUSH_CUSTOM_TTS_MODEL`、`CARDBUSH_CUSTOM_TTS_PYTHON` 指定。模型不存在时明确跳过，测试使用隔离配置，不改变用户朗读选择。

## 外放误触发与语音引导

通话的录音分段与消息发送独立：短暂停顿约 1.25 秒时可以先转写，45 秒到达单段长度上限也只切音频。已经识别的片段留在当前话轮，继续说话会顺序合并；转写期间再次开口、存在未处理录音或尚未交付的录音时，都不会抢先提交上一段。等待时间从最近的语音活动计算，慢转写不会额外再等待完整的静音时长。

「设置 → 语音 → 通话停顿等待」提供正常 3 秒、耐心 6 秒；Agent 正在执行时至少等待 5 秒，完成后合并成一次即时引导，再由原有引导机制打断模型请求。停顿本身、音量变化和正在转写的片段不打断播报或触发 Agent。已验证声纹的完整独立指令，如「先停一下」，可在识别后跳过额外等待；含有同样词语的长句不会被当成快速指令，未验证的声音仍需确认。

胶囊收集输入时显示「还在听，可以继续」，展开后可见尚未发送的合并文字。点击「说完了」会结束当前录音并暂时停止收音，显示「正在整理，准备发送」，等待本轮录音全部识别完成后立即提交或进入确认。静音、打开设置、麦克风断开时不会后台自动发送草稿；结束通话或切换会话丢弃待发草稿。此机制不使用额外模型，也没有把下一步预测接入语音。

验证覆盖思考停顿、识别延迟、连续说话、45 秒切片、3/5/6 秒等待、手动完成、整轮确认、重试合并、退出后的迟到结果，以及真实 Electron 录音与设置持久化。时间阈值是交互默认值，不能保证推断出所有语义上的停顿；需要更长时间思考时可选耐心模式或先静音。

安装声纹模型不等于已经录入或开启声纹锁定。通话胶囊显示锁定状态，可直接进入语音设置；必须录好当前人员并开启锁定后才有身份过滤。

- 未启用锁定时，整轮转写合并后进入待确认，不发送、不打断播报。只要本轮有一个片段未通过身份验证，就需要确认整条消息。确认期间暂停收音，避免背景视频覆盖正在编辑的文字。确认后才作为即时引导提交，也可忽略；普通录音发送保留主动提交方式。
- 自动发送依据主进程返回的本段 `speakerVerified`，不能仅凭前端缓存的开关。未匹配/不确定的声纹不产生待确认文字；校验后切换档案会废弃迟到结果。锁定被关闭或旧主进程未返回验证信息时回到确认模式。
- 在通话中点击「说完了，立即识别」可主动结束当前语句，无需等待静音窗口；仍经过声纹/转写/确认流程，不能凭检测到声音就中断任务。
- 即时引导只取消当前模型请求并在同一任务中续接，不取消正在执行的工具。引导接收日志记录模式和是否已中断模型，不记录录音或引导正文。

## 下载、杂音打断与默认胶囊修复（2026-10-03）

开发机系统代理能访问官方模型。原下载器通过 Electron `net.fetch` 请求手动重定向时，在 GitHub 302 响应处报 `Redirect was cancelled`，同时没有使用应用的代理配置。现在注入现有 `PluginNetwork.fetch`，既可逐跳校验来源，又能复用系统/PAC/手动代理及绕过列表。实测走系统代理从官方完整下载约 172 MB，380 个文件校验和安装后 acquire 校验通过；验证发生在隔离测试目录，不修改用户选择。网络错误只给出处理入口或 HTTP 状态，不回显代理凭据、上游响应正文或签名下载地址。

录音与通话默认显示同一种可拖动胶囊。录音保留时长、发送和取消；通话保留静音、状态和结束，播报期间可直接停止声音。点击状态展开详情、识别确认及设置；普通展开不遮挡或锁住会话输入。录音发送后立即释放麦克风，胶囊显示转写进度；完成后消失，失败时可重试或展开查看原因。

音量变化不再直接打断播报。采集端加入持续时长、语音频段与自适应噪声门限，减少短促碰撞、低频嗡声、纯音及宽带噪声进入识别。只有有效转写或用户明确确认才停止播报；空结果、模糊短词、失败及与最近播报高度相似的疑似回声都保留当前播报。疑似回声送到人工确认而非悄悄删除，避免用户主动重复时丢失内容。中文、英文、中英混合公开语音均通过真实浏览器音频分析器的门限回归。

上述噪声与回声过滤本身不验证说话人；需要区分用户与旁人的讲话，可另外开启下面的声纹锁定。自动插话要等待一句话的断句和识别，响应会比纯音量触发慢；需要立即停止时可用胶囊的停止按钮。没有引入云端判断，也没有把下一步预测接入语音。

## 可选声纹锁定（Windows x64）

声纹锁定默认关闭，不预装模型。它复用现有模型安装、代理下载、完整性校验和本地 CPU 运行体系，另外安装 CAMPPlus 小型声纹模型；无需 Python、GPU 或云服务。模型权重约 28 MB，含运行库下载合计约 **52 MB**，安装后约 **50 MB**。ASR 和 TTS 保持用户原来的选择。

1. 在「设置 → 语音 → 声纹锁定（可选）」展开「本地模型」，下载并安装 CAMPPlus。
2. 点击「添加人员」并命名，最多保存八份独立档案。选择人员卡片只查看和管理其段落，**不会更换当前允许说话的人**。
3. 点击「准备第一段」，可以自行修改朗读文字，再点击「开始本段录音」。界面显示音量、计时和录入状态。每段建议说 8–12 秒；可以提前结束，12 秒时只自动停止当前段，**不会自动开始下一段**。录入会结束正在进行的录音或语音通话，不停止 Agent 任务。
4. 录完先试听，点击「使用这一段」后才进行质量、一致性检查并保存。再手动点击「录制下一段」。每人至少三段、最多八段；已经保存的段落可跨次继续录入，也能逐段重录、删除或补充。校验失败、取消重录不会覆盖旧段落。
5. 声纹就绪后自行开启锁定。多人录好后，只有点击「使用此人」才切换授权，**每次仅允许一人**。默认采用严格匹配；本人经常被拒绝时，优先换安静环境重录，也可改用标准匹配。声纹操作立即保存，无需再次保存其他语音设置。
6. 删除未使用的人员不会影响当前锁定；删除当前人员会关闭锁定，不会自动改用别人。锁定中的人员至少保留三段，需先关闭锁定才能删到三段以下。卸载模型前也需先关闭锁定。

原始录入音频只在确认前暂存内存用于试听，通过内存交给本地辅助进程提取；保存或取消后释放，不保留已存段落的录音回放。人员名称、朗读文字、段落时间和声纹特征一起使用 Windows 系统安全存储加密，保存于本机 `userData/voice-speaker-profile.json`；不上传、不同步云 Agent，也不会随日常通话自动学习旁人的声音。界面和 IPC 仅返回开关、当前人员、匹配模式与档案／段落元数据，不返回声纹特征。旧版单人声纹自动显示为「我的声纹」，保留原开关与匹配模式；编辑时升级存储格式。配置或解密失败时拒绝验证，仍可从设置清除后重新录入。

录音转文字和语音通话统一在主进程执行声纹验证，位于任何本地／云端转写之前。未匹配或不确定的音频不会送入转写服务、Agent、文字重试或确认队列，也不会中断播报。关闭声纹锁定时沿用原语音流程。开启后，即便选择云端识别，也只在本地匹配通过后上传该段录音。

验证使用重叠窗口逐段匹配，避免只比较一整段的平均特征；语音过短、过轻、失真或模型运行失败时不自动放行。当前至少需要约 1.5 秒有效声音，因此“停”等极短口令可能被拒绝；需要立即停止播报时可以使用胶囊按钮。此功能用于减少误触发，**不分离重叠人声，不能保证拦住所有旁人、录音重放或仿声，不作为敏感操作的身份认证**。更换麦克风、噪声、语言及嗓音变化也会影响结果。
