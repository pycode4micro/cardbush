# Source 依据备注

Source 在输入框的 `＋` 中切换，按会话保存，默认开启。发送、排队和重试保留提交时的开关状态；新会话回到开启。它只控制最终回复的说明标注，普通文件、媒体、网页、提取和消息引用不受影响。

## 提示词与缓存

- 系统提示词只说明用途和入口；工具说明承担具体格式。工具列表不会随开关变化。
- 本轮状态以内部 user 消息 `source_preference` 追加，关闭时明确禁止创建和添加 Source 标注。用户正文保持原样。
- 不改写先前的消息、工具结果或 Source 记录。压缩后恢复当前状态，避免摘要遗漏“关闭”。引导的状态随引导消息追加。
- 增加工具或更新工具说明会改变对应版本的稳定前缀；同版本内切换 Source 保持已有 cache chain。说明更新不重写旧消息、旧工具结果或旧备注。

## 记录与展示

`remember_source` 的 `explanation` 使用简短自然语言补充正文之外的原因：为什么需要修改、不改会造成什么后果、证据怎样支持判断，或为什么选择这个方案。不要复述修改清单、测试通过数或正文摘要；没有新增解释价值就不创建标注。必要条件与实现选择须区分，不能把一种方案写成唯一必须，也不能为满足格式编造原因。不要求固定标题、模板或额外结构化字段。

例如，正文可以写“修复 WebSocket 断开后客户端未移除”；Source 补充“开始关闭与完成清理共用一个标志，会提前跳过关闭通知，服务器因而无法移除客户端；独立标志让清理只执行一次”。“换成独立标志，4 项测试通过”只是结果复述，不是该备注应承担的理由。缓冲必须在发送完成前保持有效属于必要条件，采用四槽缓冲池则是需要说明取舍的实现选择。

`sources` 选择能支持原因或约束的真实位置，而不只是罗列改过的文件；也可为空，表示 Agent 自己的设计说明。一个备注可关联多个文件或 HTTP(S) 链接。返回的 `[编号](cardbush-source:编号-身份校验)` 放在相关正文旁，不能取代交付文件链接。最终正文仍应独立可读，不把重要结论或限制藏入悬浮备注，也不再复制备注充当正文摘要。

复用 ToolExecutionStore 的持久化记录及 locator 索引；与 `cardbush-memo:` 使用不同的协议和解析器，防止互相误认。引用带执行身份校验，跨主机复制时不能误指向碰巧同号的记录；首版在备注所属运行时内解析，跨主机迁移不自动转存备注。`read_source_memos` 可分页取回原始备注。

文件记录包含大小、修改时间；不超过 2 MiB 的文件另有 SHA-256，UTF-8 文件的行号定位保留有限片段。超过此大小可记录整个文件的版本元数据，不接受行号片段。URL 不会被自动抓取，Agent 说明不代表独立事实核验。读取文件沿用工作区访问策略。版本指纹和片段不重复返回给模型。

页面渲染时预载备注，同一运行时的短期查询合并。悬浮/聚焦只展示已加载数据，不触发模型或网络查询。点击支持打开文件、网页；文件改变或删除仍展示原说明与片段。卡片支持点击固定、Esc 和外部点击关闭，并跟随主题。

主卡片分为“为什么这样说”和“依据来源”，二级卡片为“引用原文”，并注明是生成说明时保存的片段。文件条目只显示文件名、现有类型图标和行/页定位；完整路径放在悬浮提示，本地文件复用现有右键菜单。悬停条目或点击“原文”后在侧边展开，空间不足时向另一侧或下方展开，两层保持可见。通过鼠标切换、方向键或 Esc 逐级收起，无返回按钮；片段导航完全复用预载内容。

首版展示行号及历史片段，点击打开当前文件。定位结构预留 page、object、region；精确跳转、PPT/图片区域交互和用户主动发起的“进一步解释”留待后续接入，不自动发送二次请求。
