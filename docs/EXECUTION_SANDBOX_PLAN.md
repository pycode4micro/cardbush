# 执行沙盒与模块解耦方案

核对日期：2026-09-23。

本文记录实现前的调研和设计，不表示下面的操作系统沙盒已经实现或启用。此次核对依据是 OpenAI 官方文档及 CardBush 当前源码，尚未逐行审计 Codex 的原生实现。

## 约束

- 不分区、不创建虚拟磁盘、不要求迁移项目，也不以复制项目代替权限隔离。命令使用现有项目路径；临时文件仍放在普通目录中。
- 桌面端和云 Agent 使用相同的策略契约，由实际执行命令的主机落实限制。
- 保留当前审批、资源预算、后台终端、子代理、SSH、插件和预览能力；分别声明其边界，不能让一个“沙盒开启”标签代替多个不同的保障。
- 开启强制隔离后，后端缺失、不支持所请求的策略或初始化失败，都必须在启动用户命令前失败；不得静默重试为普通进程。

## Codex 的可借鉴机制

官方文档将审批与沙盒分开：审批决定是否授权，沙盒限制命令及其后代进程实际能访问的资源。Windows 优先采用专用低权限用户、文件权限和防火墙；受限令牌模式是较弱的后备。Linux/WSL 使用 bubblewrap 与 seccomp，部分兼容路径使用 Landlock；macOS 使用 Seatbelt。这些机制不要求磁盘分区。见 [Sandbox](https://learn.chatgpt.com/docs/sandboxing)、[Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)、[权限执行范围](https://learn.chatgpt.com/docs/permissions#scope-and-enforcement)。

网络域名规则需要实际启用并强制经过代理；只写配置或设置代理环境变量，不能视为已经阻止直接联网。MCP、浏览器、Computer Use、连接器还有各自的权限控制，不自动继承命令沙盒。见 [Permissions](https://learn.chatgpt.com/docs/permissions)。

Codex 使用 App Server 向客户端提供会话、审批和事件接口。CardBush 可以借鉴 UI 与执行服务分离的边界，不需要迁移既有 Agent HTTP/SSH 协议。见 [Codex App Server](https://learn.chatgpt.com/docs/app-server)。

## CardBush 源码核对

| 位置 | 当前职责 | 需要解决的问题 |
| --- | --- | --- |
| `packages/bush-runtime/src/toolExecutionCoordinator.ts` | 工具准入、审批、能力绑定及执行记录 | 授权决策需要生成可信执行策略；“允许命令”不能隐式表示“取消所有隔离” |
| `packages/bush-runtime/src/runtimePermissionBroker.ts` | 审批请求、回答、取消、合并等待者 | 保留现有身份绑定；新增授权范围应和具体操作、主机及策略绑定 |
| `packages/bush-runtime/src/workspaceTools.ts` | 文件操作、路径准入、搜索、终端会话、输出缓冲 | 职责集中；终端目前检查工作目录，却未给任意脚本加上操作系统文件／网络边界 |
| `packages/bush-runtime/src/processResourceGuard.ts` | 资源准入、Windows 宿主启动、进程生命周期 | 资源限制需要与访问隔离分开建模；非 Windows 分支直接启动普通进程，不能宣称具有同等内核资源限制 |
| `native/process-guard/CardBushProcessHost.cs` | Windows Job Objects、挂起启动、进程树清理、资源监测 | 保留其在运行命令前设置资源约束的顺序；当前不负责文件访问令牌或网络隔离 |
| `packages/bush-runtime/src/workspaceToolRouting.ts` | 本地／SSH 工具路由 | 环境切换不授予额外权限，不能把本地沙盒状态套在远端命令上 |
| `electron/sshConnections.mts` | SSH 连接、SFTP、远端命令和终端 | 普通 SSH 远端执行依赖远端账户权限；客户端沙盒无法限制服务器上的 shell |
| `electron/agentRuntimeHost.mts`、`electron/agentService.mts` | 无界面 Runtime 宿主及 Agent 业务服务 | 已复用 Runtime；服务文件位于 `electron` 目录不等于其执行依赖 Electron，迁移时要按真实依赖拆分 |

现有窗口、webview、iframe 的 Chromium 隔离应保留，但它们不等于终端命令沙盒。现有工作副本用于并发修改和审查，也不替代操作系统访问隔离。

## 目标模块边界

以下模块是拟定职责，最终命名可随实现调整；先在现有包内分离职责，再依据依赖关系决定是否抽出独立包，避免只搬文件而保留循环依赖。

1. **权限策略**：接收宿主配置、可信工作区及审批结果，生成不可由工具参数自行扩权的执行策略。分开表达文件读取、写入、网络访问和有效授权范围。
2. **执行服务**：接收命令、参数、工作目录和策略；统一管理启动、stdin/stdout、取消、后台会话、退出回执。业务层不自行拼接平台沙盒启动命令。
3. **平台沙盒适配器**：Windows／Linux／macOS 各自探测能力、验证可执行策略、建立隔离，再运行命令。不能支持的策略返回明确错误。
4. **资源治理**：保留 CPU、内存、进程数、并发额度和进程树回收，作为独立约束与沙盒组合。访问权限变化不能解除资源预算。
5. **宿主与 UI**：本机和云 Agent 共享能力／状态协议。UI 展示实际生效的限制、审批和失败原因；SSH、HTTP 仅承担传输职责。

审批凭据、服务访问令牌、模型凭据和应用控制通道属于宿主控制面；不应默认继承给模型启动的任意子进程。项目主动提供给命令的环境变量需有清晰的授权来源，不能粗暴删除所有环境变量而破坏开发工具。

## 执行环境的处理

- **本机命令**：由本机适配器实施沙盒，直接使用现有工作区目录。
- **云 Agent 命令**：由云 Agent 所在服务器实施沙盒，客户端不能通过连接参数扩大服务器管理员允许的范围。
- **普通 SSH 项目**：服务器没有 CardBush 执行组件时，只能确认 SSH 账户及工具准入边界。要获得同等命令沙盒，应在远端部署执行组件并握手确认能力；不把安装组件或降级执行做成隐式副作用。
- **子代理**：继承宿主认可的授权上限；不能通过新建会话、换目录或自行指定元数据扩权。独立云 Agent 由自身服务策略管理，不视作本机 fork 的安全上下文。
- **插件／MCP**：先盘点实际进程入口与服务需要的权限。宿主启动的插件进程可以逐步接入执行层，但浏览器、桌面控制及外部服务须保留单独授权模型。

## 实施顺序及验收

### 1. 公共执行层解耦

先将工作区路径策略、终端会话、资源治理和进程启动分开，保持工具参数、终端句柄及退出语义兼容。桌面端和 Agent 服务继续调用同一套实现。通过现有文件、审批、终端、子代理和 SSH 回归后再切换隔离后端。

### 2. Windows 原生访问隔离

在现有 Job Object 宿主之外明确访问隔离职责，设计一次性的受控安装与卸载流程，覆盖低权限身份、文件授权、网络规则及 UI 隔离。系统权限和 ACL 的变更必须可追踪、幂等、可撤销，并处理并行会话、应用崩溃及升级。开发签名／Windows 应用控制兼容性单独验证，不能靠关闭智能应用控制解决。

如果提供无需管理员初始化的后备实现，必须声明实际支持的范围；需要强网络或不受支持的读写策略时直接拒绝，不使用环境变量伪装内核级隔离。

### 3. Linux 云端隔离

实现与同一策略对应的 bubblewrap／内核限制，探测用户命名空间及内核能力；在受限容器、缺少工具和不支持的系统上验证失败关闭。目录映射直接指向现有项目，不复制磁盘。服务管理命令与模型命令分开，避免扩大模型的系统权限。

### 4. 网络、敏感数据及其他执行入口

完成内核出口控制与代理组合后再提供域名规则；覆盖重定向、直接 IP、DNS、IPv6、回环及私网访问。审计模型启动的命令、插件 hooks、stdio MCP、辅助进程、文件工具与预览导出路径，确认每一类入口的边界与例外。

### 5. 默认启用及回归

达到以下实际执行验收后，再改变默认行为。不能只用 mock 或检查启动参数证明安全边界成立。

- 工作区内正常构建、读写和输出预览可用，工作区外未授权写入被阻止。
- Python／Node／PowerShell 间接启动及孙进程受到相同约束。
- 符号链接、junction、硬链接、路径大小写、受保护配置和权限变更不能绕过约束；不能安全支持的情况必须拒绝。
- 网络关闭时直接 socket 也不可用；允许目的地可达，其他目的地不可达。
- 停止、崩溃、超时和断线不会遗留不受管辖的命令进程；单次等待取消仍遵守当前后台终端语义。
- 审批后的扩权仅作用于认可的范围，下一条命令不会意外继承更高权限。
- 本机、云 Agent、普通 SSH 的实际能力分别测试并准确呈现。
- 测量冷启动与热启动延迟、长任务吞吐及内存开销，避免每条命令都递归扫描整个项目或改写全盘 ACL。
