# 插件代理

插件页右上角的“代理”打开统一设置页。上方配置插件默认代理，下方列出已安装插件和独立 MCP；可搜索并直接逐行修改，无需进入每个插件详情。手动代理地址在当前行展开，修改后保存。搜索不会丢弃未保存的行内容。

列表中的每个插件或独立 MCP 支持：

| 方式 | 行为 |
| --- | --- |
| 使用默认（当前方式） | 自动使用本页上方的全局配置；单项初始状态。全局修改后自动跟随，无需逐行保存 |
| 跟随模型代理 | 使用模型代理，即使插件默认已设为其他方式 |
| 无代理 | 直连，清除进程继承的代理变量，并设置 `NO_PROXY=*` |
| 跟随系统 | 按目标 URL 解析系统代理，包括 PAC 和绕过规则 |
| 手动代理 | 分别配置 HTTP_PROXY、HTTPS_PROXY 和 NO_PROXY；支持 HTTP、HTTPS、SOCKS4、SOCKS5 和 SOCKS5h 地址 |

插件默认初始为“跟随模型代理”。单插件/单 MCP 的选择优先于默认配置。插件详情中也保留“网络代理”入口，和列表使用同一个配置。插件所附 MCP 按所属插件设置，不在列表中重复拆分为多个项目；独立 MCP 拥有自己的条目。

“全部使用默认”一次清除已保存的单项覆盖，并清空列表中的单项草稿；全局代理和其他插件配置保留。插件与独立 MCP 仍分别使用原有配置文件，某一项保存失败时显示错误，保留实际已完成的修改，可重试。

## 持久化与生效

- 插件默认保存在现有 `product-host/config/apps.json` 的 `proxy` 中，单插件覆盖保存在 `plugins[].config.proxy`。缺少字段的旧配置自动继承默认值。
- 独立 MCP 覆盖保存在现有 `product-host/config/mcp-servers.json` 的 `servers[].proxy`，不再建立一份服务配置。移除该字段即恢复继承。
- 有效代理由宿主统一解析，进入内部 MCP 连接快照以判断哪些连接需要更新；不会进入模型可见的工具定义。凭证和本地中转端口不作为第二份持久化配置。
- 保存后通过现有异步连接调度生效。只替换有效代理发生变化的连接；活跃轮次继续遵守既有工具目录发布边界。不会为了应用代理刷新整个界面。
- 后台刷新保留已显示的列表和编辑器，不反复显示加载占位。较晚返回的旧配置不能覆盖已保存的新版本；未修改的观察结果复用现有界面状态。

## 网络覆盖范围

HTTP/SSE MCP、stdio 进程、HTTP 认证 Header Helper、直接 OAuth、插件 Hook，以及 Agent 局部 MCP 使用对应项目的代理。市场下载、Git/npm 市场获取和共享插件账号登录使用插件默认代理。共享 OpenAI 账号的登录/令牌刷新使用全局插件代理，各个已登录应用的 MCP 请求使用其自身覆盖。

宿主为代理配置创建独立 Chromium 代理解析会话；Node 网络与 stdio 的标准代理环境通过本机、随机凭证保护的 HTTP 中转使用同样的规则。HTTP 和 CONNECT 保持流式传输，取消会关闭上游连接；代理故障不会擅自退回直连。手动 HTTP 与 HTTPS 地址只用于各自协议，未填写的协议直连。

这控制的是 CardBush 的网络传输和插件进程的代理环境。插件内部自行忽略标准代理环境的代码，以及已有外部浏览器、Blender 等程序的网络，仍由它们自身配置。没有更改机器全局代理或父进程环境。

## 回归

`npm run test:plugin-proxy` 覆盖配置继承、持久化、独立 MCP、不同代理并行、绕过、原始输出、代理凭证、SOCKS、流式取消，以及隔离 Electron 中的真实 PAC、Utility Process 和 stdio。界面回归覆盖统一列表、过滤时保留草稿、逐行保存、失败重试、恢复继承和窄窗口。

测试使用本地服务器和隔离临时配置，不调用真实模型或第三方账号接口。
