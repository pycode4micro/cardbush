# 日志与缓存保留机制

本次在流式事件合并之后增加存储维护。运行记录采用无损归档，不删除已发布的流式事件或重排事件编号；旧游标、完整正文、工具事件和时间信息都能还原。

## 默认策略

| 数据 | 策略 |
| --- | --- |
| Runtime 事件日志 | 已结束、文件 7 天未修改且至少 64 KiB 时，由 `.jsonl` 无损压缩为 `.jsonl.gz`。小文件保持原格式。 |
| 内存事件缓存 | 有持久化副本、已结束、无订阅者且 10 分钟未访问的流，在维护时释放；再次访问从磁盘恢复。 |
| 诊断日志 | 仅在明确的日志目录内，删除超过 14 天未修改的 `.log` / `.jsonl` 及编号 1–3 的轮换文件。普通调试日志按每日首次写入或 8 MiB 轮换，最多当前文件及 3 份备份。 |
| 会话、工具结果、Source/Memo、检查点 | 不按时间删除；继续按现有引用关系保留。删除会话后才回收无引用数据。 |
| 归档临时文件 | 中断遗留的 UUID 临时文件保留 24 小时后，纳入已有垃圾回收。 |

Runtime 与诊断日志维护均在启动 1 分钟后运行，之后每小时检查。Runtime 忙时延后，新命令或新一轮任务到来时中止后台维护、优先处理用户操作；显式“清理缓存”也执行归档。已关闭的桌面或云端宿主停止相关定时器。

时间阈值是达到后具备清理资格，实际处理在下一次维护时发生。归档每批最多检查 16 个候选文件，累计扫描约 64 MiB 后停止该批（允许单个更大的文件）；检查位置会向前推进，避免异常或未结束日志持续挡住后续文件。

## 数据保护

- 逐条校验协议、原始记录校验和、身份、连续序号和终止状态。近期、未结束或仍打开的日志跳过，损坏日志保留并报告错误。
- 流式压缩，核对解压后的 SHA-256 与总字节数，刷盘后排他发布归档，最后重新确认原文件未变化才移除原件。无法发布归档时保留原件。
- 若中断发生在归档发布与原件删除之间，读取优先使用原件；下一轮校验两者相同后再完成清理。冲突时保留文件，不覆盖已有归档。
- 引用收集器读取归档解压后的文本，并正确处理跨块 UTF-8 与引用。读取保留数据失败时，停止整个删除阶段。
- Session 消息、模型请求、Provider replay、Cache chain、工具结果和 Source/Memo 编号不改写；用户工作文件和自定义输出目录不纳入时间清理。
- 归档依赖文件系统支持同目录硬链接。若不支持，维护报告错误且保留原始日志，不降级为有丢失风险的覆盖操作。

## 验证

86 项相关测试通过：Runtime 71 项、桌面清理 11 项、云端 Agent 4 项。完整 Runtime 构建、Electron TypeScript 检查及 `git diff --check` 通过。
