# MCP 图片回传与 Chrome 截图诊断

MCP 原生返回保存在执行记录中。模型收到的工具文本移除标准图片块、嵌入图片资源及图片 Data URI 中的二进制数据，图片走已有的模型视觉通道。

## 图片路径

1. 直接 MCP 调用和 `mcp_call` 返回中的标准 `content[].type=image`、嵌入图片资源都进入 `ModelImageStore`。仅面向用户的图片不自动附给模型。
2. 复用已有校验、压缩和持久化：图片按内容寻址，单图最多 400 万像素、最长边 4096，目标不超过 1 MB。原生返回不改写。
3. 每次返回最多处理 16 张图，源数据总预算为 64 MB；每轮最多附加 4 张不同图片，并服从剩余上下文预算和 `requestCapabilities.vision`。
4. 模型工具文本携带 `runtime_image_files`；内部 `tool_image_observation` 标明图片来源调用、序号、本地路径及 `attached`、`vision_disabled`、`attachment_budget` 或 `failed`。路径可供后续按需注入。
5. 模型提供方提交时将持久化路径转换为图片输入。Base64 不进入普通工具文本，不需要模型重写图片编码。
6. 新归档保留图片路径；读取升级前的原生 MCP 图片归档时，按需生成相同的持久化文件，并清除文本中的图片编码。会话历史保存图片路径，重启继续对话时复用。

## 截图超时

Chrome 扩展中的 `Page.captureScreenshot` 在 25 秒后返回具体的 `screenshot_timeout`，早于连接桥的默认 30 秒超时。超时不代表 Chrome 已取消命令：同一标签页中仍有截图未结束时，新调用立即返回 `screenshot_in_progress`，不继续提交截图。其他操作仍可执行。

截图完成或标签页断开调试器时清除占用。断开连接会让等待中的调用返回 `screenshot_interrupted`；旧命令稍后完成不会清除新连接中的截图占用。运行中的命令不进行隐藏重试。

工具返回记录页面选择、连接、握手、扩展接收、权限检查、调试器连接、命令执行和响应接收阶段的累计耗时。连接错误的 `details.diagnostics.stage` 是最后到达的阶段；截图结果或错误也包含 `timings`。旧版本扩展没有阶段消息时，只报告已观察到的连接阶段。

同一会话、同一页面的连续失败返回 `consecutiveFailures`、`cumulativeAttemptMs`、`failureWindowMs`，第二次起提供切换预览路径或检查连接状态的建议。成功截图、导航、关闭页面或释放连接会清除对应记录。该反馈不限制总调用次数，不改变其他会话的状态。

这些诊断随工具结果进入现有执行记录，不记录额外的网页正文、截图编码、连接令牌或命令参数。阶段只能说明等待位置，不能单独证明 Chrome 内部故障原因。

## 验证

- Runtime 图片测试：直接调用、间接调用、归档、损坏图片、视觉关闭、图片数量与压缩预算、原生结果保持不变。
- Provider 生命周期测试：小图、大图、源文件删除及重启后的图片回放。
- Chrome 扩展测试：截图重入、超时、晚到响应、断开和重连；连接桥测试验证阶段消息与超时归因。
- 2026-09-13 SVG 任务原始 PNG/JPEG 离线回放：工具文本由 55,017/8,202 字符降为 494/496 字符，图片进入 `input_image`，旧归档的图片文件验证一致。此数字是文本字符数，不是 token。
- 同一 SVG 的实时复查两次截图约 145/139 ms，未复现原来的 30 秒超时；因此不将超时根因标为已确定。

构建不会重启正在运行的应用。Runtime 更新需要重启 CardBush；扩展后台更新需要在 Chrome 中重新加载 CardBush Browser Connector，或重启 Chrome。
