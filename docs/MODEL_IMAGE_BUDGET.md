# 模型图片与请求体积预算

图片 Token 与编码字节不是固定比例。视觉 Token 受模型、像素和 detail 影响；HTTP 请求体还包括 Base64、文字、工具定义及参数。因此分别检查上下文 Token 和完整请求的 UTF-8 字节，不能把 Base64 长度伪装成真实 Token 用量。

## 新图片入口

`ModelImageStore` 在新用户附件、`inject_image_input` 和明确标记 `model_input` 的工具图片进入模型时生成不可变副本。默认最多 400 万像素、长边 4096 px、编码后 1,000,000 字节；保持比例，不裁切、不放大。小图不重复有损编码。普通图片使用 JPEG，透明图片保留 alpha 使用 WebP，并处理 EXIF 方向。

原文件和工具界面的预览地址保留。副本按实际内容的 SHA-256 入库，历史消息只引用这个地址。后续请求、重启和缓存前缀重放不重新压缩。旧图片快照也不就地重写。

`inject_image_input(original: true)` 可明确读取原始像素，仍受单张 9,000,000 字节限制。默认压缩允许读取最多 64,000,000 字节的源文件；解码限制为 6400 万像素。大动画需先提取相关帧或显式选择原图，不会静默变成首帧。远程 URL 仍由供应商获取；宿主不会主动下载。解码失败明确报错，不回退到未经限制的大图。

## 完整请求预算

Responses、Chat Completions 和 Anthropic Messages 适配器统一采用 **40,000,000 字节（40 MB）** 的默认请求体预算，由旧的 32,000,000 字节扩大而来。这是本地派发预算，不能代表各供应商的真实限制。上下文 Token 预算另行计算。

对明确知道传输上限的连接，可通过适配器构造参数 `maxRequestBodyBytes` 覆盖为其他正整数预算。按实际投影参数序列化完整 JSON，计算包含 Base64 的 UTF-8 字节；达到预算的 87.5% 时触发上下文维护。默认情况下，35,000,000 字节（35 MB）开始维护，40,000,000 字节为派发硬上限。计数接口和发送入口检查同一个预算。

Token 或体积预算触发维护后，Runtime 都使用已有的 `checkpoint_context` 事务。默认渐进模式与旧协议都支持按完整消息或工具交换分段；思考、并行调用及其所有回执保持完整。渐进模式保留全局来源编号，分段结果仅暂存，由模型合并成完整来源摘要后，全部来源一起提交。原会话、实际调用与回执、分段边界及恢复进度保留；重启后继续未完成的段。无法再分割的消息或最终合并请求明确失败，不截断原文冒充完整摘要。

`model_request_usage` 的 Token 字段仍来自供应商真实 usage；请求字节和上限单独记录为 `requestBody`。字节预算不进入模型输入指纹。

## 验证

回归覆盖双预算、三种 API 默认发送 32–40 MB 的请求且在超过 40 MB 时阻止派发、超过旧单图上限的输入、透明与旋转图片、动画、小体积大像素图片、原图读取、用户附件、工具观察、源文件删除、会话持久化与重启、低 Token 高体积时分段维护及继续执行、渐进分段的来源隔离与原子提交。

2026-09-13 对导致 413 的会话中 16 张 PNG 做本地验证：原始文件合计 37,582,379 字节，压缩后 7,157,037 字节；Base64 从 50,109,860 字节降到 9,542,732 字节，约减少 81%。这组图片均保留原分辨率。该结果仅为本地编码验证，未重新调用模型，不能据此推算供应商真实视觉 Token。
