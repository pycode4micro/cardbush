# 权限

[English](PERMISSIONS.md) · [简体中文](PERMISSIONS.zh-CN.md)

本机会话输入框提供两种审批选择。远程 worker 还需遵守其自身的宿主策略：

- **申请批准**：普通文件操作可使用授权工作区；范围外访问、非沙箱命令及准入要求审批的其他工具等待用户决定。
- **完全访问**：普通工具权限请求直接通过；硬性拒绝、宿主强制命令隔离和操作系统权限仍生效。

设计区分审批策略与执行边界，参考[公开沙箱说明](https://learn.chatgpt.com/docs/sandboxing)。这里没有额外模型自动审查，也不是每次读取都询问。沙箱配置在「设置 → 运行环境」：检测不安装依赖，用户主动点击安装后默认启用隔离；已明确关闭的设置跨检测／重启保留。详见[执行沙箱](EXECUTION_SANDBOX.md)。宿主 `auto` 在申请批准模式下隔离常规命令，完全访问运行普通进程；`required` 不受界面选择影响，始终强制边界。

设置属于执行主机，每次命令读取一次。修改不影响已运行命令或待审批项，不改 schema／历史。部署显式指定的 `off`、`required` 保持锁定。

## 命令审批

即使 cwd 在项目内，非沙箱命令也需要审批：授权目录不能约束该进程访问范围。会话授权绑定完整命令、解释器、规范 cwd 和执行主机；任一改变需要新审批，直接 SSH 相同。

非沙箱终端输入绑定完整输入、原主机和终端 ID；轮询／空输入不新增审批。真正受沙箱约束的终端可在既有边界内继续。完全访问由共享协调器跳过这些普通询问。

强制隔离允许边界内工作区命令，但超出部署硬限制直接拒绝，不提供无法生效的批准。受保护删除在普通权限绕过之前拒绝。

`auto` 下，`additional_permissions` 可申请读写目录与网络。批准绑定精确命令和规范范围，仅扩展该进程及其后代，保持 OS 隔离。范围外 cwd 显示为额外可写目录；新进程仅在同一精确调用获得会话授权时复用。等待审批时目录链接变化会令授权失效。网络授权目前为全部目标，审批明确显示。

拒绝返回工具失败，说明不能通过间接方式重试同一行动。反馈沿普通回执追加，不改系统提示或引入另一套 loop 中止阈值。

## 兼容与缓存

线协议保留 `task_free`、`all_free`。旧 UI 保存的 `user_free` 归一为 `task_free`，已有完全访问保留；旧 API 客户端和子代理配置仍接受协议值 `user_free`。历史消息和工具定义不改写。

权限在校验具体调用参数与规范范围后申请。旧 `request_permission` 预授权工具及兼容处理器已经移除；直接调用实际操作，由执行边界请求必要批准。旧工具合同不迁移或重放，见[工具交互](TOOL_INTERACTION.md)。

命令准入在共享 Runtime 实现。远端 Agent 必须更新相应版本；只升级桌面仅改变选择器／偏好，不改变旧服务器的执行策略。
