# bush-it

bush-it 是以 Markdown 文档为主体的写作、整理和展示工具。默认是一张可直接写作的空白页面：编辑标题和正文，再按需要插入内容或配置协作。文档不需要节点或执行任务；普通 `.md` 文件可以直接打开、编辑、预览和保存。

进入 bush-it 后，应用左侧栏显示页面列表、新建、搜索和回收站，可以返回对话导航。页面顶部只保留页面名与插入工具；点击页面名打开菜单，按需使用配置、Markdown 源码、图谱、Team 和文件操作。文档目录与关系概览默认收起；启用关系概览后，在文章末尾显示缩略图。图谱是同一份文档的另一种视图，不是独立的执行格式。

## 编辑与保存

- “文档”中直接编辑标题和正文。使用顶部 `+`、正文旁的 `+` 或段落开头的 `/` 插入标题、列表、任务清单、引用、代码、表格、分隔线和图片；选中文字后显示格式工具。修改同步到 Markdown，支持撤销和中文输入法组合输入。
- “Markdown”编辑完整源码。修改配置或暂时写出无效元数据时保留输入框和光标，不用旧图覆盖当前文字。
- 插入菜单中的“可引用章节”增加独立引用的内容；启用 Team 后，“Team 任务”增加明确参与执行的章节。普通内容无需配置章节；页面与章节配置只在主动展开时显示。
- 工具栏插入跟随当前编辑的正文或章节标题，菜单靠近触发按钮；连续插入图片保留已有内容。菜单支持外部点击和 Esc 收起。窄窗口目录以浮层打开，选择章节或点击正文后收起，不挤占正文列。
- 图谱支持拖动、缩放、平移、自动排列以及 Alt + 方向键移动。普通引用与 Team 等待条件独立维护；Team 视图以实线箭头表示依赖，以虚线表示普通文档引用。
- 每页自动保存在本机，切换页面和重启后继续编辑。移至回收站后可以恢复；旧版单份草稿保留为第一页。文件操作位于页面名菜单，打开文件和重新载入均新增页面，保留当前草稿。取消文件选择保留当前内容；保存检查文件版本，拒绝覆盖外部修改。
- 图片支持链接或上传 700 KB 内的 PNG、JPEG、WebP、GIF；上传后嵌入 Markdown。无法转换的原始 HTML、引用式链接等保留为可编辑源码块，避免编辑其他内容时丢失。富文本编辑可能规范化 Markdown 的空白和格式；完整源码视图仍可直接编辑原文。

文档文本上限为 2 × 1024 × 1024 个字符、128 个结构化章节。Team 最多执行其中的 64 个任务；普通说明章节不计入执行节点。文档可以有任意普通 Markdown 标题，不必把每一节都配置为节点。本地存储失败时会提示另存为 `.md` 文件，当前内存中的编辑内容继续保留。

## 一份文档中的内容与配置

可选 YAML 文件头记录文档属性。正文可以从一级标题及“为什么这样做”开始，自由组织内容，不要求固定提纲。需要独立引用、图示或 Team 配置时，在二级标题后紧跟 `md-node` 元数据块。展示使用 `name`，标题中的 ID 用来稳定引用。

````markdown
---
name: 订单核验
author: 项目组
team:
  id: order-review
  description: 核实依据后交付结论
  max_parallel: 2
---

# 订单核验

## 为什么这样协作

库存数据与订单信息来自不同来源，先分别核实，再汇总缺失项。

## rationale
```md-node
name: 思考与备忘
```

这是一段普通文档，不会被执行。任务设计见 [[#stock|库存查询]]。

## stock
```md-node
name: 库存查询
agent_id: warehouse
depends_on: []
```

根据本次输入核实库存，交付数量、来源和缺失信息。

## report
```md-node
name: 汇总回复
agent_id: reviewer
depends_on: [stock]
```

依据上游结果交付简短结论、证据和待确认事项。
````

`[[#章节ID]]` / `[[#章节ID|显示名]]` 是文档引用，不会创建执行依赖。代码块、行内代码和转义的引用不建立链接。Team 只执行具有 `agent_id` 的章节，只根据显式 `depends_on` 调度。普通章节可以互相引用或形成循环，Team 的执行依赖仍须无循环。

正文中的未闭合代码块和 `md-node` 格式示例会通过元数据中的 `markdown` 多行文本完整保存，避免吞掉后续章节。`position` 可选，只影响图谱排版。此功能组织单份 `.md` 文档，不扫描外部 Obsidian vault。

## 从文档到实践，再回到文档

在 bush-it 的页面名菜单中点击“用 Team 实践”增加执行配置。在需要执行的章节选择员工、填写任务正文及等待条件；其余内容继续作为说明。员工的岗位指令、工具、Hooks、Guard 和记忆仍由员工注册页管理。

“保存 .md”保存文件；“保存到 Team”通过现有 Runtime 保存可执行定义，并把完整文档保存在 `presentation.markdown`。所有背景、标题、普通笔记和额外文档属性都会保留。仅修改执行定义而省略 `presentation` 时，Runtime 保留原文章；再次展示时将最新员工、任务和依赖映射回文档。

“实践”先保存当前 Team，选为对话团队并准备一条对话输入，由拥有模型和权限上下文的 Agent 确认输入后执行。打开文件、阅读文档、编辑正文、展开图谱都不会运行任务。

Team 的“团队文档”页和聊天右侧详情使用同一套文档展示；详情默认只读，也可以展开关系图。“在 bush-it 中编辑”将当前文档带到写作界面，保存到 Team 后两边都能读取。Agent 直接编排出的 Team 即使没有附加文档，也会根据名称、简介、任务与依赖生成可读文章。

旧图谱版本的 Team Markdown 仍可读取；重新导出使用独立的 `team` 配置和显式依赖。保存继续校验已启用员工、有效 ID、任务正文、依赖和 revision，运行继续冻结启动时的定义，没有第二套模型执行循环。

参考 [完整协作文档示例](examples/team-order-review.md)。

## 验证

`npm run test:md-presentation` 覆盖文档/Team 往返、普通引用与执行依赖分离、正文保留、图形编辑、文件冲突以及 Chromium 中的文档视图、实践入口和窄屏布局。`npm run test:team` 覆盖执行、记忆、调度、结果通知和持久化边界。
