# summary_for_user 与个性化记忆

## 设置和调用选择

设置侧栏提供独立的 **summary_for_user** 页面。习惯和预测仍是独立开关，默认关闭；输入框「+ → 个性化记忆」与习惯开关同步。设置从下一轮任务生效，关闭不删除已有记忆。

自动总结阈值默认 **10,000 tokens**，可设置 1,000–200,000 的整数。页面显示有效记忆估算用量、习惯/预测/待整理笔记数、累计命中与否定次数、失效记录数和历史变更数，支持手动总结与失败后重试。手动总结使用当前选择的已配置模型；自动总结沿用触发任务的模型。两者会产生模型用量。记忆条目页可检查原文、条件、来源、确认/过期时间，修正、撤销或确认并固定；历史页显示变更前后内容，并提供撤销入口。

每个运行环境独立保存 `dataRoot/personalization.sqlite`。设置页可选择本机或已连接的 Agent 查看状态、手动整理；模型配置和阈值沿用客户端配置，记忆内容不跨主机自动复制。

## assistant 主对话接入（2026-10-08）

assistant 的文字主对话及转写后交给主对话处理的语音，复用本机 Runtime 的 `personalization.sqlite` 和全局个性化设置，不建立第二份记忆。新用户输入触发与普通会话相同的相关召回：`context` 模式投递约 510 估算 tokens 预算内的内部参考，`hint` 模式仅提示候选数量；当前上下文已经收到的记录不重复投递。引用与已处理输入一起持久化，模型重试、重启不重复观察同一输入。引用不会作为可见用户消息展示。

主对话开放现有 `check_habit`、`summary_for_user`、`revise_memory`，沿用同一组参数校验、分类开关、原文补查、幂等回执、变更历史和用户固定保护。明确纠错只能引用本次响应的新用户原文，不能用历史用户话语或工具输出代替证据。后台任务回传不触发自动召回或预测证据收集，也不能新增或修正记忆；仍可按需读取、发送空的最终展示回执和报告任务结果。习惯与预测都不构成自动派发任务的授权。

设置从下一次用户输入生效。主对话在每次模型请求前检查引用的失效/变更；对话压缩后额外保留最近至多 64 条引用的版本标记，以便后续撤销仍能生效，同时避免版本信息无限增长。更早的记忆需要时仍可按 ID 补查。重置 assistant 会清空其对话与注入记录、隔离迟到结果，保留共享记忆库；存储暂不可用时仍能正常回复并返回真实的未保存状态。

原生实时语音直连供应商使用独立音频会话，本次主对话接入不改变该通道；其派发的执行子会话继续按原有 Runtime 记忆规则运行。源码更新后需重启加载新的 Runtime。

`npm run test:assistant` 包含 `assistantMemory.test.mjs` 的共享库集成、提示/开关、跨轮与重启去重、语音转写、补查/保存/纠错、固定保护、后台回传、失效更新、压缩后的版本跟踪、重试、重置和存储失败回归。测试使用隔离临时数据库，不读取或改写用户记忆。

## 简洁工具

- `summary_for_user({ habit?, prediction? })`：两项独立、可省略，每项仅必填 `text`，可附 `applies_when` 和 ISO 格式的 `expires_at`。习惯记录有依据的通用偏好，预测记录尚未确认的后续需求，不能混写或为填齐而编造。建议少于 200 tokens，每项正文与条件合计最多 400 估算 tokens、正文至多 1,600 字符。启用项超限会明确拒绝该次写入，不静默截断。不要记录工具执行流水、秘密或推测的敏感特征。
- `check_habit({ mode?, kind?, cursor?, topics?, ids?, count_only? })`：默认按 `topics` 的 1–3 个简短主题查找相关条目，合并候选并共用约 1,000 tokens／最多 5 条的摘要预算；省略主题读取近期有效记录。`kind` 可限定习惯、预测或旧笔记。用户要求列出自己的习惯时，用 `mode: "list", kind: "habit"` 渐进读取：每页包含该类别的准确总数、预算内的一小页条目和 `next_cursor`，需要更多时保持类别沿游标续读。列表按稳定序号分页，新写入不挤入已开始的扫描，不再需要猜关键词拼凑全量。元数据本身超出单页预算的旧记录会在 `omitted` 返回 ID 和 `budget_limited` 原因，游标继续前进；原文仍可单独按 ID 读取，既不静默丢弃也不阻塞后续页。`count_only: true` 只返回候选数量，不加载内容；无主题时计数不受相关搜索的 64 条候选限制。`ids` 单独使用可读取至多 3 个指定 ID 的完整原文，包括失效状态和替代关系，不执行摘要截断，只在确实需要原文时使用。重复读取不因已投递而屏蔽。不调用是正常情况。
- `revise_memory({ id, revision, action, reason, user_quote?, replacement? })`：按当前版本标记 `dispute`、`retract` 或 `supersede`。撤销/取代必须提供当前用户纠正中的原句，宿主核对该句确实存在于当前用户消息；缺乏这类证据时只能标记争议。取代需传简短的新条目及 `kind`。用户在设置中确认并固定的记忆，Agent 不能改动。一次例外不应被解释为永久偏好变化。

调用规则写入系统提示、每轮个性化偏好和工具描述：本轮执行过其他工具且准备给出最终回复时，Agent 应调用一次可用的 `summary_for_user`，再输出最终答复。开启记忆时可附带有依据的新笔记；没有新笔记或记忆关闭时，仍用 `{}` 发出终轮展示信号，不能把“无内容可记”理解为“工具任务无需收尾提示”。普通聊天可以直接回复，完全不调用工具，不需要空调用占位。`check_habit` 继续按需补查。

这是模型的调用提示，不是运行时强制：Agent 决定何时收尾，本地不自动补调、不因漏调额外循环，也不把调用设为任务结束条件。先完成记忆事务，再返回 `status/final_response/saved` 和逐项 `writes`：`created`、`deduplicated`、`rejected` 或 `skipped`，包含记录 ID 或拒绝原因，不回显正文。存储失败不阻塞最终答复。相同操作 ID 的重试重放原回执；同轮同内容的重复写入也不增加观察次数。模型重复写入不刷新用户确认时间。

例如：`{ "habit": { "text": "默认关注 A 股。", "applies_when": "查看股市走势" }, "prediction": { "text": "用户可能需要 XLSX 数据表。", "applies_when": "查看 A 股走势之后" } }`。预测未指定期限时默认 7 天；习惯默认不自动过期。过期记录退出搜索和预测证据收集，但仍可按 ID 检查。`applies_when` 是可核查的简短条件，不是自动执行代码或授权。系统不把模型自报的数值当作已验证置信度。

## 混合检索

每个新用户轮次依据本次输入检索少量相关记忆，以内部 `habit_reference` 参考消息追加，总体约 600 tokens。引用包含明确的历史参考标识：笔记未整理、预测未确认；当前用户指令和既有操作权限优先。没有相关记录时不追加消息，不改变系统前缀。

设置可切换为“仅提示候选数量”：主机仍做本地检索，但不附带记忆内容，由 Agent 决定是否调用 `check_habit`。默认保留自动附带少量相关内容。候选数量仅表示本地词项检索结果，不是已验证的适用条数；有限候选达到上限时标明 `count_capped`。

**去重只作用于自动注入，显式读取不受已投递 ID 影响。** 自动路径同时识别直接检索和 `parallel_tools` 中已返回的记忆。搜索摘要明确给出 `truncated`，按 ID 可读取完整原文。检索回执区分 `no_match`、`disabled`、`unavailable`，自动路径另有 `already_supplied` 和 `budget_limited`；按 ID 缺失/关闭的条目逐项列在 `omitted`。没有匹配不意味着存储不可用，已经提供也不意味着原文消失。

条目返回 `created_at/age_days`、`last_confirmed_at`、`last_rejected_at`、来源会话/轮次或整理来源 ID。更新时间、模型复述和压缩日期都不能当作用户确认时间；未知确认时间保持空值。旧引用仍在当前上下文时，记录失效、过期或恢复会追加 `memory_state_updates`，不会静默改写已保存的对话。

索引使用中英文分词、中文双字片段及中英混合短词，按词项匹配与近期记录排序。数据库维护词项索引，只选有限候选；不扫描或返回全库。它是本地词项检索，不是向量语义搜索；总结时保留用户使用的短别名，模型也可换主题词补查。

## 存储、预测复盘和总结

1. `habit`、`prediction` 分类持久化，正文、条件和显式期限共同确定去重身份；跨类别不合并。同轮重放不增加观察次数。已有混合笔记保留原 ID 和原文，后续整理依据出处分类，不按关键词猜测强行迁移。
2. 开启预测时，只为预测或旧笔记中的候选预测关联后续真实用户输入，长度有界；习惯记录不进入预测命中计数。证据仅受预测开关控制，关闭习惯不影响预测和证据的读取。助手自己生成表格或执行了工具，不作为用户命中证据。
3. 累计到阈值后在后台调用模型整理；未达到时不额外调用总结模型。整理同时合并同义笔记、保留条件化习惯、审查预测与后续证据、淘汰无依据预测。单个输入过多时分批处理，每批限制输入/输出，单次作业有时间和批次数上限；关联证据还未审查完时，保留对应的原预测，避免后续批次失去复盘依据。
4. **命中和否定在模型总结复盘时写入 SQLite，而非每次输入都额外调用模型分类。** 只有后续用户明确需要预测内容才算命中，明确反驳才算否定；仅话题相近、过期或没提到不算失败。预测和证据 ID 必须真实存在且关联时间正确，同一对证据不重复计数。
5. 总结模型根据重复命中或明确长期偏好形成习惯；已被否定的预测只有在用户证据确实支持时，才归纳成带条件的负向偏好。未验证猜测不能直接当习惯。这样可逐渐形成“查看大 A 走势时通常需要 XLSX 报表”一类可复用偏好。

模型整理是共享 `ModelProvider` / `executeModelRound` 的独立无工具请求，沿用配置的 Responses、Chat Completions 或 Anthropic 适配器。它不执行工具，不参与主对话的继续/结束决策，不引入自动执行预测的任务队列。旧版认领/消费字段已从两个工具的公开接口移除。

SQLite 短事务保存条目、索引、操作回执和变更日志。纠错把原条目标记为失效，保留原文和替代 ID；后台总结也使用同一条留痕路径，将旧条目标为已整理，保留来源、原始记录时间与确认依据。同类总结不延长来源的有效期，模型执行期间过期也会拒绝更新。用户固定条目不参加模型整理，已失效条目不能通过重复写入或模型总结悄悄复活。设置页撤销操作会检查受影响记录的版本，不能覆盖其后的修改；撤销总结时一并恢复对应复盘计数和证据。

总结先取得有租期的快照锁，模型请求在事务外执行；成功输出经结构、来源、证据、条件和缩减幅度验证后，再在事务内更新有效视图。并发写入导致版本变化时保留原数据，提示稍后重试。模型失败、无效结果、取消、超时均不清空原数据。进程内合并同时触发的总结，数据库租期阻止多进程重复整理。

整理使用运行时的 `contextWindowTokens`，不读取旧的 `maxContextTokens` 字段。每批最多 32 条，按实际序列化记录估算输入，预留指令、JSON、来源 ID 与推理的输出空间；单次作业最多 8 次请求、120 秒。输入超限或输出截断时最多缩小批次两次，不能把截断 JSON 写回记忆。只完成部分批次不会把整份记忆标成已经整理，后续可继续处理剩余记录。

错误状态区分输入超限、输出截断、供应商失败、JSON/结构校验失败、快照变化和取消，记录标准结束原因、输入/输出 token 和批次条数，不回显记录正文或供应商错误原文。瞬时错误保留固定五分钟重试间隔。确定性失败按“记录 ID/版本 + 模型配置”指纹暂停自动重试，重启或追加无关笔记不会再次发送同一失败批次；修改相应记录、模型配置或手动重试可以重新尝试。SQLite 保留最近 256 个失败指纹，手动操作不受失败指纹或等待时间限制。

有效记忆受 token 和 8,000 条记录上限约束；变更日志限制 2,000 次／32 MiB 正文，操作回执保留最近 10,000 次。达到上限会暂停新增并明确报告，不静默清空。历史不自动注入模型，设置页分页读取；用户可明确清理失效原文和历史，保留有效记忆及防止失效 ID 被重新写入的简短标记，清理后不可撤销。旧结构首次打开时在事务内升级，不维护两套工具参数协议。

## 展示生命周期与验证

Runtime 只认可当前轮的真实成功工具回执，下一条助手响应带有 `finalResponse: true` 时，在首段正文开始流式输出就折叠之前的执行记录，最终正文单独继续显示。折叠区仍可展开，流式阶段保留运行状态，真正结束仍由 terminal/done 处理，完成操作按钮与产物汇总不会提前出现。继续调用工具会恢复过程展示，新用户引导会使旧终轮意图失效；主机追加的记忆状态通知不取消这个展示信号。
