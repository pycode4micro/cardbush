# Team 独立插件

Team 的执行、成员配置界面、配置文件存储和专用提示已从主应用拆出，位于 `packages/cardbush-team-plugin`。本轮只做插件化，保留旧的 `team_delegate` 行为；没有实现 `team_chat`、群聊、私聊或自由讨论。

## 安装与更新

在仓库根目录执行：

```sh
npm run build:team-plugin
```

产物是 `release-plugins/team-0.2.0.zip`。通过「插件 → 从 ZIP 安装」安装，也可安装构建后的 `packages/cardbush-team-plugin/plugin` 目录。

主应用的依赖、默认 Runtime 构建和内置市场中已经移除 Team。安装包同时包含 Runtime 与界面代码；更换插件包即可更新这两部分，不需要重新编译 CardBush。当前仓库保留插件源码方便开发和回归，并不表示应用发布时仍携带该包。已有旧版内置 Team 安装状态需要用这个 ZIP 重新安装。

## 宿主边界

- 清单使用 `cardbush.runtimeExtension` 对象声明 `apiVersion: 1`、`entry` 和可选 `renderer`。入口是包内自包含 `.mjs`，不再使用宿主写死的 Team 工厂或界面导入。
- Runtime 提供通用工具注册、命令、能力声明、数据目录与既有子任务接口。注册先暂存并校验，成功后整体提交，失败不能留下部分工具或覆盖核心命令。
- 界面通过通用 DOM 挂载、选择状态订阅和命令接口加载。插件可自带 UI 框架，主应用不导入其 React 组件、配置校验器或提示实现。现有 Team 导航和历史委派字段作为兼容入口保留。
- 插件路径必须在包内，校验实际路径、入口大小和 API 版本。安装与解压继续沿用既有事务和路径校验。
- 只加载已安装并启用的插件。工具和界面按内容哈希复用，未变化的清单不会反复装配、刷新编辑器或清空草稿。
- 停用、卸载先关闭新请求入口，正在使用的处理器保留到运行结束；更新也会等待当前执行或配置命令收尾。普通 Subagent 属于核心 Runtime，独立可用。
- 可选模块抛错会保留具体错误并关闭相应入口；界面显示局部错误，不以重载整个应用兜底。安装包错误、配置错误与核心会话运行分开处理。

这是 CardBush 的原生扩展协议，执行代码具有 Runtime 进程权限，界面代码也是受信任的本地插件代码，不宣称沙箱隔离或可直接运行于其他 MCP 宿主。自包含 bundle 可以导入 Node 内置模块，但不能依赖宿主安装目录中的 npm 包或源码路径。

## 配置与历史

配置位置仍是 Electron `userData/plugin-data/team/teams.json`，由宿主显式传入；不根据 `apps.json` 所在目录推断，避免在 `product-host/config` 下意外创建第二份配置。

该文件是唯一可编辑来源。保存使用文件哈希、文件锁与临时文件替换；外部编辑或另一窗口保存后，旧草稿不能覆盖它。JSON/YAML 导入导出和首次 localStorage 迁移保留。停用、卸载、重新安装不会删除配置。

运行时快照继续用于校验实际执行约束。保存先校验并提交快照，再写配置；不确定响应或写入冲突后，下次按配置文件重新同步。此处沿用之前的事实边界，不新增另一套配置或执行历史。

## 验证

- `npm run test:team-plugin`：既有 Team 配置与委派回归、通用扩展回归、独立 ZIP 安装/卸载/更新、损坏包、路径越界、配置保护，以及配置界面测试。
- `node scripts/test-runtime-plugin-ui.mjs`：只从实际安装 ZIP 中加载界面；验证原生配置桥接、选择与快照、刷新时 DOM/焦点/草稿保留、禁用、损坏配置恢复、独立界面更新与窄窗口布局。
- `npx electron scripts/test-runtime-utility-host.cjs`：独立 Electron Utility Process 使用安装后的入口，验证启停、错误恢复和明确的配置目录。
- 主应用和插件分别进行类型检查与构建；主应用构建不再编译 Team。

没有调用真实模型 API，没有新增 Team 执行能力，也没有修改用户实际插件安装状态。
