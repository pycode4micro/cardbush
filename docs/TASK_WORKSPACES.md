# Local、Worktree 与文件版本

CardBush 的工作区现在采用 Local / Worktree 两种执行模式，并使用 Git 对象保存 Git 工作区的文件版本。代码、文档、表格、图片和配置使用相同机制，文件类型不决定是否能够保存版本。

本次借鉴的是 Codex 公开的执行模式及 Git 管理方式，不声称复刻其未公开的逐轮快照实现。参考：[执行环境](https://learn.chatgpt.com/docs/environments/modes)、[Git worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)、[审阅与撤销](https://learn.chatgpt.com/docs/code-review?surface=app)。

## 使用方式

- 新任务自动使用 **Local**，直接在所选项目目录工作，会话顶部不再显示工作区详情栏。
- 需要查看 Git 分支、创建仓库、应用任务副本或恢复检查点时，打开右侧栏的“审查”，再展开工作区操作。项目会话即使还没有文件修改，也能进入审查；工作区读取在打开审查时进行。
- **Worktree** 必须显式选择，并要求 Git 仓库根目录及至少一个提交。CardBush 创建 detached HEAD 工作副本，带入原目录未提交的修改及未被忽略的新文件，不改动原项目分支、HEAD 或暂存区。
- **Local** 的 Git 仓库根目录也能记录终端、脚本和文件工具产生的逐轮修改。没有首次提交的 Git 仓库可以使用 Local。
- 普通文件夹保持 Local，不自动创建隐藏仓库。点击“创建 Git 仓库”后在原目录执行初始化并启用后续任务版本，不自动创建提交。
- 选中的仓库子目录、未安装 Git 或无法完整版本化的目录仍可使用 Local。文件工具保留原有撤回方式；不宣称终端修改已纳入 Git 版本。无法启用时显示实际原因。
- 已有 Worktree 任务保留执行位置。`auto` 协议值为兼容入口，新任务按 Local 处理；不会迁移正在使用的工作副本到原目录。
- Worktree 的“应用到原项目”只应用已审阅的文件变化，不提交、暂存或移动分支。“丢弃副本”只删除此任务拥有的 worktree，原目录不会被删除。
- 尚未开始且没有任务修改的 Worktree 可以切换到 Local。当前未实现 Codex 完整的双向 Handoff、暂存区操作面板或逐块接受界面。

## 文件版本与执行事实

- Git blob 保存原始文件字节，Git tree 保存路径与文件类型/可执行位。恢复点通过 `refs/cardbush/workspaces/<任务哈希>/snapshots/<tree>` 保持可达，使用仓库现有对象库。
- 临时 Git index 与用户的 index 分离，写完即移除。恢复点不会产生用户分支上的自动提交。
- 文件哈希使用 Git 的 `--no-filters`，新增内容以批量对象写入，跳过换行转换、clean/smudge 和编码过滤。恢复时按原始字节写入并验证对象内容。SHA-1 与 SHA-256 仓库均有测试。
- 每轮保存执行前后 tree 引用。事务日志只记录前后 tree 引用及受影响路径，不再持久化整份 JSON 文件清单。原来独立的 `blobs/` 和 `snapshots/` 不再用于新版本写入。
- `ToolExecutionRecord` 继续记录实际工具调用、结果和冻结的模型文本。Git 版本不伪装成模型工具调用，也不把后台扫描算成模型已读取文件。
- 文件工具只有确认当前轮的 Git 版本覆盖该路径后，才省略独立的旧内容备份。忽略文件或目录外的工具编辑仍保留原有证据，界面不会把它们隐藏在 Git 检查点下。
- 单次工具的中间修改与整轮的最终差异属于不同时间范围。历史事实不因后续编辑、审阅或撤回而改写。

## 历史读取与实时审阅

`runtime.get_workspace` 支持 `view: history` 和 `view: live`：

- 历史模式只读取已记录的恢复点及 Git 对象，不枚举工作目录，不触发文件恢复。对话加载和历史修改记录使用此模式。
- 实时模式重新核验工作目录的文件集合和字节，给审查面板中的工作区操作提供待应用的当前版本。尚未经过新审阅的外部修改不能使用旧审阅凭证应用。
- 同一个 tree 的历史差异可以复用内存中的只读投影。缓存按任务、目录及前后 Git 对象 ID 区分，返回值隔离，缓存不承担持久化事实或恢复依据。
- 未变化的内容复用 Git 对象和 tree 引用，不生成新的版本清单。字节校验仍然保留，不把 mtime 或文件大小相同当成内容未变化的证明。

工作区操作展示任务起始版本（Worktree 为上次应用版本）以来的差异；它不是 Git 暂存区、分支或整个仓库全部未提交修改的通用面板。

## 冲突、中断与迁移

应用和撤回会预检当前文件的实际字节、文件类型与版本。写入前保存事务意图，并在每个路径写入前再次核对；恢复只处理仍匹配事务前或事务后状态的路径。外部出现第三种内容时保留该内容并报冲突。

Git 原生对象和 refs 负责版本数据；多文件恢复的执行及中断处理仍由 Runtime 负责。Git ref 的原子更新不能替代文件系统的多文件事务。

运行中的已知终端不会决定模型何时结束，也不会单独阻止下一轮对话。应用、撤回和丢弃前必须确认相关终端已退出。

旧的 `bush.task_workspace.v1` 检查点读取时会先验证原清单和内容的 SHA-256，再导入 Git，并原子更新为 v2 引用。未完成的恢复事务一并迁移。失败时保留旧状态；成功后也不主动删除旧恢复数据。

一次撤回若同时包含 Git 覆盖内和覆盖外的工具修改，会在写入前明确拒绝，避免返回只恢复一部分文件的成功结果。只有覆盖外工具编辑的轮次仍可使用原有撤回路径。

## 范围

- Git 版本覆盖已跟踪文件、未被忽略的新文件及此前已纳入版本的路径；文件工具明确纳入的本轮新路径即使后来被忽略，也保留在本轮版本中。
- 忽略的依赖、缓存、环境文件不自动复制。二进制和大文件可以保存版本，但界面省略超过 128 KiB 的内联全文差异；Git 不提供表格单元格或文档段落层面的自动合并。
- 不恢复 Git HEAD、分支、用户 index、ACL、扩展属性、时间戳或空目录。POSIX 文件模式遵循 Git 的可执行位语义。
- 子模块、非 UTF-8 路径及无法安全处理的文件类型暂不提供完整工作区版本；Local 仍可保留文件工具的撤回能力。
- 版本依赖原仓库的对象库。恢复点 refs 暂不自动清理，旧快照也不自动回收；删除或移动仓库需另行处理。
- Worktree 是独立目录，不是操作系统沙箱。本次没有新增系统沙箱，也不覆盖外部系统副作用。
- 文件捕获与恢复不能锁住 Runtime 之外的进程，不是操作系统原子快照。崩溃恢复测试构造磁盘上的中断状态，不等同于真实断电测试。

## 验证入口

- `npm run test:task-workspaces`：真实临时 Git 仓库、Local/Worktree、文件字节、冲突、中断状态、旧数据迁移及界面投影。
- `npm run test:app-views`：隔离 Chromium 中的真实组件交互。
- `npm run benchmark:task-workspaces -- --files 1000,10000 --turns 4`：本地规模基准，分别统计历史读取和实时审阅；无付费模型调用。
- 全量 Runtime / 协议测试、前后端类型检查及产品构建。

新增跨轮回归还发现并修复了 Cache Chain 的统计误报：原先在请求 schema 统一字段顺序前计算哈希，轮内工具消息与重放消息会因 JavaScript 字段插入顺序不同而被报告为前缀断裂。现在在实际交给 Provider 的请求形态上统计，保留严格内容校验。

Runtime 全量回归按测试文件顺序执行，310/310 通过；协议测试 24/24 通过。另完成工作区投影、Runtime 客户端、会话与历史契约、前后端类型检查、产品构建，以及隔离 Chromium 中的真实界面交互回归（包括 Local 默认值、创建 Git 仓库与 Worktree 操作）。

曾在同时执行构建、Chromium 和 Runtime 全套测试时触发两个既有终端测试的两秒墙钟断言。单独复现与顺序执行均通过，未放宽断言或修改终端时序逻辑。界面测试另修复了等待条件：先等异步操作完成、按钮恢复可用，再点击刷新或丢弃。

千文件 × 12 轮、万文件 × 4 轮的相同夹具对比均通过。万文件组创建副本 245.08 → 118.07 秒，开始/收尾中位数 9.02/9.64 → 2.40/2.76 秒，实时审阅 8.77 → 2.70 秒。创建成本仍然较高，千文件组收尾约 1.2 秒、改善不明显；不以热缓存历史读取代表冷启动性能。
