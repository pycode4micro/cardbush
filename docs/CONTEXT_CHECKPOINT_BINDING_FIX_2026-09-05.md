# 上下文检查点参数绑定修复

## 本次故障

会话 `local-7632fc24-32f7-4858-9cee-bb6ec6325d84` 的 Turn `turn_23339377-5483-4b3f-8d71-f10f1e8dece9` 在第 72 轮触发前置 Turn 与当前 Turn 的联合压缩。三次返回分别因身份/边界校验、active_turn 类型、身份/边界校验失败，最终以 context_compaction_failed 结束。

会话当时的 revision 为 3，期间没有并发修改记录；原始会话和运行时日志校验完整。故障不是网络断连，也不是压缩摘要成功落库后丢失。

## 新协议

checkpoint_context 的模型输入保持两个固定字段：

```json
{
  "summaries": ["按通知顺序填写前置 Turn 的摘要"],
  "active_summary": "当前 Turn 的累计事实、未完成事项和下一步"
}
```

无前置 Turn 时 summaries 为 []；未授权当前 Turn 压缩时 active_summary 为 ""。有授权时，摘要必须是非空字符串且不超过 6000 字符，摘要数量必须完全匹配。

- Runtime 在安全轮次边界持有授权快照，用它绑定 session revision、前置 Turn 顺序、当前 Turn ID 和 throughMessageId。模型不再回填这些字段。
- 新格式禁止混入身份字段；旧格式为已保存的工具目录保留兼容，并逐字段检查其身份声明，不能用兼容分支覆盖过期 ID 或边界。
- 提交仍检查真实会话 revision；未授权的主动压缩仍被拒绝。没有放松并发或持久化保护，也没有猜测、截断或自动补造缺失的摘要。
- 成功后继续使用原有临时检查点、原始历史和 developer 续跑指令；不会生成替代业务 Turn，也不会执行已完成的工具前缀。

## 失败诊断与重试

错误反馈明确指出字段、期望条件以及实际类型/数量/长度。压缩重试事件和终止事件持久化这些诊断与参数字符数、SHA-256 指纹，不复制完整摘要或工具参数到日志/模型上下文。

模型格式错误仍最多尝试三次，纠正消息只追加到请求尾部。持久化/应用错误不会被当作格式错误再次请求模型；网络重试规则不变。

## Cache Chain 与兼容性

工具 schema 不含动态 revision、ID、边界、数量约束，不随压缩或纠错轮次变化。范围和摘要数量放在尾部通知中。旧恢复检查点沿用其原有工具目录与对应通知格式。

升级后的工具定义变化可能影响首次请求的缓存；真正完成压缩也仍然需要替换上下文。此修复避免的是每次授权/纠错都重写稳定前缀，并非承诺压缩后仍能命中全部旧缓存。

数据库与恢复检查点的数据结构没有迁移，原始工具执行记录不改写。
