# Plugin support baseline

[English](PLUGIN_COMPATIBILITY.en.md) · [简体中文](PLUGIN_COMPATIBILITY.md)

CardBush reads public OpenAI packages/custom marketplaces and original Claude plugin components into shared execution interfaces, preserving each source's invocation and Hook semantics. It does not generate converted Skill files. LSP is outside the product scope; other unsupported executable declarations are reported by compatibility checks. The original specification review was on 2026-09-10; dated measurements in the [Chinese source](PLUGIN_COMPATIBILITY.en.md) remain historical evidence, not current account certification.

## Parsing and capabilities

`electron/pluginManifest.ts` is the read-only parser shared by preview, installation, discovery and execution. Receipts pin source, version and original marketplace entry, not a converted manifest or duplicated Skills.

1. Agent Plugins 1.0.0 root `plugin.json` owns identity; Skills/MCP come from fixed `skills/` and `mcp.json`.
2. When present, `extensions.com.openai` replaces the complete legacy overlay; fields are not mixed. Otherwise use `.codex-plugin/plugin.json` extension configuration.
3. Without a standard root, support standalone Codex, then Claude manifests. Unknown standard schema versions fail explicitly.
4. Hooks retain source identity; denying a tool, requesting continuation and stopping a turn remain distinct. Runtime still owns facts and permission enforcement.

## Connection startup and updates

Readiness requires handshake and complete tool discovery. Separate preparation/handshake deadlines default to 15 seconds each, discovery to 60 seconds; `startupTimeoutMs` overrides them. Timeout closes the attempt, releases its queue slot and retains its phase error. Cancellation, disable and shutdown abort waits; late connections cannot replace a newer one or publish stale tools. Windows stdio launchers must preserve the tracked process and stdio: invoke the real interpreter directly or wait for its child and forward its exit code. POSIX `execv` behavior is not automatically portable to Windows. The source's Qianchuan timing is a historical reproduction only.

Hot reload compares transport configuration and `implementationFingerprint`, derived from version, runtime source and dependency manifests. Hashing skips symlinks, dependency/cache/log/output/docs/Skills directories, streams large files and reuses unchanged hashes. Timestamp-only changes, identical reinstalls, icons or docs do not restart MCP. Local replacement waits only for that server's dispatched calls before releasing its port; remote replacement can publish the new catalog while retaining the old transport for in-flight calls. Native extensions retain old versions per invocation until disposal is safe. Other plugins are unaffected.

At the next ordinary model boundary, additions/changes/removals generate one bounded notice. Existing model requests stay unchanged; old arguments/approvals cannot authorize revised definitions and business actions are never replayed. Child/plugin-agent/scheduled scopes do not automatically widen. External dependency changes can use `reconnect_mcp_server` with an exact ID; it reconnects one non-bundled service without editing config or restarting the app. `pending.applicationPhase` distinguishes connecting, waiting for calls and resources; schema loading does not restart a process.

Config saves and reconnect return after acceptance; slow connections run independently in the background (default concurrency four). Required-service transactions retain all-or-rollback semantics. Manual reconnect only affects its target; superseding config cancels old attempts. `updateState/pendingServerIds` describe management state, `tools` only published definitions. UI observes progress without reloading the application. Internal callers may await the same manager; there is no second connection implementation.

## Skills and plugin children

- OpenAI interface name/icons/example prompts serve UI, while SKILL.md description serves discovery. `allow_implicit_invocation:false` and Claude `disable-model-invocation:true` prohibit automatic model invocation but retain allowed manual use. `user-invocable:false` hides manual entry independently.
- Namespaced `plugin:skill` prevents collisions. `/plugin:skill args` and `$plugin:skill args` invoke manually where permitted. Models search then use `run_skill`; commands and Skills retain distinct identities, and conflicting manual entries fail installation checks.
- OpenAI `dependencies.tools` MCP URLs use normal connection management. Same-name bundled services can be reused, conflicting addresses fail. Preview neither connects nor opens login. Missing/unexposed/out-of-scope dependencies fail execution.
- Claude `context:fork` supports general-purpose, Explore, Plan or same-plugin Agent, normally background; `background:false` waits. Agent `background:true` and subagent background mode are also supported. Parent model/permission ceilings apply, tool restrictions can narrow them. Children cannot recursively dispatch through Skills/Commands; inline Skills remain usable. Explore/Plan require read-only tools.
- Agent `skills` preload same-plugin static content. Missing/disabled/model-forbidden/out-of-scope dependencies fail after local MCP connects. Dynamic/forking Skills cannot preload as static instructions.
- Dynamic shell context uses normal escaping, approval and cancellation. `allowed-tools` cannot bypass host permissions; `disallowed-tools` applies during execution. Preview/install/catalog browsing never run scripts.
- `pluginHookScopes`, `pluginAgentEnvironment`, `pluginBackgroundTasks` and desktop `pluginAgentMcp` separately own scope, resources, background lifecycle and transport. Skill/Command Hooks activate on actual invocation through session end; fork activates only its child. Agent Hooks last only for that assignment and local Stop maps to SubagentStop. Persist activation IDs, reread definition/trust on every execution.
- `isolation:worktree` requires a committed Git root. Unchanged copies without background processes are cleaned; modified copies remain for review/application and never overwrite the source automatically.
- Agent-local `mcpServers` may reference parent connections or trusted inline stdio/HTTP definitions. Connect on child start, close on finish/cancel, preserve stable OAuth identity and child namespaces, keep local tools out of the parent's public catalog. Exact tools and server wildcards work; discovery requiring login uses the existing host flow.
- Background work reuses Subagent journals, maximum eight concurrent, observed with `tasks`. Results deliver on the next parent round and are marked delivered only after commit. Restart marks ownerless work interrupted without replay. Permission requests after the parent turn use an independent host form; closing/canceling ends the wait.
- `permissionMode`: default inherits; acceptEdits uses workspace grants; bypassPermissions requires the parent already allow full access; dontAsk refuses extra grants; plan restricts to read-only tools.

## Discovery, replay and cache

`mcp_search` returns names, short descriptions, loaded state and paging, not schemas. `get_tool_schema` takes one exact `name` or up to 16 exact `names`, not fuzzy names or legacy reload. Partial batches retain successes/errors; budget-deferred items are not marked loaded. Full receipts bind source/revision/session and persist as ordinary messages. Each request restores loaded definitions only from complete visible receipts or complete archive pages; summaries, references and partial pages are not sufficient. Changed definitions append new receipts without changing history. `call_tool` always rechecks current scope, revision and permission. The final model projection removes boilerplate protocol/session/next-step fields; archive bodies/offsets and durable identities remain intact.

`search_skills` returns metadata and `mainResource`; ordinary file reading obtains the body, without a new Skill-load API. Plugin Skills still require `run_skill` for policy/args/dependencies. Skill/MCP search default Top 8 is configurable in plugin settings from 1–50; per-call limit wins, pages advance by actual count. The existing apps.json stores it; changing it does not reconnect, change schema or rewrite history. Exact-name schema batches are independent. See `test:plugin-search-settings`.

Responses native `tool_search` maps to the same discovery records and `tool_search_output`; loaded calls pass normal coordinator checks. Deterministic wire aliases handle long names, derived from request/receipts without another mapping store. Complete schemas enter `additional_tools`. Parallel batches commit all results before attributed discovery/archive additions, including incremental requests. Generic fallback uses the same history/parser/registry.

Capability negotiation uses actual explicit protocol rejection, not vendor/model-name guesses. Authentication, quota, network/service faults and schema errors do not imply unsupported native search. Generation and counting capabilities are separate. A context recovers its protocol from validated provider replay; expiry does not switch a live chain. Duplicate schemas across top-level/search/additional tools are emitted once, with every call result preserved. Key order does not change equality. Changed declarations are removed only from the derived outbound history; if already sent, abandon the old response anchor and replay full history once, then resume continuation. Durable results are unchanged.

Stream item indexes bind text/reasoning/tools. Done/final snapshots may fill missing deltas, duplicates never concatenate twice, conflicting identity/args fail before execution. Cancellation checks precede each delivered event; terminal events end reading and truncated tool batches do not execute. Archive overlap must agree. Existing `toolSearch.test.mjs`, `pluginContextCache.test.mjs` and [historical adversarial testing](RESPONSES_ADVERSARIAL_TESTING.md) cover these transport boundaries, not universal provider cache hit rates. User-visible errors follow UI language while raw provider details remain expandable; prompt language guidance is not proof of model compliance.

## MCP Apps and media

UI resolves from a recorded tool execution's `_meta.ui.resourceUri` or `openai/outputTemplate`, on that same server. Supported types include MCP Apps HTML, legacy skybridge and HTML. Successful tools can append `runtime_app_reference` with a title and `cardbush-app:` Markdown reference; the model chooses whether/where to cite it. The reference is bound to the original session/turn/call, not issued for failed results, and is preserved in archives without rewriting existing messages/tools.

Opening a reference loads its independent view; a new turn closes/cancels it and neither revisiting history nor finishing a turn auto-reopens it. Recorded embedded outputs use the shared describe/render path without replaying generation. Explicit artifacts, MCP media and resource links retain original execution provenance; ordinary files use Markdown links/images, with optional `remember_file` when a durable memo is needed. No arbitrary log scraping invents deliverables. Child-local historical UIs still need a live authorized connection.

Final reply image/audio/video appears only at its authored position/order, audio/video as players; no duplicate top/bottom media region is synthesized from tools. During the loop, media follows the originating call; later observation of the same file updates its existing preview. Streaming, stop/failure and reopened history use that order. File-change summary stays last. Multiple UI outputs follow execution order; newest loads by default, but explicit selection of an older output is respected.

`McpAppPanel` retains initialization, results, tool/resource requests, authorization, follow-up messages, context updates and common `window.openai` APIs. Calls/resources in one instance queue by arrival and receive their own result/error with permission, Hook and journal handling. Failure does not retry or block subsequent requests; status/authorization/context/close bypass the queue. Closing/canceling/connection expiry discards queued work and late replies. Authorization IDs prevent old status from redisplaying answered requests.

Tool names resolve within the task/server/Agent scope, exact server names first. A unique short name may omit one dot-delimited prefix (`studio.export-design` → `export-design`), preserving case/punctuation. Missing, ambiguous and UI-forbidden errors are distinct; a prohibited exact match never falls through to another tool. UI-only tools follow the same checks without appearing in model discovery.

Host theme variables supply colors, font and radius using [MCP Apps host styles](https://apps.extensions.modelcontextprotocol.io/api/functions/app.applyHostStyleVariables.html). Theme updates do not reload the iframe or override a chart's own palette. Transparent defaults, `CanvasText`, and `prefersBorder:false` avoid duplicate borders/black text on dark backgrounds. DOM height fallback is 160–900px; explicit intrinsic-height notifications win, including legacy notifications without handshake. Expansion promotes the existing dialog to the browser top layer, preserves its placeholder and iframe/input/state, updates host/window context and collapses with Esc; oversized content scrolls inside the iframe.

The iframe has opaque `sandbox="allow-scripts"`, resource-declared CSP domains, and no camera/mic/location/clipboard by default. Denied sessionStorage gets page-local in-memory Web Storage, cleared on close/reload, never same-origin/cookies/persistence. Host blocks self-navigation, validates source windows and retains instance tokens outside the iframe. It cannot target another server; external links/follow-ups require host confirmation. UI `_meta` stays in native results/UI only, not model output.

Script/style loading and uncaught page errors create expandable diagnostics/retry and observations with URL queries/fragments stripped. A broken single image, empty content or arbitrary business field is not inferred as tool failure. Only MCP `isError:true` marks failure and suppresses its UI; original evidence remains. Actual client reconnect/account change invalidates instances; unrelated catalog publication does not. Explicit expiry/connection errors may reload resources once, never replay generation/UI actions. Further errors expose manual retry. Network follows [plugin proxy settings](PLUGIN_PROXY.en.md).

`mcp_app_status` reports declarations, active instances and ordered `resource_loading/resource_loaded/frame_loaded/initialized/failed/closed` observations (latest 128 with sequence/time/truncation). Loaded HTML is not a handshake or task success, historical events are not active instances after restart. New observations append at existing model boundaries without forcing another round or rewriting prefixes. Plugin `ui/update-model-context` is separately attributed untrusted data, deduplicated and saved for the next request; it never impersonates user instructions or wakes an idle model.

Schema receipts separate server schema/UI from `hostCapabilities`; search does not repeat full metadata. Upload/import instructions stay with the tool, without application-specific rewriting. Native MCP results stay intact; model/archive projection only removes private `_meta`. No extra status envelope, invented facts or JSON extraction is added. `structuredContent` can be null/scalar/array/object, outputSchema mismatch does not discard a received result, but the base protocol must decode. Invalid responses retain `rawResult` errors. Never replay to repair result formatting or infer success from prose; cancellation blocks late response delivery, and SDK interaction continuation is not final completion.

OpenAI hosted app-only tools remain UI-visible only for the selected app. Other apps/resources cannot be reached. Proprietary payment, ChatGPT upload/download or account entitlement APIs are not faked.

Plugin prompt examples and “ask the assistant to diagnose” open editable drafts, not auto-send/install. `$` references installed plugins with icon/name and original absolute manifest link; unavailable catalog entries use a generic plugin badge without rewriting history. Diagnostics carry current service identity/state/error so the model can read the plugin's own instructions, not a hard-coded dependency installer.

## Hook boundaries

Events: SessionStart, SessionEnd, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, Stop, Interrupt, SubagentStart, SubagentStop, plus PostToolUseFailure compatibility.

Installation/enabling grants no Hook trust. UI exposes original event/matcher/handler; explicit trust records the definition hash in existing plugin config. Definition or location changes invalidate trust. Matching handlers start concurrently; denials dominate, and explicit Stop/SubagentStop stop dominates continuation. Handler errors are failures, not semantic tool rejection; rewritten args still validate and pass admission. PermissionRequest only runs when permission is actually needed and cannot override hard denial.

`mcp_tool` reuses connected tools with no service startup, recursive Hooks or extra permission request. Its budget is the smaller of Hook timeout and service timeout (default 60s), excluding user elicitation waiting; unavailable for SessionEnd/background. Background command Hooks have eight slots per session, then queue. Completed context enters the next existing model request after current model/tools settle; idle completion does not start a turn. Closing cancels work/discards pending context; SessionEnd is synchronous.

ToolExecutionStore records actual post-Hook args while original model calls stay in assistant messages. PostToolUse may change only model-facing output, not native results/effects. Late background records persist without reopening a closed stream. Command default timeout 600s; Interrupt/SessionEnd default 1s, configurable 1–3s. Support commandWindows, PLUGIN_ROOT/PLUGIN_DATA and additionalContextLimit; large output archives with head/tail, input ≤2 MiB and stdout/stderr ≤8 MiB combined.

Claude prompt Hook is a tool-free single model round (30s default); agent Hook allows up to 50 rounds with only already-exposed parent `read_file/search_file_content` (60s default). Both use current binding and no recursive Hooks. Output must be `{ok:boolean, reason?:string, impossible?:boolean}`, reason required on denial. Pre/PostToolUse prompt denial normally ends the turn unless continueOnBlock; agent denial permits follow-up. Stop/SubagentStop denial requests continuation, except prompt impossible:true may end. Already-dispatched parallel calls may finish; queued ones cannot start after stop.

Claude HTTP Hooks POST event JSON to HTTP(S), no redirects; only allowedEnvVars may expand headers, input ≤2 MiB, response ≤8 MiB, with timeout/cancel. HTTP/prompt/agent definitions all need trust. SessionStart runs first use/resume and compact-before-continuation at the real checkpoint; pre/post compact bracket it. Interrupt means explicit main-task stop, SessionEnd means delete/normal Runtime shutdown, not navigation. No invented 30-minute idle disposal or manual clear/compact events. Tool names/args remain real; terminal_exec is matched as Bash, polling does not rerun PreToolUse and PostToolUse waits for command completion. `transcript_path:null`, mapped permission_mode plus real cardbush_permission_mode avoid fabricated host state.

## Connection configuration and accounts

Plugin “services and tools” edits `config.mcp_servers` in existing apps.json, not the manifest:

```json
{"mcp_servers":{"docs":{"enabled":true,"default_tools_approval_mode":"prompt","enabled_tools":["search","read"],"tools":{"search":{"approval_mode":"approve"}},"oauth":{"client_id":"provider-issued-client","scopes":["docs:read"]}},"design":{"server":"my-design-mcp"}}}
```

Aliases refer to bundled MCP or `.app.json`; an explicit server must exist/enabled, otherwise unavailable without fallback. Bindings reuse declarations, not another host's login; namespace, tool policy and OAuth identity remain separate. Revision checks reject racing edits, keep unsaved input and prevent login with unsaved changes. `list_plugin_connections/configure_plugin_connection/request_plugin_credentials` reuse the same host/store/resolver, with exact plugin/component/revision. A saved config followed by apply/read failure returns `saved:true` with the separate error.

Same alias in `.app.json` and bundled MCP merges in preview/UI without editing source, preserving registration/transport. `provider:openai` explicitly uses fixed hosted transport; package URL/headers/OAuth cannot leak into it. `provider:direct` uses bundled/user direct config; switching retains it. Partial connection overrides preserve unspecified options; explicit server binding replaces transport entirely and does not mix stale addresses. Duplicate MCP aliases across files remain invalid.

Top-level scopes/oauth_resource, package oauth, user oauth merge in that order after snake/camel normalization. callback_port yields `http://127.0.0.1:<port>/callback`, full callback_url wins; SDK resource validation remains. Credential identity ignores key order. Placeholder client IDs/missing secret env vars request configuration. required inherits package unless explicitly overridden; missing required binding/address reports its plugin/service rather than silently dropping it.

OAuth loopback validates state, callback and issuer. Desktop safeStorage encrypts `userData/mcp-oauth.bin`, with no plaintext fallback. Tokens/verifier never enter models, public receipts or manifests; verifier is transaction memory only. Sign-out clears CardBush local credentials, not necessarily server authorization. Preset secrets require trusted `expectedIssuer/expected_issuer`; discovered mismatch stops before disclosure. DCR clients/tokens retain SDK issuer tags, and old untagged credentials require login rather than assigning a newly discovered issuer.

Private secret entry stores encrypted content and only `clientSecretRef` in config, bound to endpoint/client ID. It overrides env reference without restart and never crosses model args/results/journals. Cancel/conflict rolls back uncommitted credential writes; sign-out keeps client config. Removing a ref does not claim historical encrypted entries or old unrelated plaintext/logs were erased.

Header helpers run the user's shell only when connection needs headers, emit bounded JSON, cache per connection and refresh once on 401/403. Explicit headers win, credentials never follow cross-origin redirects or enter OAuth server URLs. Preview never runs helpers.

Elicitation binds service/task/turn in main; navigation/remount cannot reassign it and cancel closes it. Legacy untagged protocol serializes interactive calls; modern request context permits concurrency. SDK advertises elicitation only with a real desktop bridge. States distinguish auth_required, configuration_required, unavailable and ready (handshake/catalog only, not proof of account entitlement). Optional failures do not block others; required ordinary failures preserve batch failure, auth/config requirements are recoverable without infinite reconnect.

An ordinary call's real auth rejection may prompt login, share one connection login across concurrent callers, and resume original args once after authorization. Cancellation ends waiting, second auth failure stops, unrelated errors do not replay. Settings login updates manager state; stale errors cannot overwrite new config. MCP Hooks only report auth status. Shared account management lives alongside marketplaces; per-app authorization/enablement is independent. OpenAI is integrated; other account platforms remain explicitly unavailable. See [account research](ACCOUNT_MANAGEMENT.md) and [hosted access](OPENAI_HOSTED_CONNECTOR_PROBE.en.md).

## Acquisition and rate limiting

Git/GitHub preview pins a commit and reads manifests/config, not repository ZIP. Bare/blob-filtered Git may still fetch objects if filtering is unsupported. Immutable GitHub metadata/icons cache 30 minutes, at most 64 MiB/256 LRU entries, no ZIP memory cache. Concurrent identical requests coalesce; explicit refresh bypasses ordinary read cache, network concurrency is three.

Installation streams pinned repository ZIP to disk without an entire-repository 32 MiB limit and extracts only the selected plugin. Revalidate manifest/identity/capabilities before atomic replacement. npm/local use preview staging. Report downloaded bytes and known totals; cancel preparation/download/extraction/validation, disable cancel during atomic install. Failure/cancel cleans temp data and preserves old install; retry same unexpired commit, disk errors separately.

ZIP/Git/npm share archive link resolution: internal relative symlinks and tar hardlinks materialize as ordinary files/directories with contents/executable bits, no Windows symlink privilege or plugin scripts. No live link semantics remain. Resolve only within archive indexes and the selected plugin/package boundary, not host paths. Reject absolute/escaping/dangling/cyclic/case-conflicting/device entries with paths. Bounds: 16 MiB/file, 2000 files, 64 MiB expanded, 10,000 entries, finite resolution depth/path count; copied targets count again. Validate completely before writing empty staging and check actual expanded disk demand. Local folder sources retain their own link checks; local ZIP compressed limit remains 32 MiB.

429 or rate-limited 403 ends the request without automatic retry/alternate endpoint. Valid Retry-After or x-ratelimit-reset pauses same egress/domain only; no invented exponential countdown without a server time. Proxy/PAC changes isolate prior waits and pooled HTTPS tunnels, and stale responses cannot poison the new route. Ordinary 403 is permission failure. Fixed total deadline includes routing/queue/read/at most one reset/502/503/504 retry: 15s metadata, 10min repository files. Expired queued requests never send; retries do not reset time. Immutable cache/other domains remain usable, failures are not cached as success, expiry does not auto-download. UI retains retry/proxy controls and loaded browsing.

## Automation and verification

Trusted command/MCP/HTTP Hooks may request queued work through `cardbush.activateAgent.prompt`, sharing `schedule_task`, records and stop behavior. This is separate from Claude event-review prompt/agent semantics. See [automation](AUTOMATIONS.en.md).

Use the existing suites: `test:plugin-local-install`, `test:plugin-connections`, `test:plugin-marketplaces`, `test:plugin-extensions`, `test:plugin-capabilities`, `test:mcp-integration`, `test:plugin-search-settings`; `connectionScheduling.test.mjs` tests admission/publication/cancel/stale completion, and `test-plugin-compatibility.mjs` runs with extensions. Network UI subset: `node scripts/test-plugin-connections-ui.mjs --network-only`. They cover archive attacks/rollback, actual Hook processes and local MCP, OAuth/PKCE/issuer/refresh with isolated fake credentials, Electron safeStorage/restart, UI sandbox/CSP/permissions/contexts, child-local scopes, worktrees, background results and narrow layouts. Public read-only probes use `node --use-env-proxy scripts/verify-public-plugin-mcp.mjs` when appropriate; never infer real account access from fixture success.

Historical timings, specific Linear/Gmail/OpenAI observations and unverified account flows remain in the dated sections of the Chinese source. This implements the listed modules/events, not complete replicas of both vendors' hosts. LSP, vendor-only lifecycle events, marketplace publishing and platform entitlement retain their explicit limits.
