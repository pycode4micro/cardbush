# LEM 轻量检索与学习修正

## 范围与原则

- 仍是本地经验库，不训练模型、不引入向量服务、不增加模型分类调用。
- 不添加任务分类器、领域关键词白名单/黑名单、人工“强相关”分数线。
- 不强制每轮或收尾时 consult。新提示词仅明确已有工具的使用边界。
- 不注入动态经验目录到 system/developer 前缀；工具定义不随经验库内容变化。

## 每 Turn 一次的内部助手提醒

- 仅在 Turn 首次请求模型前做一次本地 BM25 匹配；不放进 Tool loop 或网络重试循环。
- 使用本会话全部有效用户指令（包括用户引导）和此前已完成 Turn 的最终回复。读取原始持久化事实，因此多 Turn 压缩不会使较早用户要求丢失；被编辑替换的消息、工具结果、思考内容、内部摘要、提醒自身及中途/失败回复不参与匹配。
- 本 Turn 未来的最终回复会从下一 Turn 起参与匹配，不在当前 Turn 结束时另加一轮。
- 只有存在词法候选且本 Turn 开放 `consult_logic` 时，追加一条 `name=lem_consult_reminder` 的 developer 消息。没有固定时间间隔、业务关键词规则或语义分类器，也不设人工“强相关”阈值。
- 提醒只包含固定可信模板，不把用户文字、命中词、经验正文或其他外部内容提升到 developer 优先级。不自动执行 consult、展示教训、强制确认或要求 Agent 再跑一轮；Agent 可自行忽略。
- 消息先经协议 schema 规范化，再进入正常 generatedMessages 和恢复检查点，避免首次发送与持久化读取的字段顺序不同导致 cachechain digest 变化。仅尾部追加，不删除旧提醒或绕过缓存检查；压缩后不在同 Turn 补发。
- 恢复已有首轮提醒、进入后续 loop 或网络重试均不重复追加；跨 Turn 允许各有一条，并保留旧消息事实。提醒不会记成 Tool 执行或经验采用，也不参与点赞归因。
- 经验库损坏或不可读时跳过可选提醒，不中止用户任务；显式 consult 仍通过正常工具结果报告错误。
- 相同历史文本的分词/词频可以复用，但不缓存检索结果。每次仍读取最新经验库；缓存只保留最近一次匹配涉及的文本，切换会话/移除经验后不累计无关文本。

### 本地性能测量

运行 `node --expose-gc scripts/benchmark-logic-reminder.mjs`（先构建 Runtime）。合成数据、6 次采样，包含语料筛选、经验文件读取和词法匹配；不含模型、Session journal 投影和 UI。下表均包含历史最终回复：

| 历史 Turn / 经验数 | 语料字符 | 冷启动 | 缓存后中位数 | 新增用户指令 | 额外保留堆内存 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 20 / 10 | 22,646 | 5.7ms | 0.4ms | 0.8ms | 0.14MiB |
| 200 / 100 | 226,786 | 51.7ms | 1.5ms | 2.0ms | 0.85MiB |
| 1000 / 1000 | 1,134,786 | 248.0ms | 7.5ms | 10.8ms | 4.58MiB |

这是当前机器上的合成基准，不保证其他语料/设备性能。每 Turn 最多增加一条短提醒的输入 token，不增加独立模型请求。BM25 仍是词法召回：长会话、通用词及语义不同的同词可能触发提醒，不能视为“已确认相关”，也不保证模型一定采用经验。

## Consult

- 使用 ICU `Intl.Segmenter` 词级分词、Unicode NFKC 和大小写规范化；统一忽略单字符词元，不再逐个汉字计分或跨标点拼汉字。
- 使用标准 BM25，`k1=1.2`、`b=0.75`：按库中文档频率、词频饱和与文档长度计算，不使用业务词表或反馈奖励参与相关性计算。
- 默认最多返回 3 条词法候选。没有词项匹配则返回空结果。
- 分数用于同一次查询内的排序，不是概率；移除 `strong/partial` 标签。词法重合不保证语义适用，例如“确认”仍可能单独召回候选，执行中的 Agent 必须核对当前证据和适用范围。
- 去掉顶层重复的 bias/反思问题和请求参数回显；每条经验带已存的 evidence、outcome、evidence_state。验证状态是存储的声明，不是独立验证结论。
- 增加显式 `mode=list` 分页目录，使用 `next_offset` 翻页；不再用“全部记录”查询猜测目录。目录不输出 `matched_logic`，不会被记为检索采用。

## Learn 与持久化

- 首次 learning_count 从 1 开始。相同证据重复提交不会增加计数或自动提高置信度；新的证据文本可更新记录，但不会自动获得置信度加成。
- 条件数组规范化排序后计算身份；识别旧数组顺序生成的身份，并保留原 logic_id、已有反馈和计数。没有自动改写历史经验内容或修正旧计数。
- 省略的证据、结果等可选字段不再清空已有值。不存在自动语义合并或真实性分类。
- learn/feedback 使用互斥的参数分支；兼容仅提供 logic_id 与反馈值的隐式反馈；已发布的参数不再存在原先 oneOf 重叠问题。
- 工具反馈未指定 source_id 时，使用 Runtime 的 session/turn 身份去重，避免同轮重复反馈制造额外奖励。删除未实现的 background 参数。
- 替换文件失败时不先删除旧库。非法 JSON 根结构失败关闭，不用空库覆盖。无关联经验的回复反馈不写经验库。

## 反馈归因

- 回复点赞/点踩继续关联本轮涉及的经验，但记为 `scope=turn` 的反馈事实，不改变经验 confidence/reward/suppression。
- 对明确 logic_id 的评估反馈仍为 `scope=logic`，保留撤销和同 source_id 覆盖语义。
- 两类反馈分别保留有界记录，避免大量回复反馈挤掉明确经验反馈而间接改变分数。
- 旧 `user_thumb` 事件读取时解释为 Turn 反馈；原文件不因读取而改写。

## 验证

- 回归覆盖 BM25 公式、中文单字/跨标点误召回、词频与长度归一化、Unicode、多语言分词、分数与反馈解耦、目录翻页、重复/并发学习、旧身份兼容、反馈去重/撤销/保留以及非法存储保护。
- 用已有真实经验库只读复查：“窗口缩小后图片预览被遮挡”“核对财务报表中的金额合计”不再误召回 HTTP 经验；HTTP/413/连接池查询仍返回对应记录。
- 原始经验库内容未改写；未重跑历史 Turn 或请求真实模型。
- 修改会一次性改变新版静态提示词与工具定义，不承诺跨版本复用旧前缀；执行中没有额外的动态前缀替换。
