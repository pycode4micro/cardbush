# Git 工作区改造后的规模对比：2026-09-06

本轮将独立的内容 blob / JSON 清单存储替换为源仓库中的 Git 对象和恢复点 refs，并分离历史读取与实时扫描。新任务默认 Local，Worktree 显式选择；本报告规模测量使用 Worktree，以便与[旧基线](TASK_WORKSPACE_BENCHMARK_2026-09-06.md)直接对照。

## 方法与范围

- 同一机器、相同文件构造与轮次：1,000 个生成文件 × 12 轮、10,000 个生成文件 × 4 轮，另各有两个覆盖文件。包含二进制、128 KiB 文件、初始未提交修改、未跟踪文件和应排除的忽略文件。
- 每四轮修改 5 个文件为新内容、恢复原内容、再次写新内容、保持不变。真实 Git、真实生产 TaskWorkspaceManager，独立临时仓库；没有模型或远程 API 调用。
- 开始、收尾与实时审阅取中位数；实时审阅还包含创建后的首次读取。创建和最后的应用、撤回、丢弃各测一次。夹具建仓、断言、清点不计入操作时间。
- 两组基准顺序运行，期间没有同时运行构建、Chromium 或其他测试。本轮与旧基线没有清空操作系统缓存；表格是本机样本，不能作为普遍延迟保证。
- Runtime 源码、构建产物和 Git 存储源码 SHA-256 随原始数据保存。两组使用同一实现。

## 操作耗时

单位：秒；单元格为旧实现 → Git 实现。

| 覆盖文件 / 轮次 | 创建副本 | 每轮开始 | 每轮收尾 | 实时审阅 |
| --- | ---: | ---: | ---: | ---: |
| 1,002 / 12 | 19.42 → 7.32 | 1.09 → 0.72 | 1.20 → 1.21 | 1.28 → 1.15 |
| 10,002 / 4 | 245.08 → 118.07 | 9.02 → 2.40 | 9.64 → 2.76 | 8.77 → 2.70 |

千文件组的收尾约 1.2 秒，与旧版接近，不能声称所有操作都提速。Windows 上多次 Git 进程启动仍有固定成本；实时审阅仍保留全目录字节核验，并不因采用 Git 而变成常数成本。

| 覆盖文件 | 管理器重建后实时审阅 | 随后重复审阅中位数 | 应用 | 逆序撤回全部轮次 | 丢弃 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1,002 | 2.17 | 0.70 | 0.90 | 2.91 | 1.12 |
| 10,002 | 2.88 | 2.39 | 2.48 | 3.16 | 3.55 |

## 历史读取

| 覆盖文件 | 样本数 | 中位数 | 最大值 |
| --- | ---: | ---: | ---: |
| 1,002 | 12 | 1.50 ms | 4.07 ms |
| 10,002 | 4 | 0.64 ms | 1.39 ms |

这些历史读取紧接同一管理器的实时审阅，差异投影缓存已经建立，**只代表热缓存路径**。本轮没有单独测冷启动历史读取；冷读取仍需解析 Git 对象和构造差异。回归测试另验证历史读取不依赖工作副本存在，也不会执行未完成的文件恢复。

## 版本数据增长

单位：字节。新增内容一轮仅修改 5 个文件。

| 覆盖文件 | 每轮新内容 blob | 对应新 Git tree | 丢弃后新增对象原始大小 + state.json |
| --- | ---: | ---: | ---: |
| 1,002 | 10,240 | 1,195 | 75,527 |
| 10,002 | 10,240 | 4,345 | 37,234 |

旧实现每次新版本分别新增 137,228 / 1,379,228 字节的全仓库 JSON 清单。新实现复用原仓库已有 blob 和未变子树，tree 增长由发生变化的目录结构决定，无需再写一份完整清单。两种元数据编码不同，此处比较的是逻辑表示成本。

Git 数据统计为相对测试源仓库原有对象的增量、按解压后的原始对象大小加总，另加任务 state.json。它不包含对象压缩、pack/index 文件、refs 文件及文件系统分配开销；不能把这一列与旧报告的历史总大小直接相除，宣称节约了相应比例的物理磁盘空间。历史 refs 仍未自动回收。

## 正确性与验证

两组所有断言通过：初始脏文件与未跟踪内容一致、忽略文件排除、每轮差异正确、无修改轮次与已有内容复用不新增 blob/tree、重复读取不增长版本数据、应用字节完全一致且原 index 不变、全部轮次逆序撤回、丢弃仅删除任务副本。

Runtime 全量测试 310/310、协议测试 24/24 通过；工作区投影、会话/历史/客户端契约、隔离 Chromium 界面交互、前后端类型检查和产品构建通过。两个既有终端时限断言曾在并发负载下失败，单独复现及全量顺序运行通过，未修改其时限；界面夹具改为等待异步操作完全结束再点击下一按钮。

字节校验、冲突保护、磁盘中断状态恢复、旧 v1 检查点迁移、SHA-256 仓库、忽略路径回退及跨轮 Cache Chain 均有针对性回归。当前基准重建管理器，不模拟真实进程强杀或断电；没有重跑模型编码能力或 API 缓存命中率基准。

方案与能力边界见 [TASK_WORKSPACES.md](TASK_WORKSPACES.md)。本次采用 Codex 公开的 Local / Worktree 与 Git 工作区方向，不声称复刻其未公开的逐轮版本实现。
