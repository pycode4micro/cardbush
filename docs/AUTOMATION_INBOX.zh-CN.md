# 定时任务收件箱

[English](AUTOMATION_INBOX.md) · [简体中文](AUTOMATION_INBOX.zh-CN.md)

CardBush 现有 Runtime 调度器同时管理计划和执行结果；所在宿主必须运行。没有第二套调度服务，错过的多个时间间隔在恢复时合并执行一次。

## 结果与已读

每次运行都有稳定的 run ID、turn ID 和执行会话 ID。终态结果初始均为未读，包括失败、中断和权限阻塞。打开结果、用 `scheduled_results` 查询、继续对话都不自动标记已读。用户可单条切换已读/未读，或批量确认当前显示的结果。

已读命令指定准确 run ID，先验证整批，只更新 `readAt`，不改变计划、执行状态、下次时间或计划编辑修订号。新到结果不会被进行中的批次误包含。每计划最多保留 50 条已确认历史；该上限不清理未确认结果。

结果页提供未读、今天、全部视图并按本地日期分组，计划管理独立显示，侧栏展示未读数。原有计划控件和对话创建保留。

## 执行会话

时间计划在独立临时会话执行。创建或明确保存计划时，模型、工具白名单、生成选项、工作区和权限快照写入调度器私有 `jobContexts`；普通来源 turn 不改变它。不会复制来源聊天历史或响应链，因此计划提示必须包含完整任务要求。删除来源不影响定时器及保存配置，仍能编辑、运行、暂停、恢复；只有会话存储确认来源仍存在，才提供返回入口。

临时执行的普通会话日志持久保存，`hidden: true` 使它不进入最近列表，完成后不删除。打开结果检查器仍隐藏；明确打开完整执行会话才把同一会话加入最近列表。检查器和计划详情分别保留来源入口。删除会话需确认并说明对定时任务的影响。

旧时间计划将未来运行迁移到独立会话，并一次性保存最近的来源配置。已完成/运行中的身份、未读和手动暂停状态不变；中断任务暂停，不自动重放。旧配置缺失明确失败，不能从聊天语义猜测。旧提示不重写，依赖先前讨论的要求需自行补全。事件计划和可信插件唤醒依赖来源事件，删除来源会暂停并取消排队唤醒；事件计划也可选择独立执行会话。

检查器用共享消息渲染器展示真实执行会话。追问走普通 Runtime turn，使用保存的模型、工作区、权限和工具限制。关闭或隐藏不取消追问，重新打开观察同一 turn；停止必须明确点击。会话缺失不能由检查器悄悄重建。

## 上下文提醒

准备真实用户 turn 前读取最新未读快照，写入用户消息元数据，使 UI 能展示发送时附带的事实。模型输入中，在用户正文后追加简洁内部 user 消息：总未读数以及最多 8 个近期标题、状态、时间和稳定 ID。`scheduled_results` 默认分页浏览简要结果，用 `next_offset` 继续；指定 `run_ids` 才读完整保存结果，两者均不确认已读。`schedule_task` 列表也默认简要回执，编辑时通过 `action: "get", job_id` 取配置。

提醒注明 `asOf` 观察时间，标题和结果属于数据，不是新指令；不修改用户原文。已发送的确切内部消息和其他输入一样写入日志及恢复检查点，UI 隐藏内部正文，可在原用户消息上显示附件标记。定时唤醒、子任务及目标续跑保留已有观察，不增加新提醒。

运行中用户引导也附最新快照。状态变化追加在引导后，收件箱清空时也追加零计数，不过滤或替换旧消息。仅 `asOf` 变动不重复注入。去重对比当前模型上下文中最新的真实提醒；压缩移除后，可重新追加非空快照。调度器仍是收件箱唯一状态源，日志只记录已发送内容，不另建提醒状态库。

## 请求连续性与缓存诊断

自动化启动沿用来源工具顺序，同时从权威注册表刷新定义及可用性。触发信息以保存的 run ID 和激活时间提交为 turn 输入，不插入 system/developer 前缀；重试和恢复复用原观察。保存上下文使用协议共享生成选项（含 `temperature/topP`），不持久化临时响应链或输入消息。

缓存诊断将前缀变化与参数变化分开。`frozenPrefixBreak`、`breakIndex` 及兼容别名 `messageBreakIndex` 只表示消息/输入项改写或截断；`parametersChanged/changedParameters` 单独说明输出预算、温度、绑定或顶层工具变化，同时发生时保留两类信号。Provider 格式切换设置 `projectionFormatChanged`，建立新基线前不比较前缀。实际压缩与历史 schema 重写仍是可观察的消息断链。旧日志不回填，读取器利用其独立前缀计数，不把旧的合并标记误当消息断链。

## 验证

`npm run test:automations` 覆盖调度、迁移、持久化、已读竞态、未读保留、真实 Electron worker 执行/追问、结果 UI 和关闭重连；还使用非空工具目录及显式生成选项，对比普通/自动/重复 turn、未读变化、引导及恢复时的完整 Provider 输入。UI 测试使用隔离临时配置和测试模型，不执行用户真实计划。
