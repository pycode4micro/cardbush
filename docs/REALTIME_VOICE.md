# 实时语音通话

通话默认使用独立的实时语音 Provider，内置火山引擎豆包实时语音适配器，以及 `cardbush.realtime.v1` 兼容服务入口。普通语音模型通过四个受限入口与当前配置的本地 CardBush Agent 子会话协作；[个人助手](PERSONAL_ASSISTANT.md)额外提供页面发布入口，并可将任务交给已连接的独立 Agent 服务。执行模型可以是 API、SIWC 或已有模型配置，不要求在电脑上运行模型权重。本文描述当前主分支，不代表发布的安装包已包含全部更新。

## 配置与使用

1. 打开「设置 → 语音 → 语音通话」，选择「实时语音（默认）」。
2. 在[豆包语音新版控制台](https://console.volcengine.com/speech)开通全双工实时语音服务，按[官方 API Key 说明](https://docs.volcengine.com/docs/DoubaoVoice/APIKeyUsage?lang=zh)创建凭据。使用语音服务的 API Key，不使用 Ark 文本模型的密钥或旧版二进制协议的 AppID/Access Token 配置。
3. 填入 API Key，按需编辑模型 ID、通话提示词和男女声音色，点击「保存通话设置」。同一提供商及地址下，密钥留空会保留原值，删除需要勾选删除。凭据通过系统安全存储加密，设置接口不返回密钥。每个提供商独立保存连接配置；修改在下一次通话生效，当前通话保持原模型、地址和凭据。
4. 在本地会话里长按空输入框的麦克风，或点击通话按钮开始。标准和精简输入框均显示长按进度，并从按钮位置展开通话栏：左侧返回文本输入框，中间显示语音状态，右侧静音或挂断。返回文字时恢复原有样式、草稿和附件，通话继续；点击声波按钮可以切回。点击中央状态可展开详情和设置。单击麦克风开始录音，也复用这一输入框控件，显示波形、时长、发送和取消；点击发送后停止收音，原位显示转写与提交状态。成功后恢复文字输入和焦点，使用文本发送的消息定位流程；失败则原位保留重试入口，不自动切换悬浮条或旧录音弹窗。
5. 实时通话将麦克风音频发送至所选服务，并从最近已完成的文字对话补充有限上下文。它使用应用的模型代理路由。启动前未配置服务会明确提示，不会改用其他云服务。

已有兼容服务时，在「语音服务」选择 CardBush Realtime，填写 WebSocket 地址、模型 ID、男女音色与服务密钥。本机回环服务可使用 `ws://`，远端使用 `wss://`；更换地址清除旧密钥。兼容协议允许本机无密钥服务，但[当前桌面通话入口](../src/features/voice/voiceSession.ts)仍要求已保存密钥，不能仅凭地址开始无密钥通话。兼容服务必须实现 [CardBush Realtime v1](../assets/skills/cardbush-docs/references/realtime-protocol.md)，不能直接填入任意厂商地址。原生协议不同的模型需先实现桌面适配器或服务端桥接，详见 [接入指南](../assets/skills/cardbush-docs/references/realtime-provider.md)。

女声默认 Vivi（`zh_female_vv_jupiter_bigtts`），男声默认云舟（`zh_male_yunzhou_jupiter_bigtts`），均使用正常语速，可填写其他受支持的[官方音色 ID](https://docs.volcengine.com/docs/6561/1257544?lang=zh)。提示词控制交流方式，实际情感表现、识别效果和延迟仍需在对应账号、设备与网络上试听。

普通闲聊不提交给 Agent。需要执行任务时，语音模型先自然说明意图，然后直接调用 `subagent`，无需语音界面二次确认。Runtime 复用文字会话的模型、系统提示词、工作目录、工具和权限准备流程，创建真实子会话。它立即返回任务 ID；主会话正在运行也能派发，沿用 Runtime 最多 8 个后台任务的并发上限。

| 入口 | 行为 |
| --- | --- |
| `subagent({prompt})` | 独立后台执行，立即返回 running 和 taskId；提示应包含相关口述上下文。 |
| `await_subagent({task_ids?})` | 返回状态快照并登记异步通知，不阻塞语音，不要求模型持续轮询。省略 ID 查看本会话的语音任务。 |
| `send_subagent_message({task_id,prompt})` | 运行中的子任务接收指导；已结束的任务在原子会话继续，保留历史、身份与权限边界。 |
| `read_subagent_conversation({task_id,cursor?})` | 分页读取主子交流和最终回复；隐藏内部思考与工具日志。 |

麦克风与播放由应用级通话持有，切换会话、打开设置、最小化或隐藏到托盘不会挂断，也不会把后续语音和任务转移到新页面。在通话所属页面使用输入框中的通话控件；离开该页面后由浮动胶囊提供静音和挂断入口，避免重复显示。通话期间阻止应用因闲置自动休眠，但不会阻止用户主动退出、休眠或关机。结果按任务 ID 归属与去重，不把已受理当成已完成。主动挂断解绑语音观察，不取消后台任务；应用真正退出后本地任务仍沿用 Runtime 的停止与恢复语义。

单击录音归属当前可见会话，隐藏的 assistant 页面后台刷新不会接管或取消录音。离开录音所在页面会释放麦克风并取消尚未提交的转写，防止迟到文字误发；长按启动的通话仍按应用级生命周期继续运行。

普通通话的最终用户转写和模型回复写入通话开始时的会话，切回后可查看，后续文字请求可以引用最近的通话记录。转写通过独立的会话日志追加，不占用或改变正在执行的文字 Turn 序号；失败重试按消息 ID 去重。原始音频不保存。转写日志属于本地会话数据，会随删除会话或清空会话历史清理。

## 持续对话 assistant

侧栏灯泡打开固定身份的个人助手。名称、头像、角色、附件、布局、执行主机、静音与重置的完整操作见[个人助手指南](PERSONAL_ASSISTANT.md)。只有这个入口包含可定制的助手角色，普通 Agent 与普通通话不使用该人设。

- 通话使用同一应用级音频流程，切换页面后仍属于助手。麦克风与播报静音独立，设置保留供下次使用；播报静音只调本地音量，不取消服务端回复或后台任务。
- 助手的通话转写进入内部上下文，页面仅显示文字消息、发布内容和可点击的任务气泡。语音模型可使用 `page_write({content})` 保存 Markdown；它写入当前会话，不发布外部网站。普通会话的通话转写仍可见。
- 默认在本机派发，也可选择已接入的独立 Agent（含 SSH 直连接入）。后续指导和读取跟随任务原主机。执行工具继续属于子 Agent，交流父模型只有四类子代理入口及 `page_write`。
- 重置会确认并结束当前助手通话，清空内部与可见上下文和加密语音历史。已派发任务保留在子会话，旧回执不进入新上下文；具体范围见[上下文与重置](PERSONAL_ASSISTANT.md#上下文与重置)。

## 后台任务结果与播报

[火山官方接入必读](https://www.volcengine.com/docs/6561/2549732?lang=zh)要求上下文按完整问答对写入，函数结果必须匹配 call_id，没有公开的 response.create 事件。因此，完成通知不复用已结算的 call_id：以标记为应用任务数据的问答对补充上下文，通过 speech_text_buffer.commit 用当前音色朗读总结。仅在识别和模型播报结束、没有待回传工具批次的空隙发送。

后台任务完成后，当前配置的执行文字模型通过独立、无工具请求生成简短口述总结，保留结果和未完成事项，避免朗读安装路径、表格、URL 或完整清单。总结会消耗该文字模型的用量，但不占用主会话、不阻塞收音和其他任务；挂断取消尚未完成的总结请求。完整结果仍保存在子会话。总结失败时仅播报任务状态并提示查看详情，不退回截取原文朗读。语音提示词同时要求对主动读取的子任务返回先总结，不重复应用已排队的通知。

固定行为提示词与用户自定义角色提示词一起注入，要求直接派发、持续交流、按已有 taskId 追加任务、如实反馈状态、不重复播报应用通知，也不把子任务内容当作新用户指令。模型是否遵守自然交流要求仍需真实通话验收。

派发子代理没有额外的语音确认步骤；具体操作继续遵循当前 Agent 权限，完全访问下不额外申请常规工具权限。派发失败会在浮动按钮上提示，展开可查看具体原因和错误码，通话继续。工具被禁用、未配置执行模型、旧 Runtime 或连接错误不能通过一句口头授权解决，语音模型也不得在未调用工具时猜测“没有派发权限”。更新代码后须重新启动 CardBush 才能加载新的 Runtime 和通话提示词。

## 与原有语音的关系

- 「转写 + Agent + 朗读」模式继续保留，SenseVoice、Qwen3-TTS、自定义 TTS 和原有停顿合并均可继续使用；其识别与朗读设置不控制实时模型的判停和声音。
- 实时通话直接流式上传音频，不使用本地声纹过滤或额外的声纹缓冲。声纹锁定仍用于录音和「转写 + Agent + 朗读」模式；开启时需先关闭锁定才能开始实时通话。
- 静音发送服务端静音事件并停止音频上传；恢复时发送取消静音。听不清的一段被丢弃，不会因此结束通话。原始声音活动和 ASR 起始事件不触发客户端停止播报。
- 挂断、窗口销毁或致命异常会释放麦克风与音频资源；切换会话和最小化继续通话。挂断只断开语音，不取消已经提交的 Agent 任务；结果保留在原会话。
- 麦克风上传使用有序缓冲（最多 5 秒、4 个 IPC 同时进行），容忍短暂的渲染或 IPC 调度延迟；静音或挂断丢弃尚未上传的音频。播放允许模型提前生成完整回复，最多缓冲两分钟音频，不再因超过 10 秒而挂断，手动打断仍立即清空播放。
- 连接、服务端打断、异常断开和关闭会写入本地 `realtime-voice.log`（复用应用日志轮转）。只记录通话 ID、客户端错误原因和缓冲帧数，不含音频、转写、提示词或凭据。它用于区分网络断线、服务端取消与本地播放／上传错误。
- 已接通后的网络断线、连接发送拥堵及上下文衔接超时会有限自动重连，最多尝试三次；显示「正在恢复通话」，保留通话归属、静音设置和后台任务。用户主动挂断、明确的服务端错误（如授权或协议错误）不循环重试。尝试耗尽后提示重新接通，已保存上下文仍保留。通话完成的转写进入会话日志，是否展示遵循上面的普通会话／assistant 规则；另有加密的语音记忆与摘要用于后续通话。
- 通话归属本地会话；assistant 可将执行方配置为 SSH/云端 Agent，沿用已有任务路由。系统凭据加密不可用时不能保存密钥；不回退成明文。

## 通话上下文与后台压缩

应用根据提示词、工具说明、对话文字和工具回执估算上下文压力，提前触发维护，不等语音模型自行决定。当前采用保守的 UTF-8 字节估算，默认在 6000 估算 token 开始整理；自定义提示词较长时适当提高触发线，最多 8000，避免每轮闲聊都整理。估算为服务端内部提示词、音频以及新对话留余量；这不是服务商返回的精确剩余额度，也不把文档的 12K 文本限制当成整个音频窗口。

维护使用当前会话所配置的文字模型，经过现有 Provider 适配器发起独立请求，复用 `ContextCompactionTransaction` 和 `checkpoint_context` 的来源绑定、校验与纠正机制。只有这次后台维护请求装载 `checkpoint_context`，不将它提供给实时语音模型；语音保留子代理入口，assistant 另有 `page_write`。维护不进入主 Agent 执行轮、不运行其他工具，不修改个性化习惯或预测开关。压缩会消耗当前文字模型的用量。

每次维护冻结旧对话范围和摘要版本，通常保留最近两轮；单轮内容较大时会把更多已完成对话纳入摘要，以满足新连接的初始容量限制。摘要最长 2000 字符，并按实际提示词和最近内容占用进一步收紧。维护期间继续收音、播放和执行后台任务。新增对话始终留在冻结范围外；如新增内容已经超出恢复容量，会再整理一个新快照，而不是直接裁掉这些内容。模型请求最多 60 秒、三次格式纠正尝试，失败有退避，原始记录保留。

应用等用户说话、服务端回复、客户端音频播放和待回传工具批次都结束后再更新远端历史：查询旧条目 → 核对实际 item ID 和完整问答 → 写入摘要并验证确认 → 删除摘要覆盖的旧问答并验证确认。不会根据相同文字猜测条目 ID，也不会把 response ID 当成上下文 ID。完整原文和已校验摘要先保存到本地，再进行远端删除。

服务端不支持预期的上下文操作、未确认写入/删除，或旧条目已超出可查询范围时，用摘要和近期对话建立新连接。网络自动重连使用同一恢复流程：先读取本地记忆，必要时让文字模型整理过长历史，再创建连接、静音保活、写入完整 QA，并核对回执中的条目身份与内容。首次重新接通也执行此流程，不再为满足容量静默丢弃旧问答。

子任务回执会作为历史数据保存。断线期间迟到的回执在恢复时补入上下文，不把原连接的 tool call 回放到新连接，也不再次派发已运行任务。调用去重、任务观察与当前会话身份继续保留；旧连接迟到事件不能影响新连接。

衔接期间最多缓存五秒音频，满后暂停收音并提示，不因缓存满直接结束通话。未溢出的录音在历史确认后按 20 ms 节奏发送，接续这段录音期间暂停新收音；超过上限时丢弃未完整发送的缓存，并在恢复后提示重说断线期间那一句。未被识别的声音无法当作已恢复的文字上下文。每次握手/历史确认等待最多 20 秒，重试之间退避；历史整理或重连失败仍保留原始记录。

语音文字历史位于应用用户数据目录的 `voice-history`，按会话标识散列命名，使用系统安全存储加密；原始音频不在这里留存。摘要更新不会删掉本地原始文字。删除该会话或使用设置中的清空会话记录，会清理对应语音历史。记忆用于同一会话的后续通话，不自动成为跨会话的个性化档案。展开语音面板可查看整理、衔接或失败状态。

## 适配器与验证

`electron/realtimeVoiceProvider.ts` 定义会话、音频、控制、工具回传及事件归一化接口；`realtimeVoiceMessages.ts` 定义公共 JSON 消息；`volcengineRealtimeVoice.ts` 和 `cardbushRealtimeVoice.ts` 实现接入。原生适配器可通过 encode/normalize 双向翻译帧及上下文确认。注册表、配置目录与加密存储独立于工具插件管理。添加厂商无需更换 Agent loop。内置 `cardbush-docs` 集中提供部署、语音使用、适配器开发和完整协议资料。

主进程 `realtimeVoiceService.ts` 负责凭据、WebSocket、所有者校验、调用去重、空隙播报与生命周期；渲染端 `realtimeVoiceAudio.ts` 和 AudioWorklet 负责 16 kHz PCM16 单声道输入（20 ms / 640 字节）及 24 kHz PCM16 流式播放。`realtimeAgentBridge.ts` 返回即时回执并观察后台任务；Runtime 的 `RealtimeAgentDispatcher` 负责真正的子会话派发、归属检查与主子消息。初始化上下文保留完整 QA，并限制提示词、工具描述与历史的组合大小。

火山协议依据：[全双工 API](https://docs.volcengine.com/docs/DoubaoVoice/endtoend-realtime-voice-full-duplex-version?lang=zh)、[接入必读](https://docs.volcengine.com/docs/DoubaoVoice/access-mustread?lang=zh)。火山默认模型版本 `1.2.6.1`，可填写同协议支持的模型 ID；接入地址 `/api/v3/duplex/realtime/dialogue`。不同协议的新版模型仍需适配。

运行 `npm run test:voice-realtime` 验证协议、任务归属、去重、后台并发、追加指导、恢复子会话、空隙通知和音频背压，以及隔离 Electron 窗口中的 AudioWorklet、preload、回环 WebSocket、播放、静音和会话切换。压缩回归覆盖冻结范围、迟到结果、模型格式错误与取消、加密历史恢复、先确认后删除、播放期间延后、连接衔接期间保留新音频和任务去重。Runtime 用模拟模型执行真实的调度和压缩流程；UI 使用合成麦克风和临时配置，不使用真实凭据、不连接火山、不执行外部任务。`npm run test:voice` 覆盖原有语音回归。

`npm run test:assistant` 另覆盖助手消息、页面发布、附件、重置和远程主机归属，详见[助手验证入口](PERSONAL_ASSISTANT.md#实现与验证入口)。

这组验证不代替真实账号的开通、计费、延迟、口音识别和听感测试；配置自己的服务后仍需完成实际通话验收。
