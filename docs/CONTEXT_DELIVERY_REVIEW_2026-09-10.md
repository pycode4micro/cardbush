# 上下文与文件交付优化验收报告

日期：2026-09-10。

**审查结论：这轮克制方案已完成，历史结构回放与离线回归通过。建议下一步进行小规模真实 API 验收，暂不扩大架构。** 当前证据支持交付链路的确定性修复；是否减少模型绕路、提高任务成功率和服务端缓存命中，需要真实运行验证。

本轮没有调用真实模型或第三方应用 API，没有执行历史记录中的命令，没有更改原会话日志或重启用户的 CardBush。测试使用模拟 Provider、内存 MCP 传输、回环 HTTP 服务和独立临时目录。仓库原有未提交改动保留，本轮未提交或推送 Git。

## 实施范围

| 环节 | 修改与解决的问题 | 保留的边界 |
| --- | --- | --- |
| 附件输入 | 图片进入视觉输入时，在当轮上下文同步给出有序的原始来源；本地路径、UNC 路径可直接定位。内联图片明确没有本地路径，不把 Base64 填入文字。 | 每轮最多 4 张，与现有视觉输入限制一致；附件来源不进入稳定系统提示词。 |
| 文件备忘录 | 新增 `remember_file` 与 `read_file_memos`。限制为文件路径、一句用途、最多 3 条重点；工具返回可直接复制的 Markdown 引用。 | 模型决定是否记录；不自动登记所有文件，不注入检索提醒，不保存对话摘要或执行流水。 |
| 工具发现 | 先保留精简命中目录，完整定义按容量交付；未交付定义明确列出，支持精确名称优先、单工具加载与分页。 | 只有在模型实际上下文中完整出现且版本匹配的定义才算已加载。原生 `tool_search` 与普通 `mcp_search` 使用同一份交付事实。 |
| 压缩与历史 | 活跃轮、已提交轮和重启恢复使用一致的检查点表示。通用续跑规则进入稳定的主 Agent/子 Agent 指令。 | 新检查点标记 `stable_v1`；旧检查点保留已发送的续跑消息，避免收尾删除。真正压缩仍可重建上下文。 |
| MCP 返回 | 普通返回保持原样；SDK 校验失败时保留原始 `rawResult`，并单独说明客户端解析错误。撤销之前补齐 `result` 外层的行为。 | 不将 `null` 改为 `{}`，不制造成功结果，不因解析失败自动重试工具。授权、网络和协议错误继续区分。 |
| 前端交付 | Markdown 链接和图片引用解析到现有文件预览。图片、音频和视频可以直接展示；文件变化、缺失、解码错误有明确退路。 | 沿用现有检查器与右键菜单；不增加内嵌 HTML/BI 系统，不要求旧附件和原生 MCP 媒体迁移到备忘录。 |

备忘录用途最多 120 字符，每条重点最多 160 字符；额外字段、换行、超长内容会被拒绝。读取按文件 ID 或每页最多 10 条进行。

## 事实归属与持久化

备忘录的路径、文件名、大小、修改时间由宿主读取；用途与重点明确属于**模型备注**，不标记为宿主验证过的结论。

引用形如 `cardbush-memo:<session>/<turn>/<tool-call>`，定位已有工具执行日志中的一条记录。相同文件可以更新备注，每次引用固定指向当时的记录；前端和模型读取都复用这份日志，没有另外建立附件数据库或执行历史查询系统。

引用固定的是备注记录，**不是文件字节快照**。界面打开时检查当前文件，发现大小或修改时间不同会标注“文件已变化”；文件消失则提示不可访问。同大小且修改时间被恢复的改动不能据此检出，文件迁移后也不会自动猜测新位置。

重点覆盖了：

- 144 组工具数量、定义长度和上下文容量组合；定义完整或未加载，不产生半截 Schema。
- 工具描述抢占搜索结果、精确名称与描述关键词冲突、分页、压缩后定义退出上下文。

初次完整回归中，部分旧测试把“执行搜索”视为“模型已收到定义”，或依赖后来会被删除的续跑消息。本轮改为模拟真实交付、检查点边界和持久化配置后重新运行全套，没有通过放宽执行校验保留旧行为。

Vite 仍有部分分块大于 500 kB 的提示，构建成功；本轮未扩展到打包体积优化。界面测试验证组件行为和路由，不等同于所有文件格式的视觉验收。

## 下一步审查

**建议进入真实 API 验收。** 继续增加宿主策略，目前缺少收益证据；剩余不确定性主要在真实服务返回和模型使用工具的选择上。

建议用隔离测试会话做三组小样本：

1. **附件 → 文件备注 → 交付引用**：使用同一张本地/UNC 图片，观察模型能否直接使用来源、是否在需要时记录重点，最终引用能否打开正确文件。不给它额外的本地检索提醒。
2. **工具发现 → 单工具加载 → 只读调用**：确认真实 Seedream 定义能够加载，再用 Canva 已授权的只读工具验证返回。先验证发现和读取，不把图像生成费用或应用写操作混入基础验收。
3. **压缩 → 完成 → 下一轮 → 恢复**：用可控测试窗口触发一次压缩，比较发出的真实请求前缀和缓存统计，验证没有重复执行已完成工具，也没有因收尾删消息而再次断开前缀。

验收时分开记录宿主错误、服务端错误与模型决策。模型未主动使用备忘录不能直接归为宿主故障；服务端返回非法结构也不能因收到部分内容就宣布成功。应先依据原始请求/返回定位，再决定是否值得继续优化。

单次完整定义默认上限为 128,000 字符，并仍受当轮上下文容量约束；超限会明确保持未加载。自定义备忘录 URI 在 CardBush 内可解析，导出到其他客户端的可移植转换未包含在这轮。MCP Apps 对非法结构的交互 UI 仍可能无法正常显示，原始返回兜底不意味着所有第三方协议错误都已被修复。

此外，[独立连接验证说明](OPENAI_HOSTED_CONNECTOR_PROBE.md) 已更新：过去通过补齐返回外层获得的 Gmail 验证结果属于旧实现，不能充当当前“不改写返回”实现的真实 API 验收证据。
