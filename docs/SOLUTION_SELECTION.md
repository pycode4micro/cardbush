# Solution Selection

`solution_selection` 是受限的方案提供工具。Agent 应先查阅现有上下文、使用可用工具并自行判断；只有重要方向或必要信息仍无法确定，且自行选择可能造成明显错误时才使用。不能用于日常偏好调查、教学提问、进度汇报、权限申请或重复确认已经授权的工作。

输入只有 `prompt` 与 `options`：一项实际待定方向，1–3 个互不重复的纯文字方案。提示和每个方案最多 15 个 Unicode 字符，不截断用户需要判断的内容。推荐可以写进方案文字，例如 `保留现有数据（推荐）`；没有推荐标记字段，也不注入“其他”选项。界面始终提供额外的自由输入。

卡片替换所属会话的普通输入框，点击方案直接提交，也可以填写自己的方案。没有默认选择或计时提交。切换会话不取消请求；原来的会话草稿和未提交方案仍保留。关闭卡片返回明确的取消结果，不能解释成选择默认方案或获得授权。停止任务会取消等待。

运行时持有待处理请求，通过 `runtime.list_solution_selections` 恢复仍在运行的等待。回复通过 `runtime.answer_solution_selection` 校验请求 ID、会话 ID、回合 ID 和选项范围。关闭/重新打开视图与重连不会重新执行工具；应用进程退出仍遵循既有任务中断与恢复机制。用户的选择或自由输入作为工具结果写入真实对话记录。

每个会话最多一个待决方案请求。完整权限模式也必须等待真实回复。子 Agent 保持工具声明不变，在实际调用时拒绝；它应将未解决的依赖报告给主 Agent。

验证：`npm run test:solution-selection` 包含运行时与真实模型工具循环、前端 IPC 回复链路、会话输入框替换和深浅色界面测试。所有测试使用隔离数据，不调用真实模型或修改个人任务。
