# 渲染资源与运行中的窗口

[English](RENDERER_ASSET_LIFECYCLE.md) · [简体中文](RENDERER_ASSET_LIFECYCLE.zh-CN.md)

运行中的窗口保留打开时构建版本的 JavaScript 模块 URL。稍后进入审查、源码预览、Markdown 或设置时，可能才首次请求某个分块。此时删除旧的哈希分块，即使新版存在相同组件，也会破坏旧窗口的请求。

因此，本地 Vite 构建使用 `emptyOutDir: false`：更新入口文档，保留旧的内容寻址资源。应用运行期间不要清空 `dist/assets`。目前保留全部旧资源，没有自动垃圾回收。发布包应来自全新的构建目录／检出，避免包含开发历史。

可选 React 模块使用 `recoverableLazy`。局部边界处理加载失败、记录诊断并保留外围工作区。Diff 回退保留源码、增删和行号；源码与 Markdown 回退保持文档可读；设置等面板显示局部不可用状态。无关渲染异常仍交给所属错误边界。

Chromium 可能在文档整个生命周期缓存失败的原生模块 URL，仅重建 `React.lazy` 无法可靠清除。语法／Markdown 回退因此保持可用，不提供误导性的装饰重试，也不自动重载进行中的会话。普通面板重试会创建新的 lazy 组件并清除应用层拒绝的 Promise，但不能承诺恢复 Chromium 缓存失败的 URL。之后新打开的窗口可以正常使用可用资源。

将来实现在线更新时，应保持同一生命周期：

1. 将完整版本下载并校验到独立暂存／版本目录。
2. 所有引用资源到齐后才发布新入口／版本指针；旧窗口继续绑定旧版本。
3. 使用旧版本的全部窗口关闭后才能回收它。下载和准备更新不得强制重载运行中的会话。
4. 继续保留针对下载中断、安装损坏和资源缺失的局部回退；仅保留文件并不足够。

这项改动没有实现在线更新安装流程。现有 NSIS 打包与上述本地构建策略是不同事项。

`npm run test:deferred-modules` 在隔离 Electron 窗口持续运行时构建两次，检查全部旧 JavaScript 分块字节不变；再实际拒绝审查／源码／Markdown 模块请求，验证基本预览、草稿与工作区保留、新文档恢复和局部面板重试。构建及浏览器配置均隔离在 `tmp`。
