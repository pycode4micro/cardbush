# 远程子 Agent 提问回传修复

## 根因与范围

NAS 网关原来的远程委派长连接只传心跳和最终结果；子 Agent 的 `ask_parent` 等待保存在 53 的 Runtime 中，网页原来只查询父 Runtime。因此父任务持续运行，但网页看不到远端的问题。

NAS 旧版提问协议还限制题目最多 15 个字符、至少一个预设选项，不能接收 53 的长题目、自由文本或多问题表单。此次在网关边界兼容新版提问，不升级已发布的 Runtime 协议，也不改模型契约、审批、插件、文件互传或飞书策略。

## 实现

- 独立的 `GET /sessions/:sessionId/solutions` 合并本地和远端待答问题。网页每 5 秒读取这个小接口，后台页面暂停，返回前台立即检查；不刷新整段历史、不等待父模型产生新消息。
- 远端问题从真实 `chat.jobs` 和 `runtime.list_solution_selections` 恢复，按账号、会话、连接和任务归属过滤。公开的问题 ID 是绑定这些身份的 HMAC，重连和网关重建后保持稳定。
- 回答重新查询远端的待答状态及连接授权，再将选择、文本、多题答案或取消原样送到原来的 `selectionId/sessionId/turnId`。不创建第二个等待、不向父模型追加伪造的用户消息、不重新提交任务。
- 并发重复回答合并；冲突回答、其他账号/会话、已结束问题、撤销授权及身份改变均拒绝。传输失败不自动重试答案，也不推断用户批准。
- 获取问题失败时保留已有卡片并显示连接提示，恢复连接后重新读取。切换会话取消旧读取，避免迟到响应覆盖当前会话。

主分支复用共享协议与现有 `SolutionSelectionCard`。NAS 的有限回移包含独立的协议边界兼容文件、同一新版提问卡片及所需语言键；这是旧发行的兼容层，不是另一个 Runtime。
