# NAS 会话服务稳定性修复（2026-11-09）

## 已确认的问题

- Web 网关在 512 MiB 容器内读取、克隆和序列化大段带图历史，曾三次发生 JavaScript 堆内存耗尽。
- 旧版 `agent.lock` 只记录 PID。容器重启后复用相同 PID，会把上次异常退出留下的锁误认为仍有进程持有；受影响账号曾连续重启 21 次。
- 旧启动检查最多执行 35 次、每次等待 30 秒；网页断线后仍显示“思考中”，无法反映实际连接状态。

## 实现

- Agent 使用持续存在的内核锁 inode、进程身份元数据以及原子发布的兼容 PID 文件。异常退出释放内核所有权；仍在运行的其他实例保持排他访问。获取所有权后才读取状态。
- 启动、健康检查及初始化共享 60 秒截止时间，单次探测 2.5 秒。新建会话容器最多重启 3 次，连续失败有短暂冷却和明确错误码。
- Runtime 按页提供展示历史，过滤模型私有重放信息，保留原始日志与模型输入；图片保留文件预览引用。限制页大小、读并发和缓存占用。网关容器调整为 1 GiB，Node 堆设为 640 MiB。
- 网页区分准备、重连和失败；断线停止假的运行提示，恢复时从原任务事件游标继续读取。发送收据保存在账号及会话隔离的缓存中，未知结果的相同提交重试复用请求 ID，不自动重放有副作用的任务。
- 镜像显式提供 `flock` 依赖，并保证去除全部 Linux capabilities 的 broker 用户可以读取发行代码；不放宽配置、数据或 Docker socket 权限。
