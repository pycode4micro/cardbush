# 招财网站：仅远程子 Agent

管理中心 → **远程 Agent** 可注册、检测、编辑、停用和删除独立 CardBush Agent 服务。此入口不会创建进程、容器或本地 Agent，也不会自动装配角色、同步模型配置或插件。远程服务必须已由管理员独立部署。

## 1. 启动远程服务

在远程机器已构建的 CardBush 仓库根目录运行（Node.js 22.12+）：

```sh
node dist-electron/agentServiceCli.mjs --data-dir /srv/cardbush/agent-employee-a --name 商品资料助手 --host 0.0.0.0 --port 4780
```

Windows 可将数据目录换成 `D:\CardBushAgents\employee-a`。每名人员使用独立实例、独立数据目录；采用容器时必须分别使用独立卷，并只挂载该人员可访问的文件。不要使用桌面主配置目录，也不要把其他人员的目录挂进实例。

也可使用 `deploy/agent/compose.yaml` 部署原生独立服务。默认 Compose 只监听宿主回环地址；网站从 NAS 访问它时，需要管理员配置可达的 HTTPS 反向代理，或只对受信任内网开放 HTTP 端口。

通过 CardBush 原有 Agent 连接管理界面接入此服务，并为远程服务配置默认模型、必要的工具和指令。网站不会为远程服务自动安装插件或复制凭据。不要使用 `--disable-tools` 或 `--web-restricted`：前者不提供委派，后者是网站内部租户入口，不能作为外部服务注册。

首次运行后，访问令牌保存在该实例数据目录的 `access-token` 文件；也可由部署环境提供 `CARDBUSH_AGENT_TOKEN`。

## 2. 在网站注册

1. 管理员登录招财网站，打开 **管理中心 → 远程 Agent → 注册远程 Agent**。
2. 填名称、能力说明、远程服务地址、访问令牌。例如 `http://192.168.1.20:4780/` 或 `https://agent.example.com/`。填服务根地址即可，也兼容末尾 `/api/agent/v1`。
3. 选择授权人员并勾选启用。首次授权会绑定远程实例身份与该人员。
4. 点击 **检测连接**；成功后点击 **验证并保存**。服务器会验证访问令牌、CardBush 协议、委派能力及固定实例身份。
5. 让该人员在对话中说：“请让商品资料助手处理……”。招财通过 `list_subagent_options` 发现已授权目标，再用 `subagent` 异步委派、`await_subagents` 等待，或通过 `task_id` 继续原任务。

远程地址必须能从 NAS 访问。公网必须使用 HTTPS，内网可使用 HTTP。禁止本机回环地址、链路本地地址、命令、stdio、SSH 配置及 URL 内嵌凭据；不会自动启动服务或建立隧道。

## 权限与执行

- 只有管理员可修改注册信息；访问令牌在数据库中加密，页面、普通账号和模型均无法读取。
- 每个远程实例仅绑定一名人员，避免不同账号复用远程工作区。删除再注册、地址别名和更换连接名称都不能解除已有人员绑定；给另一人使用时应创建独立实例和数据目录。
- 网站每次委派、读取、继续任务都会核对账号、授权和父会话归属。发送到远端的任务与会话标识经过账号隔离转换。
- 停用、删除或撤销授权后，新增操作立即拒绝，正在执行的远程任务在下一次授权检查时请求取消（每 10 秒检查）。远端不可达时不能保证即时取消；应在远端确认任务状态，避免重复执行。
- 原生异步任务和 SSE 进度读取机制保留。每个账号最多同时委派 4 个远程任务，网关最多 16 个；达到上限会明确提示先等待已有任务。
- 委派只传任务文字，不自动发送主会话历史、个人文件、模型密钥或插件配置。远程文件仍保存在远端；本功能不自动把远程产物复制到网站个人文件夹。
- 模型不能注册、装配或启动本地 Agent，不能通过 `fork`、`clean`、插件角色、注册动作或旧的本地 `task_id` 绕过限制。
