# NAS 图片尺寸与格式转换

发布：`cardbush-web:20261016-14`，网站 `http://172.16.20.29:5199/`。网关基于线上 `20261016-13`；账号运行镜像同步为新版本，保留原命名卷。

在现有按账号授权的图片插件中增加 `image_convert`。用户上传图片或引用本会话已有图片后，可直接说“转成 800 × 800 的 JPG”。支持 PNG、JPG/JPEG、WebP，也可只改格式。默认 `contain` 等比缩放并补白，保留整图；明确指定时支持居中裁剪 `crop` 或拉伸 `stretch`。工具只写入个人 `generated` 下的新文件，保留输入原图，返回确切宽高、格式、大小及本地路径。转换不调用生图模型。

每张输入和输出均不超过 16 MiB / 1600 万像素，目标单边最多 8192 像素。静态图片经过解码验证；拒绝动图、视频、伪造图片、越界路径、链接跳转与自选输出路径。文件逐层通过目录描述符和 `O_NOFOLLOW` 打开，输出使用独立目录、临时文件及原子发布。

转换使用独立 Python/Pillow 工作进程，账号内串行，MCP 事件循环保持异步。进程有 384 MiB 地址空间、20 秒 CPU、25 秒截止时间和文件大小限制。每次获得工作槽后通过私有网关重新校验当前账号插件授权，撤权后不能派发新的转换。模型只能调用已加入固定白名单的转换工具；个人读取范围不包含插件目录。

转换回执接入现有原生会话渲染、历史工具详情延迟读取、图片预览、单张下载及 ZIP 下载。管理员插件说明同步更新。插件版本升至 1.1.0，账号下次发起对话时自动通过原生插件替换流程升级；活动生图任务期间不替换插件。

验证：44 项 Node 测试、8 项 Python 测试，以及非 root / 只读根目录 / 768 MiB / 单核容器内的完整原生插件升级、转换、撤权测试。检查精确尺寸、白边位置、EXIF 方向、透明背景合成、格式文件头、原图哈希、异步心跳、目录逃逸拦截及 MIME。浏览器在生产 CSP 下验证转换产物的延迟读取、单张和 ZIP 下载、缓存恢复、错误重试与账号切换。

线上健康、静态资源哈希、转换授权接口、会话分页及跨账号拒绝验证通过。发布时已检查任务空闲，使用 broker 原有迁移流程恢复当时活动账号，命名卷一致；其他休眠账号在下次访问时升级。发布验证未调用实际模型或写入用户对话。

编译后端仅改变 `agentWebPolicy.mjs`、`webServer.mjs`、`webToolPolicy.js` 及其类型声明；保留其他线上 Runtime 文件。

发布目录：`/volume1/docker/cardbush-web/releases/web-20261009-01/updates/image-convert-20261016-14`。备份位于 `backups/before-image-convert-20261016-14`，包含原 compose 和受保护的 broker 配置。

回退先确认账号任务空闲。网关恢复 `20261016-13`；账号镜像使用 `cardbush-web:20261016-convert-rollback`，它保留原 `20261010-10` Runtime，仅加入插件版本协调，能将已升级插件安全恢复至随包的 1.0.0。不能直接回退到原始账号镜像，否则旧版插件数量检查可能无法接受已安装的新工具。`release_config.mjs rollback` 通过受控挂载恢复网关配置并设置兼容回退镜像；随后只重建 web、重启 broker，账号在空闲后通过 broker 恢复。保留所有个人卷。
