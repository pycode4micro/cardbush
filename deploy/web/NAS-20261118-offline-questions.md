# 远程助手断连隔离与服务恢复

## 问题与行为变化

53 号 Windows 机器重启后，Agent 未正常启动。原网页将本地和远程待答问题放在同一个请求中读取；远程连接失败会使整个待答接口失败，显示“暂时无法获取待答问题”的红色提示。该提示不能单独证明整个 NAS 服务停止，但会阻断网页正常获取本地待答问题。

本次恢复了 53 上原有的 `CardBush-Agent` 计划任务，并将故障隔离修复部署到 NAS：

- 网页分别读取 `solutions?scope=local` 和 `solutions?scope=remote`，使用独立的轮询、超时和错误状态。远程断连不会阻塞本地读取或本地回答后的刷新。
- 远程读取无需启动本地 Runtime；各远程来源独立处理故障，正常来源仍可返回问题。连接读取期限为 4 秒，结果缓存 5 秒，使用有界缓存和并发队列。期限到达后关闭已建立的客户端，迟到的客户端也会关闭。
- 远程离线时显示“远程助手暂时无法连接，本地对话可继续。远程待答问题将在连接恢复后同步。”中英文文案来自语言包。恢复后继续轮询真实待答状态。
- 未带 `scope` 的旧客户端仍收到数组；远程故障时仍返回本地问题。旧客户端最多需要等待本次远程读取的期限，新版的本地读取完全独立。
- 回答继续重新校验账号、会话、任务归属、连接授权及远程身份。离线答案返回不可用，不重复发送、不消费远端等待、不重建任务。其他正常远程来源的问题仍可回答。

该改动隔离的是远程待答读取故障。运行在 53 上的任务仍依赖 53 本身可用，不能把网关恢复描述为 Windows 蓝屏已修复。
